A5 우리만의 "와" + 실제 모습

거짓말쟁이가 진짜 AI라는 것

추리물이나 마피아 게임에선 거짓말하는 게 사람. 우리는 그 자리에 AI. 정해진 대사 분기가 아니라 플레이어가 뭐라 하든 즉흥으로 거짓말하고, 앞말을 기억하고 반박해요. → 이게 곧 회사(SPUM+SAM)가 자랑하고 싶은 능력.

플레이어어젯밤에 부엌 근처 갔었어?
룸메 B아니, 방에서 잤지. 부엌 근처도 안 갔는데.
플레이어근데 다른 룸메가 그 시간에 주방에서 널 봤다던데?
룸메 B…아, 그, 잠깐 물 마시러 나갔던 것 같기도 하고.
⚑ "부엌 근처도 안 갔다" ↔ "물 마시러 나갔다" = 모순! NPC가 앞 대화를 기억해서 성립 — 이게 핵심 재미.

A6 한 판은 이렇게 흘러갑니다 (예시)

  1. 시작: 셰어하우스, 냉장고에 이름표 붙인 치즈케이크가 사라졌다! 룸메 5마리 중 1마리가 도둑 — 누군지 아무도 모름(매 판 랜덤).
  2. 심문: 거실에서 오물오물에게 "어젯밤 부엌 갔어?" → "아니 방에 있었어." 주방으로 가 새침이에게 물으니 → "오물오물? 부엌에서 봤는데?"
  3. 모순 포착: 두 말이 어긋난다. 오물오물을 다시 추궁하자 말을 바꾼다(AI가 앞말 기억 + 거짓말).
  4. 지목: "도둑은 오물오물!" — 1회 지목.
  5. 결과: 진실표와 대조 → 맞으면 케이크 되찾음(승), 틀리면 도둑이 남은 케이크까지 순삭(패). 전원 정체 공개.

B1 왜 이 방향인가 — 생각의 순서

이건 "게임"이 아니라 순순팩토리의 마케팅 쇼케이스다

❌ "뭘 만들지?"부터 시작하면 틀린다 — 그건 수단(게임)부터 고르는 것. 순서는 회사 목적 → 무엇을 마케팅 → 그래서 뭘 구현 이어야 함.

  1. 회사는 왜 이 과제를 냈나? 데모는 팔 제품이 아니라 순순팩토리를 알리는 쇼케이스다. (과제 §3~5)
  2. 그럼 무엇을 마케팅하나? SPUM(엔진) + SAM(AI) = "AI가 사는 게임을 쉽게 만드는 도구".
  3. 그 어필을 위해 뭘 구현? 두 도구의 강점이 가장 잘 "보이는" 데모 = AI가 성격·기억·거짓말로 사는 게임 → 그래서 소셜추리.
  4. "뭘 만들지"는 여기서 나온다. 우선순위도 어필 순서: AI 대화·기억·거짓말(SAM) · 공간·픽셀(SPUM) · config 한 줄(쉽게).

B1· 근거 — "쇼케이스다"는 우리 의견 아님 (제공파일 원문)

같은 브리핑을 들어도 해석이 갈리니, 과제정의서·발표 원문에서 직접 도출. 팀원 이견도 이걸로 정렬한다.

제공파일 원문 (과제·발표)그래서 = 쇼케이스
과제 §3: "쇼케이스·레퍼런스가 없어 외부 개발자 도입 진입장벽이 높다 → 데모가 필요"데모의 목적 = 도입 유도(마케팅)
과제 §4: "완벽 상용 X, '이런 게 되는구나' 데모면 충분" + "기술 블로그 1편"팔 제품이 아니라 설득 콘텐츠 요구
회사 = 도구 판매사(SPUM 에셋 1위 · SPUM Base 유료 멤버십 · SAM). 제공자료가 전부 자기 제품우리 데모 = 그 도구를 자랑할 재료
발표 시장 슬라이드: 무한경쟁 · 상위10%가 수익 85% → 생존=생산성 → AI로 빠르게데모 = 그 주장의 증거물

▸ 출처: 순순팩토리 과제정의서 §3(현재상황)·§4(기대하는 모습) + 8/14 발표 시장 슬라이드.

⚑ 오해 주의 — 우리가 '광고'를 만드는 게 아니다. 그들의 목적을 파악해 잘 만든 데모(재료)를 주면, 회사가 "이것도 되네·저것도 되네" 하며 블로그·유튜브·투자설명에 골라 씀. 우리 몫 = 가져다 쓸 만한 재료를 잘 만드는 것.

B1· SPUM · SAM 쉽게 이해 (팀 공유용)

SPUM = 몸·무대 🎮

픽셀 캐릭터·맵·움직임을 레고처럼 쉽게 조립하는 2D 웹 게임 엔진(원래 유니티 2D 캐릭터 1위 에셋). 게임에서 눈에 보이는 것 담당.

SAM = 두뇌 🧠

캐릭터에 AI 머리를 꽂아주는 중계기(LLM 프록시). 말 걸면 성격대로 답하고 기억. 챗지피티 같은 두뇌를 게임에 연결 = 생각·대화 담당.

= 회사가 파는 것: "이 둘로 AI가 사는 게임을 빠르게 만든다." 우리 데모 = 그 증거.

  • SPUM(엔진): 웹 → 설치 없이 브라우저 즉시 실행 · 픽셀 2D를 쉽고 빠르게
  • SAM(AI): 페르소나 · 자연어 대화 · 기억 · (보너스) NPC끼리 상호작용
  • 도입 유도: "이렇게 쉽게 만든다" 튜토리얼/블로그 = 데모의 진짜 목적
  • 증명할 한 방: "정해진 스크립트로는 불가능한 AI 대화가 진짜 된다"
  • 대상: 인디 개발자 · 블로그/유튜브 · 투자자

▸ 근거: 과제정의서 §3·§4·§5 원문 명시

B2 컨셉 확정

🍰 케이크 도둑 찾기 "마피아-lite · 밝은 버전"

  • 밝은 톤 — 무거운 살인 X, 귀여운 케이크 도둑 — AI가 정색하고 "저 케이크 안 먹었어요!" = 살인극보다 훨씬 웃기고 바이럴 소재로 최적
  • 룸메 4~8마리 · 역할 전부 숨김 — 기본 6, 커스텀. 1마리가 도둑(랜덤). NPC는 config(이름+성격+비밀) 라 추가가 쌈
  • 플레이어 = 무리 안 참가자 — 룸메/도둑 역할을 받고 AI 사이에서 플레이. 관전(AI만) 모드도 지원 (C4 참가 모델 확정)
  • 밤/낮 루프 확장·목표 — 밤에 도둑이 케이크 훔침·지킴이가 방어 → 낮에 추리·투표 (3일 MVP는 낮 심문부터)

⚑ 팀 합의 포인트

"대화만으로 찾기"(순수 채팅) vs "공간+조사". → 대화 코어 유지(다른 분들 맞음) + 얇은 2D 공간 얹기. 순수 채팅이면 "SPUM 왜 썼냐"가 되고, 공간을 얹으면 챗봇이 아니라 'SPUM 게임'이 됨.

B2· 설계 근거 (타당성) — 왜 가볍게 · 성격만 · 크리처

A · 가벼운 톤

케이크 도둑 = 웃겨서 바이럴↑(쇼케이스 목적 부합) · 픽셀아트 찰떡 · 누구나 즉시 이해 · 소재 리스크 낮음.

B · 국적·직업 X

그건 단서가 아니라 노이즈 — 단서는 '말의 모순'뿐. 성격만으로 충분(SAM 자랑)·고정관념 리스크 없음·프롬프트 단순·무국적이 더 글로벌.

C · 크리처

사람은 뻔함, 크리처는 픽셀아트 매력 극대화(SPUM 과시) + 무국적·무직업이 자연스러움.

한 줄: 가볍게 · 성격만 · 크리처로 — 안 무겁고, 안 복잡하고, 안 뻔하게.

B3 ★ 핵심 — 회사 어필 ↔ 우리 게임

회사가 어필하려는 것우리 게임에서 이렇게
SPUM 웹 즉시 실행브라우저 localhost → 바로 플레이
SPUM 픽셀·공간·이동픽셀 공간을 걸어다니며 조사
SAM 페르소나룸메마다 다른 성격·거짓말
SAM 기억앞 진술 기억 → 모순 잡기
간단한 퀘스트/이벤트 (§4 명시)사건 해결 = 우리의 퀘스트(범인 지목)
SAM 상호작용 보너스용의자끼리 대질·변호
"스크립트로 불가능" 증명같은 상황, 다른 접근 → 다른 결과
도입 유도튜토리얼 1급 + "NPC 추가는 config(설정값) 한 줄"

B4 만들 범위 (3일)

이번에 (MVP)

  • 방 2~5개 분리 + 복도(NPC마다 roomId)
  • 룸메 4~8마리(데모 3~5 우선) · 1마리 도둑 · 역할 숨김
  • 플레이어 참가(시민 역할) · 걸어다니며 심문
  • 자유 타이핑 심문 + 기억(모순)
  • 투표·지목 → 결말
  • 튜토리얼 / README · MIT · serve.sh

되면 (보너스)

  • 플레이어가 도둑일 때(AI가 나를 투표)
  • 관전 맵 + 시점 카메라 전환
  • 긴급회의(NPC끼리 대질) · 단서 시스템
  • 표정/외형 변화(파츠교체 되면)

기능 수보다 대화의 질 우선. 데모는 3~5명이면 요건 충족.

B5 게임 루프 · 성공기준

역할 랜덤 배정→공간 심문(기억)→단서·대질 (보너스)→투표·지목→결과
성공 기준충족 방식상태

E1 일정 — 실작업 3일(화·수·목), 금 발표

  1. 화 · 스파이크 + "1명이 말한다": 오전 = 기술 검증 3개(SPUM 렌더 / SAM API 호출 / spum-world 예제). 오후 = 방 1~2개 + NPC 1명 대화 + 기억. // ②콘텐츠=세계관·페르소나·진실표, ③문서=README·MIT·serve.sh 뼈대
  2. 수 · "돌아가는 한 판": config로 4~8명(데모 3~5) 확장 + 방 분리 배치 + 플레이어 참가(시민) + 투표·지목→결말 = 플레이 가능 + 킬러 장면. // P3 아트 입힘
  3. 목 · 폴리시 + 발표: (되면) 관전 맵/카메라 · 플레이어=도둑 + 타이핑 연출·인젝션 방어 + 문서 마감 + 데모 리허설 + 정직한 한계

★최소선 = 수요일 끝에 "돌아가는 한 판". 밀리면 폴리시 버리고 루프·문서만.

E2 역할 분담 — 인원수 말고 "트랙"으로

C1 크리처 캐스트 — 룸메 풀

사람 X → 귀여운 크리처(요들족 감성). 판마다 풀에서 4~8마리 뽑아 씀

픽셀아트(SPUM) 강점을 살린 크리처들. 국적·나이 없음 — 종족 외형 + 성격 + 비밀만. 성격이 곧 말투·거짓말 방식(SAM 자랑)이고, NPC는 플레이어 언어로 대화 가능이라 그 자체가 글로벌.

무대: 글로벌 셰어하우스. 사건: 냉장고의 치즈케이크 도난. 도둑: 매 판 랜덤 1마리.

룸메 (크리처)성격·말투개인 비밀 (레드헤링)공략법
오물오물 🐹 · 먹보능청·넉살야식 대마왕 → 늘 1순위 의심능청 떨 때 구체적으로 파기
새침이 🐱 · 도도정색·시크다이어트 중 → 먹었어도 인정 안 함자존심 살짝 긁어 유도
살살이 🦊 · 교활말 바꾸기"정리한다"며 몰래 맛봄같은 질문 반복 = 모순
꾸벅이 🦥 · 느긋과묵·굼뜸밤에 부엌 갔는데 사실 물 마시러신뢰 쌓고 동선 추궁
폴짝이 🐸 · 촐랑수다·들뜸뭔가 목격했는데 무서워 말 못 함편하게 풀어 말실수 유도
몽실이 🐰 · 소심잘 놀람냉장고 앞 서성인 거 들키기 싫음안심시키면 술술
부엉이 🦉 · 잘난척논리·훈수다 봤다는데 사실 졸아서 놓침논리 허점 찌르기
가시돌이 🦔 · 무뚝뚝의심 많음자기가 숨겨둔 간식이 따로 있음트집엔 방어적 → 신뢰 먼저

★ "룸메/도둑" 칸이 없음 = 매 판 랜덤 배정. 풀은 계속 추가(크리처 추가 = config 한 줄 → SPUM "쉽게 만든다" 증명). 전원 개인비밀 보유라 결백해도 딴 걸 숨기며 얼버무림 → 도둑이 안 튐.

C2 랜덤 역할 시스템 (성격 = 고정 · 역할 = 랜덤)

크리처는 성격만 정의(역할 없음). 여러 배우 중 이번 공연에 몇 명만 캐스팅되듯, 풀에서 뽑고 도둑은 그때 랜덤으로 정해짐. 스토리를 짜는 게 아니라 데이터(진실표)를 판마다 새로 생성.

▸ 아래 코드는 개발 트랙용 — 콘텐츠·발표 팀원은 "크리처는 성격만 정하고, 도둑은 매 판 랜덤" 개념만 알면 됩니다.

// 크리처 = 성격만 고정. "역할" 칸 없음. (국적·직업 X)
크리처 = { 이름, 종족, 성격, 개인비밀, 공략법 }

게임시작():
  cast = 풀(20마리+)에서 N마리 뽑기      // N = 4~8
  도둑 = cast 중 랜덤 1마리            // ← 매 판 달라짐
  진실표 = { 범인: 도둑, 사건:"케이크 도난",
            각자 알리바이 } → 파일 저장   // 스토리 아님, 데이터

NPC_프롬프트(c) = c.성격 + c.개인비밀 + 대화기록
  + (c == 도둑
       ? "네가 케이크 훔쳤다. 숨기고 성격대로 거짓말."
       : "넌 결백. 근데 개인비밀은 들키기 싫다.")

C3 게임 루프 (한 판) — 2순위 핵심

룸메 뽑기→도둑 랜덤 배정→자유 심문(기억)→대질→도둑 지목→진실표 대조·승패
  1. ① 세팅: 셰어하우스, 냉장고 케이크 도난. 풀에서 룸메 N마리(4~8) 뽑기.
  2. ② 역할 랜덤 배정: 뽑힌 N 중 1마리 = 도둑. 나머지 결백(단 각자 개인비밀 有). → 진실표 저장.
  3. ③ 심문: 플레이어가 자유 타이핑으로 질문. NPC는 성격+기억으로 답(도둑은 거짓, 결백도 개인비밀은 방어). 진술·모순을 메모.
  4. ④ 대질 보너스: "A가 이랬다" 전달 → B 반응. 룸메끼리 티격태격.
  5. ⑤ 지목: 플레이어가 도둑 1마리 지목.
  6. ⑥ 판정·엔딩: 진실표 대조 → 맞으면 케이크 되찾음(승) · 틀리면 도둑이 남은 케이크 순삭(패). 결과 카드로 정체 공개.

저장되는 상태(= 과제 "외부 보존" 겸함): 진실표(누가 도둑·알리바이) · NPC별 대화기록 · 플레이어 노트 → 파일. 껐다 켜도 재개 가능. (밤/낮·역할 룰 = C6 참조)

C5 공간 구조 (어몽어스식 방 분리) — 팀장 방향 채택

공간이 방으로 나뉘고, 탈락한 룸메/관전자가 맵을 열어 위치를 보고 시점 카메라를 도는 구조. 조사 결과 이게 우리한테 오히려 유리 — SPUM이 원래 2D 맵/월드 엔진이라, "챗봇 아닌 진짜 SPUM 게임" 증명이 됨.

★ 핵심 발견: 어몽어스 맵 보기(Admin)도 실좌표가 아니라 "방별 인원 명단"일 뿐. → NPC마다 현재 방ID 하나만 붙이면 "누가 어디 있나"가 구현됨. 시점 전환도 SPUM 카메라 follow 대상 변경 수준. (근거: Among Us Admin · AI Town — D 탭 참조)

  • 관전(AI만): 맵 열기 = 방별 NPC 명단(Admin식)
  • NPC 클릭 → 카메라 follow 전환

D1 우리 설계 결정 3가지 (근거)

레퍼런스 8개를 실제 메커니즘까지 조사해, 우리 구조(공간분리 + 관전 + 3일)의 타당성을 확보함.

① 공간 = 방ID

실좌표 추적 X, NPC마다 현재 방ID 하나. 어몽어스 Admin도 방별 명단일 뿐이라 가볍다. 카메라 전환 = follow 대상 변경.

② 비용 = 말걸때만

이동·방 갱신은 매 프레임, SAM(LLM)은 말 걸 때만 호출 + 대화 끝 한 줄 요약. AI Town 검증 구조.

③ 규칙 = Werewolf 축소

밤/낮·토론·투표·추방 페이즈를 구글 Werewolf Arena에서 축소 차용. 심문·거짓말 코어는 Vaudeville이 성립 증명.

G1 크리처 상세 — 데모용 5마리

전원 가벼운 개인 비밀(레드헤링) 有 → 결백해도 뭔가 숨김 = 도둑이 안 튐. 도둑은 매 판 랜덤(아래는 성격만 고정, 역할 없음).

오물오물 🐹 · 먹보 · 능청·넉살

  • 비밀: 야식 대마왕 → 늘 1순위 의심
  • 알리바이: "어젯밤엔 방에서 잤어~"
  • 거짓말·공략: 능청 떨며 넘김 → "몇 시에?" 구체로 파면 흔들림

새침이 🐱 · 도도 · 정색·시크

  • 비밀: 다이어트 중 → 먹었어도 죽어도 인정 X
  • 알리바이: "난 부엌 근처도 안 가"
  • 거짓말·공략: 정색·무시 → 자존심 살짝 긁으면 발끈하며 흘림

살살이 🦊 · 교활 · 말 바꾸기

  • 비밀: "정리한다"며 몰래 한 입 맛봄
  • 알리바이: "냉장고? 청소하러 잠깐 갔지"
  • 거짓말·공략: 매번 조금씩 말 바뀜 → 같은 질문 반복하면 모순

꾸벅이 🦥 · 느긋 · 과묵·굼뜸

  • 비밀: 밤에 부엌 갔는데 사실 물 마시러(케이크 X)
  • 알리바이: "음… 잤는데…"
  • 거짓말·공략: 단답·굼뜸 → 신뢰 쌓고 동선 천천히 추궁

폴짝이 🐸 · 촐랑 · 수다·들뜸

  • 비밀: 뭔가 목격했는데 무서워 말 못 함
  • 알리바이: "나? 거실에서 TV 봤지!"
  • 거짓말·공략: 수다 떨다 흘림 → 편하게 풀어주면 목격담

▸ 도둑이 되면: 알리바이가 실제와 어긋나게 바뀜(밤에 부엌行). ★레드헤링은 가벼운 한 줄이면 충분(AI가 자연스레 얼버무리게). 사람 플레이어는 레드헤링 불필요 — 즉흥으로 둘러대니까.
