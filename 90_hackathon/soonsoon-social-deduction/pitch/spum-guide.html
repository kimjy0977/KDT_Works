0 · 시작 화면

Home Dashboard — 전체 지도

로그인하면 나오는 첫 화면. 카드에 적힌 01~06 번호가 곧 제작 순서예요. ★★★★★

  1. 왼쪽 세로 메뉴 — Home · World · Map · Object · Cast. 에디터를 여기서 오갑니다. ★★★★★
  2. 오른쪽 위 크레딧 — SSAM=AI 사용량 남은 양, STORAGE=저장 용량. AI를 쓰면 SSAM이 닳음. ★★★★☆ (표시만 봄, 과금정책 미확인)
  3. 제작 순서 카드 01~06 — ①Object(타일/오브젝트) → ②Map(공간) → ③Cast(캐릭터) → ④World(게임 조립) → ⑤SPUM Link(공유) → ⑥SPUM Frame(임베드). ★★★★★

1 · 캐릭터

Cast Editor — 사람(캐릭터) 만들기

외형·장비·성격·스탯을 만드는 곳. 아래 사진은 Stats 탭이 열린 상태예요. ★★★★★

  1. Appearance (외형) — 파츠(몸/눈/머리/투구/갑옷/옷/바지)·파츠팩·색상. 사람 외형은 여기서. ★★★★★
  2. Stats (능력·성격) — 지금 열린 화면. 기본정보·페르소나·능력치. ★★★★★
  3. Animation — IDLE·MOVE·ATK·DMG·DEATH 동작 미리보기. ★★★★★
  4. Export — 스프라이트시트(PNG / PNG+JSON / GIF)·해시코드로 내보내기. ★★★★★
  5. Manage — 캐릭터 관리 탭. ★★★☆☆ (탭만 봄, 내용 안 열어봄)
  6. Characters 목록(왼쪽) — 만든 캐릭터 목록 + ＋로 새 캐릭터, 이름/날짜 정렬. ★★★★★
  7. A. Basic Info — 이름·나이·성별·MBTI·종족·테마·직업·말투. 각 칸 AI버튼 + AI Auto Generate. ★★★★★
  8. B. Persona — 성격 키워드(성실한·호기심많은…)·배경·핵심키워드. AI Generate. ★★★★★
  9. C. Abilities — 능력 레이더(STR/AGI/INT/SPR/CMD/CHM)·등급(COMMON~LEGENDARY)·Total 390/800. ★★★★★
  10. D. Derived Stats — HP/MP/ATK/DEF/SPD/CRIT 등 자동 계산 파생 스탯. ★★★★★
  11. 미리보기 — 캐릭터 렌더 + 하단 IDLE/MOVE/ATK/DMG/DEATH 재생 버튼. ★★★★★
  12. AI Assistant — "○○ 캐릭터 만들어줘" 채팅으로 자동 제작. 지금 실제 실행되는 건 Cast뿐. ★★★★★

우리 게임에선 → 1(Appearance)로 셰어하우스 사람 외형, 8(Persona)로 성격·말투만(국적·직업은 노이즈라 생략), 2의 스탯은 대충, 필요하면 4(Export)로 내보내기.

2 · 타일/오브젝트

Object Editor — 맵 타일 "테마" 만들기

핵심: 여긴 바닥·벽·소품의 그림(타일 재질)을 만드는 곳. 맵 배치(레이아웃)는 여기서 안 함 — 그건 Map. ★★★★☆ (사막·잔디 생성물의 물 배치가 동일 = 텍스처만 교체 관찰)

📸 Object Editor 전체 캡처 대기 — 주영님이 화면 캡처해 주시면 번호 얹어 채웁니다. 아래는 검증된 순서.
  1. Concept — 만들 테마 개념 적기(예: "아늑한 집 인테리어"). ★★★★★
  2. AI Prompt / Reference — 세부 프롬프트·참고 이미지. ★★★★★
  3. Generate (gpt-image-2) — AI가 타일셋 이미지 생성. ★★★★★
  4. Slice — 생성 이미지를 격자 셀로 잘라 타일화. ★★★★★ (버튼 봄, 직접 안 잘라봄)
  5. 타일 속성 — TYPE(Floor/Wall)·MOVE(Walk/Block)·ACTION·SIZE. ★★★★★
  6. 픽셀 편집 — 펜·지우개·채우기·색/팔레트로 직접 수정. ★★★★★
  7. AI 채팅 자동실행 X — Object는 챗으로 자동 안 됨("준비 중"), 직접 만들어야. ★★★★★

3 · 공간

Map Editor — 테마 타일로 방 배치

Object에서 만든 테마 타일로 레벨(공간)을 직접 그리는 곳. 우리 셰어하우스 방이 여기서 만들어짐. ★★★★★

📸 Map Editor 전체 캡처 대기 — 캡처 주시면 번호 얹어 채웁니다. 아래는 이번에 직접 확인한 순서.
  1. Maps 목록(왼쪽) — 만든 맵 목록 + ＋로 새 맵. ★★★★★
  2. 크기 지정 — 상단 40×30 등 입력 → Apply. ★★★★★
  3. 테마 선택 — 오른쪽 MAP THEME TILES 클릭 → 라이브러리서 테마 선택 → "brush ready". ★★★★★
  4. 도구바(가운데 세로) — 선택·이동·브러시·지우개·채우기·사각형·스포이드·되돌리기·줌. ★★★★★
  5. 타일 고르기 — SRC 타일판서 바닥/벽 타일 클릭(=브러시 지정). ★★★★★ (8/19 — 손으로 칠하는 대신 코드로 전체 교체 성공)
  6. 칠하기 — 캔버스에 드래그. 사각형=방 벽 한 번에, 채우기=바닥 한 번에. ★★★☆☆
  7. Navigation — 벽=Block(빨강)·바닥=Walk(초록) 이동판정 칠하기. ★★★★★ (8/19 — obstacle·walkable 레이어를 코드로 씀·연결성 검증까지)
  8. Layers — 앞 레이어(가구)·Character·뒤 레이어(바닥). ★★★★☆

4 · 게임 조립

World Editor — 맵+캐릭터로 플레이 월드

맵 위에 캐릭터를 AI NPC로 배치하고, 대화·미션·스토리를 붙여 플레이 가능한 월드로 만듦. ★★★★★

📸 World Editor 전체 캡처 대기 — 캡처 주시면 번호 얹어 채웁니다. 아래는 직접 확인분(실행까지는 미검증 표기).
  1. 오브젝트 패널(왼쪽) — Map·Characters·Props·Events·Spawn Points 배치. ★★★★★
  2. 캐릭터별 AI 데이터 — Personality(mbti/역할/성격/말투) + AI + 메모리(기억) + Status. ★★★★★ (필드 존재 확인, 커스텀 주입은 미확인)
  3. 채팅 = 심문 — "캐릭터에게 지시/메시지"로 NPC에게 말 걸기(전체/개별). ★★★★★ (입력창 확인, 실제 응답 품질 ★★★☆☆)
  4. 미션 — 월드 목표·미션·topic 관리. ★★★★☆ (패널 봄, 안 돌려봄)
  5. 스토리 (Reverse Story Bake) — scene/node/thread 자동 생성·말풍선 재생. ★★★★☆
  6. 시뮬레이션 — AI 자율행동 + Event Log(INTENT·Cost). ★★★★☆
  7. Play / SPUM Link / Frame — 실행·공유·임베드. ★★★★☆ (버튼만, 배포 안 해봄)

솔직한 미확인 목록

✅ 그때 몰랐던 것 — 이제 답이 나왔습니다 2026-08-19 갱신

  • World 채팅의 실제 AI 응답 품질·기억 유지 → 돌려봤고, 게임 규칙에는 못 씁니다. talkConfig.systemPrompt를 무시하고, 캐릭터 메모리를 사실 근거로 쓰지 않으며, 없는 내용을 지어냅니다. 대화 모드가 Local FSM으로 고정돼 시스템 프롬프트 입력란 자체가 없습니다. ★★★★★
    → 결론: 대화는 SAM 직접 호출로 구현합니다.
  • 캐릭터 메모리에 커스텀 알리바이 주입 → 주입 자체는 됩니다(memory.recent[], 최대 20개. 스키마는 연결 가이드 §4-4). 다만 위 이유로 World AI가 그걸 근거로 말하지 않습니다. ★★★★★
  • 미션/스토리로 숨은 역할·승패 판정 → 코드로 합니다. 범인 랜덤 배정·물리단서·목격·자백 판정은 우리 런타임(proto/)이 담당. 근거 엔진 자동검증 7/7 통과. ★★★★★
  • SPUM Link 배포 결과물 → 스코프 아웃. 이번 마감에서는 안 합니다. 과제 요건은 bash serve.sh 로컬 실행이라 배포가 필요 없습니다. ★★★★☆
  • SAM 크레딧 소진·무료 한도 → 측정했습니다. 대화 턴당 약 1.7 SSAM(9턴에 15). 잔량 44,220 / 45,000 — 데모에는 충분히 넉넉합니다. ★★★★★

★ 최대 관문이던 "스튜디오로 게임 룰까지 되나 vs 코드 필요"는 코드 필요로 결론났습니다. SPUM은 에셋 저작소(캐릭터·타일·맵), 게임 규칙과 대화는 SPUM Engine + SAM 으로 우리가 만듭니다.

🔧 그 뒤에 새로 알아낸 것 (8/19)

  • 맵은 손으로 안 찍어도 됩니다 — 코드로 통째 교체됩니다. localStorage.sv_studio_maps_v1 수정 → saveServerSnapshot() → 새로고침. 실제로 40×30 맵 전체를 교체해 서버 반영까지 성공했습니다. ★★★★★
    단 방향이 중요합니다 — 서버에 직접 PUT하면 다음 새로고침 때 브라우저 로컬이 덮어써서 날아갑니다.
  • 타일 ID 공식 = tileIdBase + (row × columns) + col. 우리 테마는 tileIdBase 2049·columns 16. ★★★★★
  • 타일셋 셀 크기는 이미지에서 계산해야 합니다. grid "16x16"은 셀이 16px이라는 뜻이 아니라 16칸이라는 뜻 — 192px 이미지면 셀은 12px. 여기서 한참 헤맸습니다. ★★★★★
  • 세션이 30분쯤에 만료됩니다. /api/me가 {"user":null}이면 만료. 우측 상단 배지 → ACCOUNT → 「다시 로그인」 → 4초. 비밀번호 안 물어봅니다. ★★★★★
  • Cast Export는 신뢰하지 마세요. Generate가 비동기라 직전 캐릭터 시트가 다운로드됩니다. 받은 뒤 JSON의 characterName으로 반드시 확인. (5명 중 2명만 정상 확보됐던 원인) ★★★★★
  • 캐스트 "배치"만은 코드로 하면 안 됩니다. world.casts[]를 코드로 만들면 앱이 "없는/중복 배치 N개를 정리했습니다"로 전부 지웁니다. World Editor의 ＋ → "배치" 버튼으로. ★★★★★
  • Map Editor에서 타일이 안 보이면 오른쪽 MAP STRUCTURE → Layers의 NAV 체크박스(장애물·워커블)를 끄세요. 초록/빨강 오버레이가 타일을 가립니다. ★★★★★
  • 제공 문서는 실제로 못 받습니다. 과제정의서가 준다고 한 AGENTS.md·README.md가 전부 404입니다. 소스가 곧 문서이고, 회사에 요청해야 할 항목입니다. ★★★★★
