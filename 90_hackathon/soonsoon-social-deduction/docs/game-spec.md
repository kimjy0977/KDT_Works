# 「누가 내 케이크 먹었어?」 게임 기획서 (작업정의서)

> 팀 《순순히 따라와라》 · 순순팩토리 기업연계 · 마감 2026-08-21
> **최종 갱신 2026-08-19** — 플레이어 정의 정정본

---

## 0. 한 줄 정의

**거주자 6명 중 한 명이 되어, 밤 사이 냉장고의 케이크를 훔쳐 먹은 범인을 찾아내는 AI 소셜 추리 게임.**

## 1. ★가장 중요한 전제 (이전 버전의 오해 정정)

**플레이어는 외부 탐정이 아니다. 플레이어도 거주자 6명 중 한 명이다.**

| | 잘못된 이해(폐기) | 올바른 정의 |
|---|---|---|
| 플레이어 위치 | 바깥에서 용의자를 심문하는 탐정 | **거주자 1명 = 내 캐릭터** |
| 나머지 4명 | 심문 대상(NPC) | **동등한 플레이어** (AI가 조종) |
| 시야 | 맵 전체 조망 | **내 캐릭터 고정 카메라 + 시야 제한** |
| 대화 | 목록에서 골라 "심문" | **가까이 가서 말 걸기 / 아침에 모여 토론** |
| 밤 | 구경하는 컷신 | **나도 직접 행동** |
| 결말 | 나 혼자 지목 | **다 같이 토론 후 투표** |

→ 어몽어스와 같은 구조. **카메라 고정·시야 제한은 게임의 핵심**이지 후순위 장식이 아니다.

## 2. 확정된 설계 결정 (2026-08-19)

| # | 항목 | 결정 |
|---|---|---|
| 1 | 플레이어가 범인이 될 수 있나 | **가능 (랜덤 배정)** — 내가 도둑이면 거짓말하며 숨는 플레이 |
| 2 | 밤에 플레이어는 | **직접 조작** — 몰래 부엌에 갈 수도 있음 |
| 3 | 결말 | **아침에 모여 토론 → 투표** |

> ⚠ **이 문서는 기획(하려는 것)이지 구현 현황이 아니다.**
> 구현된 것과 안 된 것은 `docs/tutorial.md` §11 과 `docs/handoff.md` 를 볼 것.
> 특히 **§2-1 범인 매 판 랜덤 배정은 아직 미구현**이다(현재 고정 시나리오 한 판).

## 3. 게임 루프

```
저녁  모두 거실에 모임 (자유 대화)
  ↓
밤    화면 어두워짐 · 각자 방으로 이동
      · 범인(플레이어 또는 AI)이 몰래 부엌 → 케이크 섭취
      · 나머지는 자기 방. 복도에서 마주치면 목격 발생
  ↓
아침  케이크가 사라진 것을 발견
  ↓
토론  거실에 모여 대화 — 알리바이·목격·물리단서 공방
  ↓
투표  가장 의심받는 사람 지목 → 정답 여부 판정
```

## 4. 밤 시뮬레이션 근거 엔진 (핵심 시스템 · 검증 완료)

시스템이 **정답(ground truth)** 을 먼저 고정하고, 각 캐릭터에겐 **자기 기억만** 준다.

- **범인**: 매 판 랜덤 배정 (플레이어 포함)
- **물리 단서**: 범인 소매의 딸기 시럽 자국 — **확정적 단서**
- **목격**: 동선이 겹칠 때만 발생 — **보장되지 않음**
- **레드헤링**: 무고한 사람도 밤에 부엌에 갈 수 있음(케이크는 그대로였음)

**대화 규칙 (프롬프트로 강제)**
1. 자기 기억에 있는 것만 말한다. 없으면 "기억 안 나" — **지어내기 금지**
2. 범인은 **자기 동선만** 거짓말한다. 타인 정보는 사실대로
3. 서로 다른 결정적 증거로 **3회 이상 몰리면 자백**

**검증 결과 (2026-08-18, `proto/run.mjs`)** — 7/7 통과. 실제 자백 재현:
```
[압박3] 꾸벅이도 자정쯤 냉장고 문 닫히는 소리를 들었대. 이래도 방에 있었다고 할 거야?
  살살이: *얼굴이 굳어지고 손이 떨린다*   내가... 내가 먹었어.
```
비용: 9턴에 SSAM 약 15 (턴당 ~1.7).

## 5. 캐릭터 6명

| 이름 | 성격 | 말투 | 밤 기억(예시 시나리오) |
|---|---|---|---|
| **오물오물** | 먹보·눈치 없는·솔직한 | 우물거리며 느긋하게 | 11:20 부엌行 → 우유만 마심, **케이크는 그대로** (레드헤링) |
| **새침이** | 새침한·깔끔한·은근 다정 | 짧고 톡 쏘는 | 라면 몰래 먹음(비밀) + 복도 발소리 들음 |
| **살살이** | 능글맞은·말 많은·눈치 빠른 | 능글맞게 말 돌리기 | **자정 냉장고 → 케이크 섭취 → 소매에 시럽** |
| **꾸벅이** | 잠꾸러기·느긋·순한 | 졸린 듯 느리게 | 10:30 취침, 자정 냉장고 소리 어렴풋이 |
| **폴짝이** | 활발·호기심·수다 | 빠르고 톡톡 튀게 | **자정 넘어 살살이가 부엌 가는 것 목격** |

> ★ 위 배역(범인/목격자)은 **한 판의 예시**. 실제로는 매 판 랜덤 배정된다.
> 성격·말투는 고정, **국적·직업은 넣지 않는다**(노이즈이고 단서를 흐린다).

## 6. 기술 구성

| 층 | 사용 |
|---|---|
| 캐릭터 제작 | **SPUM Cast Editor** (외형·성격·기억) |
| 타일 테마 | **SPUM Object Editor** — 초기 `셰어하우스 인테리어`(173타일) → 현재 **AI 평면도**(32×32) |
| 맵 | **SPUM Map Editor** — `셰어하우스` (방5 + 부엌 + 욕실 + 중앙 거실) ※ 크기는 구현 중 바뀜 → `handoff.md` |
| 월드 | **SPUM World** — 캐스트 6명 배치 |
| 대화 AI | **SAM** `/v1/generate` (직접 호출) |
| **런타임 엔진** | **SPUM Engine** (`packages/spum-engine`) — `Engine·Scene·TileMap·Character·CameraController·InputManager·Collider·Pathfinding` |

**★ 어디에 만드는가 (중요):** SPUM **Studio의 World 런타임**이 아니라, **SPUM Engine을 구동하는 게임 페이지**에 만든다. 별도 웹서비스를 만드는 것이 아니며, 과제정의서 제공자료(`SPUM Engine 소스코드 JS`)가 의도한 사용법이다. 엔진 파일은 `proto/vendor/packages/spum-engine/`에 미러링되어 있다(65개, 커밋 제외).

**★ SPUM World 내장 AI는 게임 규칙에 쓸 수 없음(검증됨):** `talkConfig.systemPrompt` 무시, 기억을 사실 근거로 안 씀, 없는 내용을 지어냄. Local FSM 고정이라 시스템 프롬프트 입력란 자체가 없다. → **대화 로직은 SAM 직접 호출로 구현한다.**
