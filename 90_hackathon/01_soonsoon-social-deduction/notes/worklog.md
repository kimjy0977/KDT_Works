## 해커톤 세션 2차 — 2026-08-19 (맵 재작업 · SPUM 반영 · 게임 셸)

### 2-1. 맵이 휑했던 진짜 원인 (진단)

월드가 비어 보인 건 타일이 부족해서가 **아니었다.**

| 항목 | 실제 상태 |
|---|---|
| 사용 타일 | 256개 중 **4개**만 |
| `front_1` (가구 레이어) | **1200칸 전부 0** — 통째로 비어 있음 |
| 거실 바닥 | 시트 (1,1) = **옷장 타일**을 26×10 반복 |
| 부엌 바닥 | 시트 (4,1) = **화분 타일** 반복 |

→ **타일을 안 깐 것.** 173타일 테마에 침대·주방·욕조·소파·책장이 전부 들어 있었다.

### 2-2. 해결 기법 — "스탬프"

테마 시트는 낱개 타일 모음이 아니라 **완성된 인테리어 도면**이다. 가구가 여러 셀에 걸쳐 그려져 있어
(침대 1×2, 조리대 4×1, 라운지 5×4) 한 셀만 반복하면 무늬가 깨진다.
→ 시트의 **직사각 영역을 통째로** 찍는다. 원본 도면의 완성도가 그대로 옮겨진다.

결과: **사용 타일 4종 → 81종.** 침실 5 · 부엌 · 욕실 · 중앙 라운지 · 복도 가구.

### 2-3. 연결성 검증이 버그 3건을 잡았다
가구가 방을 봉인해버렸다 — ① 조리대가 부엌 문을 ② 소파가 폴짝이 방을 ③ 탁자가 거실 스폰을.
→ **스폰 7곳 상호 도달 검사를 빌더에 내장.** 실패하면 빌드가 중단된다.

### 2-4. SPUM 반영 (★★★★★ 눈으로 확인)
`work-rules.md` A-1 절차대로 `sv_studio_maps_v1` 의 `MAP_msysua8z_CKYO` 레이어 4개 교체
→ `saveServerSnapshot('manual')` → 새로고침. **서버 rev 77.**
Map Editor·World Play 양쪽에서 가구 확인.

**알게 된 것:** SPUM 저장 구조 = 로컬 `map.json` 구조와 **동일**하다.
레이어 4개(`back_1`/`front_1`/`walkable`/`obstacle`) · 각 1200칸 · `tileIdBase 2049` · `columns 16`.
→ 앞으로 맵은 **로컬에서 만들어 스크립트로 밀어넣으면 된다.** 에디터 수작업 불필요.

### 2-5. P0 게임 셸 완료 — `proto/game.html`
부팅 → 타일맵 → 캐릭터 → 이동 → 벽 충돌 → 카메라 추적.

**검증:** 탭 비활성으로 rAF 가 멈춰 FPS 0 이 뜨길래 `engine.pause()` + `engine.step(1/60)` 으로 결정론적 검증.
이동 정상 · **벽으로 400프레임 밀어붙여도 관통 없음**(방 경계에서 정확히 정지) · 카메라 추적/클램프 정상.

**엔진 소스를 읽고 확인한 사실:**
- `TileSet(img,12,12,{firstId:2049})` = 시트에서 **잘라올** 크기 / `TileMapSystem({tileWidth:32})` = **그릴** 크기. 별개다.
- `Camera.isMain = true` 를 켜야 `Engine._getMainCamera()` 가 찾는다.
- 렌더 순서 = `sortingLayer` → `transform.y` → `renderOrder`.
- ⚠ **`CameraController` 는 추적 카메라가 아니다** — 마우스 줌/팬 전용. `FollowCamera` 직접 작성.
- ⚠ **캐릭터 초상 PNG 에 알파가 없다(100% 불투명).** 그대로 얹으면 검은 사각형.
  → `tools/cut-chars.mjs` 로 **테두리 flood-fill** 제거. (색 전역 제거는 안 됨 — 머리카락이 배경만큼 어둡다.)

### 2-6. 곁다리로 고친 것
- **`server.mjs` 가 모든 정적 파일을 `text/plain` 으로 서빙했다.**
  `.js` MIME 이 틀리면 브라우저가 **ES 모듈 import 를 거부**한다 → SPUM Engine 붙이기 전 필수 수정이었다.
- `proto/index.html`(v1) 타일 좌표 off-by-one — `map.json` 좌표는 1-based 인데 0-based 로 읽고 있었다.
- `vendor/` 65파일 복구 + `mirror.mjs` 를 레포에 넣음.

### 2-7. 해커톤 세션 2차에서 틀렸던 것 (중요)

1. **과제정의서를 안 읽고 P1을 제안했다.**
   회사 과제정의서 원본이 **처음부터 로컬에 있었는데** 열어보지 않았다(현재 `_local/회사자료/`).
   `handoff → work-rules → game-spec` 체인만 따라가서 요건 문서에 도달하지 못했다.
   → **`CLAUDE.md` §2 에 "과제정의서 먼저" 를 1번으로 박았다.**
   시야 제한은 성공기준에도 보너스에도 없는데 "기획의 핵심"이라며 최우선으로 제안했다.

2. **틀린 브라우저를 썼다.** 앱 내장 `Claude_Browser` 로 SPUM 접근을 시도해 차단당하자
   "권한 문제"로 오진하고 주영님께 잘못된 선택지를 물었다. 실제로는 `claude-in-chrome`(실제 크롬)을 썼어야 했다.

3. **`packages/spum-world/` 를 통째로 안 쓰고 있었다.** 과제정의서 §3·§9 가 명시한 제공자료인데
   미러링조차 안 돼 있었다. 해커톤 세션 2차에서 23파일 확보.

4. **스프라이트 판단이 두 번 틀렸다.**
   - handoff 는 "3/5 고유"라 했으나 실제로는 **2/5**(꾸벅이=폴짝이=새침이, 오물오물=살살이).
   - "스프라이트 시트가 없다"고 단정했으나 `proto/assets/chars/sheets/` 에
     **새침이·폴짝이 idle 시트가 있었다** (1024×256, 128px 15프레임, 30fps, 배경 투명, `characterName` 검증됨).
     → `Animator` 기반 애니메이션이 **가능하다.** 나머지 3명 시트만 Cast Editor 에서 추출하면 된다.

### 2-9. 공개 레포 위생 — 처리 완료

이 레포는 **공개**다. 초기에 공개에 부적합한 자료가 섞여 있었고, 매니저가 정리를 마쳤다.
현재 회사 제공 자료·내부 문서·키는 전부 로컬 `_local/`(비커밋)에만 있다.

**지켜야 할 규칙 (이게 핵심):**
- 커밋 전 1초 자문 — *"이거 공개 레포에 올라가도 되나?"*
- 회사 제공 문서·그 파생 요약·타사 조사·내부 자료 → `_local/`
- 키는 전체든 **접두사든** 어떤 문서에도 적지 않는다
- 작업 이력에도 **사고 상세(경로·해시·노출 값)를 적지 않는다** —
  기록이 그 자체로 이정표가 된다. 교훈만 남긴다.
