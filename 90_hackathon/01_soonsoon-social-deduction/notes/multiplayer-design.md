# 멀티플레이 설계 — 사람 3 + AI 3

> **상태: 설계안. 아직 한 줄도 구현하지 않았다.**
> 작성 2026-08-21 (발표·채점 후). 기획은 `game-spec.md`, 진행 현황은 `handoff.md`.
>
> 이 문서의 목적은 **1단계를 시작할 수 있게 규칙 모듈의 계약을 못박는 것**이다.
> 계약이 흐린 채로 코드를 짜면 싱글과 멀티가 갈라지고, 그때부터는 되돌리기 어렵다.

---

## 0. 왜 이걸 만드나

보통 마피아 게임 앱에는 **AI가 없다.** AI 마피아 실험에는 **캐릭터도 공간도 없다**(팀원이 만든 것도 채팅창뿐이었다).

둘을 합치면 이런 게 나온다:

> 한 방에 사람 3명 + AI 3명. **누가 사람이고 누가 AI인지 모르는 채로** 마피아를 찾는다.

이건 지금 만든 것에서만 나오는 물건이다. 멀티를 한다면 이 방향이 맞다.

---

## 1. 지금 구조로는 왜 안 되나 (실측)

| 확인한 것 | 파일 | 멀티에서 무슨 일이 나나 |
|---|---|---|
| 역할 배정·승패 판정이 **브라우저 안** | `src/mafia/roles.js` | 클라가 자기 역할을 정한다 = 게임이 아니다 |
| 투표 집계가 브라우저 안 | `src/mafia/round.js` | 표를 조작할 수 있다 |
| 서버는 **상태 없는 프롬프트 중계기** | `server.mjs` `/api/mafia-turn` | 클라가 "나 마피아야"라고 하면 **그냥 믿는다** |
| 죽은 사람을 **화면에서만** 가림 | `src/mafia/ghost.js` `GhostVisibility` | 데이터는 그대로 있다 → 개발자도구로 다 보인다 |
| 위치를 클라가 각자 시뮬레이션 | `src/world.js` | 클라마다 좌표가 어긋난다 |

**한 줄로:** 지금은 *"나 자신을 상대로 하는 게임"* 이라 클라이언트를 믿어도 됐다. 남이 들어오는 순간 그 전제가 통째로 무너진다.

> ⚠ 흥미로운 대비: **케이크 판은 이미 서버에 정답이 있다**(`night.mjs` `newGame` — 범인·기억을 서버가 만든다).
> 마피아 판만 클라이언트에 있다. 싱글 전용으로 빨리 만들다 그렇게 됐다.

---

## 2. 핵심 결정 — 규칙서는 하나, 호스트는 둘

싱글용 규칙과 멀티용 규칙을 **두 벌로 짜면 반드시 갈라진다.** 한쪽만 고치는 날이 오고, 그때부터 "싱글에선 되는데 멀티에선 안 되는" 버그가 나온다.

마인크래프트가 쓰는 방식을 그대로 쓴다 — **integrated server**:

```
규칙 엔진 (순수 모듈)
   입력: 행동(action)  →  출력: 새 상태 + 각자에게 보낼 것
   ├─ 싱글 : 브라우저 안에서 그대로 실행    ← 오프라인 가능, 지금과 같은 경험
   └─ 멀티 : Node 에서 실행 + WebSocket
```

**싱글이 없어지는 게 아니라, 싱글이 「나 혼자 접속한 멀티」가 된다.**

### 이미 1단계를 조금 했다

평가 하네스를 만들면서 두 개를 순수 모듈로 뺐다 — 같은 이유(측정기와 게임이 같은 부품을 써야 한다)였다.

- `src/similar.js` — 되풀이 판정
- `src/mafia/attitudes.js` — 발언 태도 목록·굴리는 규칙

규칙 엔진 분리도 같은 작업의 연장이다.

---

## 3. 규칙 엔진 계약 ★ 1순위

**이것만 못박히면 나머지는 따라온다.** 순수 함수로 둔다 — DOM 없음, fetch 없음, `Date.now()`·`Math.random()` 없음(전부 인자로 받는다). 그래야 테스트할 수 있고 서버·브라우저 양쪽에서 돈다.

```js
// rules/mafia.js  (제안)

/** 판을 연다. seed 를 받아야 같은 판을 재현할 수 있다 */
export function 새판({ 참가자, seed, 설정 }) → 상태

/**
 * 행동 하나를 적용한다.
 * @returns {{ 상태, 사건[] }}  사건 = 밖으로 알릴 일(누가 죽었다, 단계가 바뀌었다…)
 */
export function 적용(상태, 행동) → { 상태, 사건 }

/** 시간이 흐른다. 타이머·NPC 판단은 전부 여기서 (setTimeout 을 규칙 안에 두지 않는다) */
export function 째깍(상태, 흐른ms) → { 상태, 사건 }

/** ★ 이 사람에게 보여도 되는 것만 남긴다 — 보안의 핵심 */
export function 시야(상태, 참가자id) → 공개상태
```

### 행동(action) 목록

| 행동 | 누가 | 언제 |
|---|---|---|
| `이동` | 사람 | 아무 때나 (좌표 아니라 **입력 방향**을 보낸다 — §5) |
| `잠자기` | 사람 | 밤 · 자기 방 |
| `살해` | 마피아 | 밤 · 대상이 근접 |
| `발언` | 사람·AI | 저녁·토론 |
| `지목` | 사람·AI | 투표 |

### 사건(event) 목록

`단계바뀜` · `사망` · `처형` · `발언` · `취침` · `게임종료`

> **규칙 엔진은 SAM 을 부르지 않는다.** AI 발언은 바깥(서버)이 만들어 `발언` 행동으로 밀어 넣는다.
> 규칙이 네트워크를 타면 순수하지 않게 되고, 테스트도 재현도 안 된다.

---

## 4. 시야 필터링 — 이게 "진짜 멀티"를 가른다

`시야(상태, 참가자id)` 가 **숨길 것을 아예 안 보낸다.** 화면에서 가리는 것과는 완전히 다른 일이다.

| 참가자 | 볼 수 있는 것 |
|---|---|
| 시민(깨어 있음) | 자기 주변 · 살아있는 사람들의 위치 · 공개 대화 |
| 시민(잠듦) | **반경 118px 안만**(현재 값) — 마피아가 다가오는 걸 그 안에서 본다 |
| 마피아 | 위 + 동료 마피아가 누구인지 |
| 유령 | 전부 (관전) |
| **아무도** | 남의 역할, 아직 안 나온 밤 결과 |

**검증 방법:** 서버가 보낸 스냅샷을 그대로 덤프해서 `role` 필드가 남의 것까지 들어있는지 본다. 눈으로 화면을 보는 걸로는 검증이 안 된다.

---

## 5. 위치 동기화 — 가장 어려운 곳

이 게임 최고의 장면이 **"자다가 마피아가 다가오는 걸 본다"** 인데, 그게 세 가지에 동시에 걸려 있다:

- 위치 (`transform.x/y`)
- 시야 반경 (잠들면 118, 깨어 있으면 210)
- 근접 살해 판정 (`살해거리`)

지연이 있으면 이 장면이 무너진다.

**제안: 서버 권한 + 클라 보간.**

- 클라는 **좌표가 아니라 입력**(방향·눌린 키)을 보낸다. 좌표를 보내면 순간이동이 가능해진다.
- 서버가 15~20Hz 로 시뮬레이션하고 스냅샷을 뿌린다.
- 클라는 받은 스냅샷 사이를 보간해서 그린다.
- 자기 캐릭터만 **예측**해서 즉시 움직이고, 서버 값과 어긋나면 부드럽게 당긴다.

친구끼리 하는 규모(6명)면 이걸로 충분하다. 롤백 넷코드 같은 건 필요 없다.

> ⚠ 현재 이동 속도는 `NavAgent`·`Walker` 모두 110. 서버 시뮬레이션도 같은 값을 써야 한다 —
> 이 숫자가 두 곳에 흩어지면 드리프트가 시작된다(§8-5). 규칙 엔진의 `설정` 으로 넘긴다.

---

## 6. AI 참가자

**서버가 돌린다.** 클라마다 각자 AI를 부르면 사람마다 다른 대사를 보게 된다.

- 빈 자리를 AI로 채운다 (사람 3 + AI 3)
- 서버가 `askMafiaTurn` 을 부르고, 받은 대사를 `발언` 행동으로 규칙 엔진에 넣는다
- 되풀이 필터(`similar.js`)·태도(`attitudes.js`)는 **지금 것을 그대로** 쓴다

### 사람인지 AI인지 숨긴다

참가자 목록에 `사람/AI` 를 **보내지 않는다.** 그게 이 모드의 재미 전부다.

> 다만 AI는 항상 몇 초 안에 답하고 사람은 들쭉날쭉하다 — **응답 속도로 티가 난다.**
> AI 발언에 사람 같은 지연을 넣어야 한다(지금도 `생각시간()` 이 있다. 그 값을 재검토).

---

## 7. 이탈·재접속 — 빼먹으면 판이 멈춘다

지금 밤은 **"마피아 뺀 전원이 잠들 때까지"** 기다린다(`sleep.js` `모두잠들었나`). 한 명이 나가면 **영원히 안 넘어간다.**

| 상황 | 처리 |
|---|---|
| 밤에 이탈 | 자동 취침 처리. 판은 계속 |
| 토론 중 이탈 | 침묵으로 취급 |
| 투표 중 이탈 | 기권 (동률·기권과반 규칙이 이미 있다) |
| 재접속 | 같은 자리로 복귀. 규칙 엔진 상태는 서버에 있으니 스냅샷만 다시 보내면 된다 |
| 마피아가 이탈 | **AI가 이어받는다.** 안 그러면 밤이 진행되지 않는다 |

모든 단계에 **상한 시간**을 둔다. 이미 낮 120초·토론 150초·지목 10초가 있으니 그 값을 규칙 엔진으로 옮긴다.

---

## 8. 비용 — 이게 실질적 제약이다

방 하나가 한 판에 SAM 을 수십 번 부른다. **방 개수 × 판 수만큼 계정에서 나간다.**

공개하려면 이건 선택이 아니라 필수다:

- 동시 방 수 상한
- 하루 총 판 수 상한
- 방당 AI 인원 상한
- 유휴 방 자동 종료
- 판당 호출 수 상한 (초과하면 AI가 침묵)

> 링크만 알면 누구나 열 수 있는 상태로 두면 **남이 내 돈을 쓴다.**

## 9. 단계 [추정]

| 단계 | 내용 | 대략 |
|---|---|---|
| 1 | 규칙 엔진 분리 (§3 계약대로) + 싱글을 그 위로 옮기기 | 2~3일 |
| 2 | WebSocket · 방 만들기 · 입장 | 2~3일 |
| 3 | **위치 동기화** ← 제일 어렵다 | 3~5일 |
| 4 | 시야 필터링 | 2일 |
| 5 | AI 를 서버에서 구동 · 브로드캐스트 | 2일 |
| 6 | 이탈·재접속·타임아웃·비용 상한 | 2일 |

**파트타임 2~3주.** 정확한 값이 아니다.

**1단계가 끝나면 멀티를 안 해도 이득이다** — 규칙이 순수 모듈이 되면 그때부터 게임 규칙을 **브라우저 없이 테스트**할 수 있다. 지금은 투표 집계를 확인하려고 판정 로직을 손으로 베껴 검증했다(7/7 통과했지만, 그건 **베낀 코드**를 검증한 것이지 진짜 코드를 검증한 게 아니다).

## 10. 하지 않는 것

- 랭킹·매치메이킹·계정 — 친구끼리 링크로 들어오면 된다
- 롤백 넷코드 — 6명 캐주얼에는 과하다
- 모바일 대응 — 나중에
- 음성 채팅 — 그러면 AI를 구분하는 게 너무 쉬워진다. **텍스트가 이 게임의 조건이다**

---

## 11. 결정해야 할 것

1. **방 크기** — 6명 고정인가, 4~8 가변인가. 지금 맵의 방이 6개라 6이 자연스럽다
2. **AI 비율** — 사람이 적으면 AI를 더 채우나, 아니면 최소 인원을 기다리나
3. **호스팅** — Render/Fly/직접. WebSocket 이 필요하므로 정적 호스팅은 불가
4. **비용을 누가 내나** — 이게 정해져야 §8 상한값이 정해진다
