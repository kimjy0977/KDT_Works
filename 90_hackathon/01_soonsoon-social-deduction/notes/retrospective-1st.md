1. **결과물은 성공했다.** 과제 성공기준 4/4 충족, 발표·채점 완료, 회사가 2차를 제안했다.

## 1. ⛔ 이 회고의 핵심 — 사고 3건은 같은 병이다

### 실제로 일어난 것

| 날짜 | 무슨 일 | 그때 규칙은 |
|---|---|---|
| **08-19** | 과제정의서·SAM 키가 **public 에 올라감** → history 재작성 | **없었다** |
| **08-27** | SPUM 에셋 **67개·13MB** 가 public 에 있던 것 발견 → 레포 분리 | **`vendor/` 만 덮고 있었다** |
| **08-28** | GMDV 추출 때 **`.env` 차단 규칙이 안 따라옴** | **대상보다 위에 있었다** |

### 왜 매번 새로 뚫렸나

```
08-19  규칙이 없었다          → 규칙을 만들었다 (_local/)
08-27  규칙이 한 종류만 덮었다 → 종류를 늘렸다 (assets 추가)
08-28  규칙이 대상보다 위에 있었다 → ???
```

**앞의 두 번은 「규칙을 추가」해서 막았다. 그래서 세 번째가 뚫렸다.**
규칙을 아무리 늘려도 **「규칙과 대상의 위치 관계」**라는 축은 안 덮인다.

> ★ **파일 단위 방어는 원리상 다 못 막는다.**
> 파일마다 규칙이 붙어야 하는데, 파일은 **생기고 옮겨지고 추출된다.**
> 규칙이 그 이동을 따라가지 못하는 순간이 사고 지점이다.

### 그래서 2차의 방침이 바뀌었다

```
1차   회사 자료를 가져오되 _local/ 로 가린다   ← 가리는 것
2차   애초에 안 가져온다 (레포를 가른다)       ← 경계 그 자체
```

**공통운영규칙 §B-1 로 승격됨**(2026-08-30). 파일이 아니라 **레포**가 갈리면,
실수해도 공개 레포에 **닿을 수가 없다.**

## 2. 무엇이 먹혔나 — 2차에 그대로 가져갈 것

### 2-1. ★ 회귀 검사 319항목

**이게 1등이다.** SAM 호출 0회로 규칙·배선·맵을 검사한다.

- 프롬프트를 크게 뜯어고칠 때, 저장소를 갈라낼 때, 폴더를 이사할 때 —
  **전부 「319/319 통과」 하나로 안전을 확인**했다
- 특히 **이사 검증**에 결정적이었다. 파일 24,604개를 옮기고
  *"게임이 여전히 도는가"* 를 5초에 답할 수 있었다

> **2차에서 제일 먼저 만들 것.** 기능보다 먼저다.

### 2-2. 신뢰도 5단계 표기

★★★★★(직접 확인) ~ ★☆☆☆☆(미확인). 보고서 전체에 붙였다.

- **모르는 것을 모른다고 쓸 자리**가 생겼다. 그러니 과장할 필요가 없어졌다
- 대표님께 *"저희 환경에서 잰 값이니 한 번 재보시라"* 고 말할 수 있었다
- ⭐ **남의 항목엔 우리가 등급을 안 매겼다** — 한 번 실수해서 남이 내려둔 등급을
  올려버렸고, 되돌렸다

### 2-3. 함정을 즉시 기록 (`work-rules.md` 114건)

막힌 순간에 **바로** 적었다. 나중에 몰아 쓰면 «왜 막혔는지»가 사라진다.

- 이 기록이 **보고서 §03 의 근거**가 됐다 — 회사에 드린 요청 A1~A9 가 전부 여기서 나왔다
- 회사가 *"안내 못 해서 미안하다"* 고 한 것도 **구체적 근거가 있었기 때문**이다

### 2-4. 정정은 덮어쓰지 않고 append

틀린 결론이 나온 실험도 **왜 틀렸는지의 근거**다. 지우면 다음 사람이 같은 가설을
처음부터 다시 세운다.

### 2-5. 백업을 먼저 뜬다

08-27 레포 분리 때 `.git` 142MB 를 먼저 떴다. 이사 때도 **복사 → 해시 대조 → 삭제** 순서였다.
**되돌리기가 스크립트가 아니라 현물**이면 판단이 과감해진다.

## 3. 무엇이 안 먹혔나

### 3-1. ⛔ 프롬프트로 LLM 을 막으려 한 것 — **세 번 다 실패**

길이 · 되풀이 · 편향, 셋 다 «하지 마라»로 안 됐다.

| | 결과 |
|---|---|
| 금지 조항 추가 | 쏠림 **안 줄고** 근거 대는 비율만 올라감 |
| 몰이 근거 8가지를 **나눠 줌** | 최다 득표 **80% → 57.9%** |

> **못 하게 막는 것보다 「갈 곳」을 여러 개 주는 편이 먹힌다.**
> 이건 회사 보고서 §05 에도 들어갔다 — AI NPC 를 쓰는 제품이면 공통일 것이다.

### 3-2. 「없는 줄 알고 다시 만들기」 — 하루에 세 번

`replay.html`(200줄·배포까지 완료) · `api/` 폴더 · `DEPLOY.md` 를 다시 만들려 했다.

**원인이 셋 다 같다: grep 만 하고 `ls` 를 안 쳤다.**
grep 은 «내가 상상한 이름»만 찾는다. 폴더는 실제를 보여 준다.

### 3-3. 자체 기획서를 과제 요건으로 착각

`game-spec.md` 가 «핵심»이라 부른 기능이 **과제 채점표엔 없었다.**
우선순위를 거꾸로 잡았다.

> **자체 기획 ≠ 과제 요건.** 원문을 먼저 읽는다.

## 4. ★ 가장 값진 교훈 — 「간접 증거로 판정하지 말 것」

**세션 셋이 마지막 주에 전부 같은 실수를 했다.** 우연이 아니라 구조다.

| 누가 | 무엇을 보고 판정했나 | 실제로 봤어야 할 것 |
|---|---|---|
| 매니저 | 말과 말을 비교 | `git log` 한 줄 |
| 매니저 | `grep "수신함"` — **낱말** | 문장의 **뜻** |
| 매니저 | 허브 숫자(= 자기가 넣은 **파생값**) | 강의노트 **원본** |
| **빌더(나)** | `git log` — **커밋된 것** | `git status` — **미커밋** |
| 튜터 | 지표(인용 1등) | **산출물**(사실정확 0/7) |
| 튜터 | 검증 안 된 자로 잰 수치 | **자를 먼저 검사** |

**앞의 넷은 「안 본 것」이고, 뒤의 둘은 「봤는데 잘못된 것을 봤다」이다.**
뒤가 한 겹 더 깊다 — 지표도 봤고 숫자도 봤는데, 그 지표가 제품을 대표하지 않았다.

> 공통운영규칙 **§F-8-A** 로 통합됨. 세션 시작 체크리스트에 한 줄이 들어갔다:
> **«이걸 확인했다고 쓰는데, 무엇을 열어봤나?»** 못 대면 «미확인»으로 적는다.

### 나(빌더)의 구체적 사례 3건

1. **커밋만 훑고 «미팅 기록 없다»고 보고** — 커밋 안 된 로컬 문서 3개가 내 작업장에 있었다.
   디렉터가 «정리한 거 있을 텐데» 라고 물어서 잡혔다.
   → **커밋은 「올린 것」이지 「한 것」이 아니다.**
2. **「디렉터 결정」으로 격상 전달** — 방향을 말씀하신 것을 확정으로 옮겼다.
   GMDV 개발팀이 검증해서 잡았다. → **「~할 거야」는 방향이지 결정이 아니다.**
3. **표본을 뽑고 세기 전에 안 읽음** — 옛 표현으로 세어 «0%» 를 만들었다.

## 6. 회사와의 관계 — 이건 잘 됐다

**결과물만 내고 끝나지 않은 것**이 이번의 성과다.

- 막힌 것 **37건**을 정리해 드렸고, 그중 **9건은 「문서 한 줄이면 안 막혔을 것」**이었다
- 회사가 **「안내 못 해서 미안하다」**고 했고, **2차 전에 규칙 문서·GitHub 환경·
  파트너 라이선스를 만들어 주기로** 했다
- **1차 에셋 사고의 책임 소재가 정리됐다** — 우리 진단(「규칙이 한 종류만 덮고 있었다」)과
  회사 인식이 일치했다

> 보고서를 만든 동기가 ① 우리 공부 ② 회사에 실제로 남는 것 이었는데,
> **②가 2차 해커톤이라는 형태로 돌아왔다.**
