## A. SPUM Studio 조작

**A-1. 쓰기 방향은 반드시 `로컬 → 서버`**
```js
window.spumStudioData.export();                    // ① 백업 먼저 (항상)
localStorage.setItem(KEY, JSON.stringify(data));   // ② 로컬에 쓰기
window.dispatchEvent(new CustomEvent("spum:studio-storage-write",{detail:{key:KEY}}));
window.spumStudioData.saveServerSnapshot("manual");// ③ 서버로 올리기
// ④ 페이지 새로고침해야 앱이 읽는다
```
> ❌ **서버에 직접 `PUT /api/studio/state` 하지 말 것.** 다음 새로고침 때 브라우저 로컬이 서버를 덮어써서 작업이 사라진다. (팀원이 3번 당함)

**A-2. 캐스트 "배치"만은 코드 금지**
`world.casts[]`에 항목을 코드로 만들면 앱이 *"없는/중복 캐릭터 배치 N개를 정리했습니다"* 로 **전부 삭제**한다. → World Editor 좌측 `Characters`의 **`+` → "배치"** 버튼으로. 한 명씩 누르고 확인(연속 클릭은 리렌더로 씹힘).
※ 캐릭터 **생성·수정·삭제**, **외형·색상**, **맵 레이어**, **월드의 mapId 교체**는 코드로 잘 된다.

**A-3. 세션은 30분 안팎으로 만료된다 → 자동 복구**
`/api/me`가 `{"user":null}`이면 만료. 우측 상단 `SSAM … 로그인 필요` 배지 → ACCOUNT 패널 → **「다시 로그인」** → 4초. **비밀번호 안 물어봄**(SSO 살아있으면). 복구 후 `saveServerSnapshot("manual")`로 재동기화.

**A-4. Cast Export(스프라이트 시트)는 신뢰하지 말 것 — ★ 막는 법 확정(2026-08-24)**
Generate가 비동기라 **직전 캐릭터의 시트가 다운로드된다.** 받은 뒤 반드시 JSON의 `characterName`으로 검증할 것.

**왜 그런지 눈으로 봤다.** Export 패널 진행바가 `Generating 12/15` → `Sheet ready` 로 간다.
캐릭터를 바꿔도 **미리보기와 「Sheet ready」는 이전 캐릭터 것이 그대로 남는다.**
그 상태에서 다운로드하면 남의 시트가 내 이름으로 내려온다.

**절차 (이대로 하면 안 어긋난다):**
1. 캐릭터 선택 → **ANIMATION·CUSTOM FRAMES 를 먼저 맞춘다** (idle 15 / move 10)
2. **`Generate` 를 반드시 다시 누른다.** 캐릭터만 바꾸고 받으면 안 된다
3. 진행바가 **`Sheet ready`** 가 될 때까지 기다린다
   ⚠ `Preview is still loading` 중에 누른 Generate 는 **씹힌다**(실제로 겪음)
4. `PNG + JSON` 다운로드 → JSON 의 `characterName`·`state`·`clipId`·`totalFrames` 확인
5. **PNG 의 md5 가 다른 시트와 겹치지 않는지** 본다 ← 이걸 안 해서 사고가 났다

**⛔ `Frame grid` 체크는 끈다.** 프레임 경계에 격자선이 구워질 수 있다.
(껐을 때 경계 열 불투명 픽셀 **0** 으로 확인함)

**실제 사고:** `주춤이` 의 idle 과 move 가 **완전히 같은 PNG**(md5 일치)였다.
게다가 idle 의 `clipId` 가 `legacy/01_Move/0_move` — **가만히 서 있을 때도 걷는 애니메이션**이
돌고 있었고, 그 상태로 발표까지 갔다. `characterName` 만 봐서는 못 잡는다.
**두 시트의 md5 를 비교해야** 잡힌다.

**A-4b. `characterId` 없는 export json 은 의심할 것**
정상 export 는 `characterId` + `exportDate` 를 담는다. 이게 빠진 파일은 손으로 만들었거나
복사한 것이다. 실측에서 이 표식이 없던 3개(주춤이·딴청이·또박이) 중 **주춤이가 실제로 깨져 있었다.**

**A-5. 썸네일은 코드로 외형을 바꿔도 갱신 안 된다**
`localStorage` 패치로 `appearance`를 바꿔도 `sv_studio_thumb_*`는 예전 이미지 그대로. 목록/추출물이 쌍둥이로 보이면 이것 때문.

**A-6. 타일셋 셀 크기는 이미지에서 계산할 것**
`mapTheme.grid`가 `"16x16"`이어도 셀이 64px이라는 뜻이 아니다. **셀 = 이미지폭 ÷ 16**. 실제로 192×192 이미지라 **셀 12px**이었고, 64로 착각해 한참 헤맸다.

## B. 브라우저 자동화

**B-1. 네트워크/DOM 덤프로 base64를 뽑지 말 것**
`read_network_requests`로 이미지 요청을 조회하면 **base64가 통째로 쏟아져 컨텍스트가 순식간에 고갈된다.** 반드시 필터링해서 개수·상태코드만 볼 것.

**B-2. `javascript_tool` 반환값이 차단될 때가 있다**
쿠키/쿼리스트링/대용량이 섞이면 `[BLOCKED]`. → **`document.title`에 값을 써서 탭 제목으로 읽는 우회가 잘 통한다.**

**B-3. iframe 안을 봐야 할 때가 있다**
Object Tile Editor는 `/studio/pixeldeidtor/index.html` iframe. 부모 document 쿼리로는 아무것도 안 잡힌다. → `document.querySelector('iframe[src*="pixeldeidtor"]').contentDocument`

**B-4. 커스텀 드롭다운은 화면 클릭으로 안 열린다**
네이티브 `<select>`가 아니면 스크린샷에 팝업이 안 뜬다. iframe 내부 `<select>`를 찾아 `value` 설정 후 `input`/`change` 이벤트를 dispatch.

**B-5. 프리셋을 바꾸면 프롬프트가 덮어써진다**
Object Editor에서 Preset 변경 시 Reference Prompt가 프리셋 기본값으로 리셋된다. **프리셋 먼저 → 프롬프트 나중.**

## H. 맵 데이터 (2026-08-19 레이어 재구성에서 얻음)

**H-1. 시각 레이어와 통행(obstacle)을 같은 함수에서 쓰지 말 것.**
한 함수가 둘 다 건드리면 **러그가 벽이 된다.** 그림을 어디에 얹을지와 걸어갈 수 있는지는
별개 판단이다. 우리 `stamp()` 는 그림만 얹고, 통행은 마스크 문자로만 정한다.

**H-2. 손으로 찍은 좌표엔 반드시 walkable 검사를 붙일 것.**
같은 실수를 두 번 했다 — 맵 생성기(가구가 문을 봉인)에서 한 번, NPC 소집 지점(모임 지점이
라운지 가구 위)에서 또 한 번. 눈으로는 절대 안 보인다.

**H-3. 스탬프가 벽 위에 걸치는 칸을 조심할 것.**
예전 코드는 마스크의 `.` 칸에 `obstacle = 0` 을 **강제로** 써서 벽에 구멍을 뚫고 있었다.
지금은 뚫지 않고, "밟을 수 없으면 러그가 아니다" 규칙으로 가구로 강등한다.
**강등 건수를 로그로 찍는다** — 조용히 넘어가면 다음 사람이 모른다.

**H-4. 휑한 정도는 눈이 아니라 숫자로 본다.**
`build-map.mjs` 가 **맨바닥 비율**과 **구역별 가구 점유율**을 찍는다.
현재 맨바닥 91% — 이게 "휑하다"의 정체다. 개선하면 이 숫자가 내려가야 한다.

**H-5. 맵 스키마는 SPUM 과 같은 `layers[]` 배열로 둔다.**
객체(`{back_1:…, front_1:…}`)로 두면 **순서 정보가 없어** 다중 레이어를 표현할 수 없고,
Studio 로 밀어넣을 때 변환이 필요하다. 배열 순서가 곧 렌더 순서다.

**H-6. 넓은 면에 깔 타일은 눈으로 고르지 말고 `tools/tile-report.mjs` 로 고를 것.**
타일 173장을 사람이 일일이 보는 건 비현실적이다. 도구가 픽셀에서 3가지를 계산한다:
`flat`(내부 색 분산) · `tileH`/`tileV`(좌↔우, 상↔하 가장자리 일치도). 점수가 낮을수록 안전.

```bash
node tools/tile-report.mjs        # 상위 후보 + 현재 맵이 쓰는 타일의 순위
```

현재 바닥으로 쓰는 `2280` 은 **10위/256** 이었다(선택이 맞았다는 확인).
반대로 부엌 체크무늬 `2092` 는 190위 — 넓게 깔면 무늬가 튄다.

**H-7. ⛔ 이 시트로는 러그·카펫을 넓게 깔 수 없다 (측정으로 확인).**
점수 40 이하(넓은 면에 안전)인 타일이 **256장 중 6장뿐이고 전부 갈색 원목 계열**이다.
**비-갈색 계열은 0장** — 최고점이 123.6 으로 안전 기준의 3배다.
러그 타일 29종은 전부 4칸씩 흩어져 있고 순위도 68~222위 — **가구와 한 덩어리로 그려져 있어
떼어낼 수 없다.**

→ **맨바닥 비율을 낮추려면 새 타일이 필요하다.** 기존 시트 재배치로는 안 된다.
   필요한 것: ① 평평하고 사방으로 이어지는 **러그/카펫** ② `front_1` 용 **덮개 조각**(문틀 상인방 등).
   둘 다 Object Editor 작업이다.

**H-8. 이미지 모델에 `seamless` 를 요구하지 말 것. "평평한 단색 면"을 요구할 것.**
AI 타일 생성 1차에서 "MOSTLY seamless … edge-matching" 이라고 썼더니 안전 타일이 **0장**
나왔다. 2차에서 "**PLAIN FLAT COLOR FIELD**, no borders, no objects, almost uniform" 로
바꾸고 품질을 올렸더니 **최고점 27.6**(기존 시트 최고 32.7보다 좋음)이 나왔다.
**균일한 칸은 좌우·상하 가장자리가 자동으로 일치한다** — 이어붙임은 결과지 목표가 아니다.

**H-9. 점수 임계선은 40이 아니라 ~50이다.**
현재 803칸에 깔려 있는 바닥 `2280` 이 **43점**인데 멀쩡하다. "안전 ≤40" 은 처음에 임의로
잡은 선이었다. 실무 임계는 **50 안팎**으로 보고, 그 이상은 눈으로 확인할 것.

**H-10. 레이어 하나에 타일셋을 섞지 말 것 — 조용히 사라진다.**
러그를 얹으면서 실제로 냈다. `back_2` 에 스탬프에서 나온 본 테마 ID(2049~) 28칸과
AI 러그 ID(4097~) 187칸이 **섞여 있었다.** 렌더러는 레이어당 `TileSet` 이 하나뿐이라
범위 밖 ID 는 **에러 없이 안 그려진다** — 픽셀 검사도 통과해 버렸다(러그가 다수라).

→ 레이어를 갈랐다(`back_2` 스탬프 러그 = main / `back_3` AI 러그 = rug).
→ **빌드 검증기를 붙였다.** 레이어의 모든 ID 가 그 레이어 타일셋의 범위
   `[tileIdBase, tileIdBase+256)` 안에 있어야 하고, 아니면 빌드가 실패한다.

> 교훈: **"화면에 보이니 됐다"는 검증이 아니다.** 다수 타일이 정상이면 소수의
> 사라진 타일은 픽셀 비율로 안 잡힌다. 데이터 불변식을 직접 검사해야 한다.

**H-11. 지표에 과최적화하지 말 것 — 눈으로 볼 방법을 먼저 확보하라.**
"맨바닥 91%" 를 낮추려고 방 내부를 통째로 러그로 덮었더니 **카펫이 아니라 잔디밭**이 됐다.
숫자는 71% 로 좋아졌지만 화면은 나빠졌다. 러그는 "공간을 구분하는 점"이지 바닥재가 아니다.
→ 면적을 줄이고 톤을 통일(남색)하니 맨바닥은 86% 로 올라갔지만 **화면은 훨씬 낫다.**

**H-12. 게임 화면은 실제 크롬(`claude-in-chrome`)으로 직접 본다.**
앱 내장 브라우저는 창이 표시되지 않으면 스크린샷이 실패한다("Browser pane is not displayed").
**실제 크롬으로 `localhost:5173` 을 열면 그냥 보인다.** 이걸 몰라서 한동안 주영님께
"직접 봐 달라"고 떠넘겼다. 픽셀 비율 검사는 보조 수단이지 육안 확인의 대체가 아니다.

## I. SPUM Studio 저장 (2026-08-19 · 작업을 두 번 날리고 얻음)

**I-1. 저장은 세 가지가 동시에 성립해야 된다 — 하나라도 깨지면 조용히 실패한다.**
① 로그인(`/api/me` 에 user) ② `localStorage` 여유(약 5MB 한도) ③ 동기화 상태 정상.
어느 것이 깨졌는지 **앱은 알려주지 않는다.** `saveServerSnapshot()` 이 그냥 `false` 다.

**I-2. 무거운 작업(생성·Slice) 전에 용량부터 잰다.**
```js
let u = 0; for (const k of Object.keys(localStorage)) u += localStorage.getItem(k).length;
console.log((u/1048576).toFixed(2) + 'MB / 약 4.98MB');
```
32×32 테마 하나가 0.4MB 다. 여유가 0.5MB 미만이면 **만들기 전에 정리**한다.

**I-3. 만들었으면 그 자리에서 저장을 확인한다.**
`saveServerSnapshot()` 의 반환값이 `true` 인지, `spum_studio_server_sync_v1.revision` 이
올라갔는지 **둘 다** 본다. 나중에 확인하면 이미 늦다 — 새로고침이 서버 상태로 되돌린다.

**I-4. 진단 순서 (저장이 false 일 때)**
```js
await fetch('/api/me').then(r=>r.json())            // ① 로그인
// ② 용량 (위 I-2)
JSON.parse(localStorage.spum_studio_server_sync_v1) // ③ revision 이 멈춰 있나
// ④ fetch 를 가로채 요청이 실제로 나가는지 확인 — 안 나가면 클라이언트 사전 검사에서 막힌 것
```
**요청이 안 나가면 서버 문제가 아니다.** 로그인·용량·동기화 셋 중 하나다.

**I-5. 원인을 못 찾으면 거기서 멈추고 보고한다.**
실제로 위 셋이 다 정상인데도 저장이 안 되는 상태를 만났다(revision 110 고정).
재로그인·새로고침·용량 확보 모두 시도했으나 해소되지 않았다.
**추측으로 밀어붙이지 말 것** — 로컬 작업은 레포에 커밋해 두고, 제품 이슈로 기록한다
(`notes/spum-feedback.md` A-2).

## J. refs 클릭과 슬라이스 기준 (2026-08-19 · 해커톤 세션 5차)

**J-1. ⚠ refs 썸네일을 "구경"만 해도 테마의 슬라이스 기준이 바뀐다 ★★★★☆**

Object Editor 좌하단 refs 스트립에서 카드를 클릭하면 상태바에 `Reference opened in
Preview canvas` 가 뜬다. **미리보기일 뿐이라고 생각했는데 아니었다.**

증거(백업 2개 대조):

|---|---|
| 17:07 백업 (클릭 전) | `""` (비어 있음) |
| 클릭: refs 3번(= v2 그림) | |
| 18:16 백업 (클릭 후) | `sha256:bdbc02f3…` = **v2** |

그 사이에 한 일은 **refs 3번 클릭 하나뿐**이다. Slice 버튼은 누르지 않았다.

→ **refs 는 읽기 전용이 아니다.** 어떤 그림이 들어왔는지 확인할 목적이라도
클릭하기 전에 현재 `sliceBaseAssetId` 를 적어 두고, 끝나면 되돌릴 것.

```js
// 클릭 전에 반드시
```

**J-2. 문서의 "적용돼 있다"를 믿지 말고 해시를 직접 읽을 것 ★★★★★**

→ **"적용 완료" 기록은 시점 정보다. 작업 시작 전에 매번 다시 읽는다.**
읽는 법은 J-1 의 한 줄.

**J-3. 테마 소스 삭제는 IndexedDB 확인 후에 하면 안전하다 ★★★★★**

`localStorage` 의 `spum-map-theme-source-state:*` 를 지워도 **원본은
IndexedDB `spum-map-theme-source-library` 에 남는다**(`spum-feedback.md` A-4).
실측: 4.36MB 삭제 후에도 테마 5개·타일 수·World 렌더링 전부 이상 없었다.

절차: ① 「내 Studio 데이터 다운로드」 ② 백업에 해당 키가 있는지 `grep` ③ 삭제 ④ 렌더 확인

**J-4. 서버 저장이 막혔을 때 복구 절차 ★★★★★ (2026-08-19 실제로 성공)**

증상: 저장 토스트가 실패 · `saveServerSnapshot()` 이 `false` · **HTTP 요청조차 안 나감** ·
용량 배지 "확인 실패" · `GET /api/studio/state` 가 500 `studio_state_object_missing`.

원인과 근거는 `spum-feedback.md` A-6. 복구는 아래 순서로 한다.

1. **로그인부터 확인.** `fetch('/api/me').then(r=>r.json())` 에 `user` 가 있어야 한다.
   없으면 재로그인 먼저 (진단 중에 30분 만료로 끊기는 일이 실제로 있었다).
2. **백업.** ACCOUNT → 「내 Studio 데이터 다운로드」
3. **읽기만 빈 상태로 가로채고 앱의 상태기계를 태운다.**
   - `window.fetch` 를 갈아끼워 **GET `/api/studio/state` 하나만** 200 `{ok:true, state:{revision:<현재>, keys:{}}, storage:null}` 로 응답
   - **PUT 은 절대 가로채지 않는다** — 실제로 올라가는 건 로컬 원본이어야 한다
   - `spum:auth-expired` → (0.3초) → `spum:auth-user` 순서로 dispatch
     ⚠ `spum:auth-user` 만 쏘면 안 먹는다. 핸들러가 `_serverBackupSuspended` 가 true 일 때만 동작한다
   - PUT 응답을 확인하고 **반드시 `window.fetch` 를 원복**
4. **검증:** 진짜 `GET /api/studio/state` 가 200 · `activeRevision` 이 올라감 ·
   패치 없이 `saveServerSnapshot('manual')` 이 `true` · 용량 배지에 숫자가 뜸

⚠ 안전 조건: 빈 상태를 넣어야 `serverHasData=false` 가 되어
`if (serverHasData && !localHasData) → _replaceStudioData()`(로컬을 서버 것으로 덮어쓰기)가
**발동하지 않는다.** 서버 상태를 진짜처럼 꾸며 넣으면 로컬이 날아갈 수 있다.

## K. 평면도 한 장을 SPUM 맵으로 (2026-08-19 · 세 번 실패하고 얻음)

**K-1. ⭐ SPUM 은 테마를 맵에 넣을 때 격자 1칸당 타일 1개를 만든다 ★★★★★**

**K-2. 추측하지 말고 SPUM 이 가진 대응표를 읽을 것 ★★★★★**

```js
JSON.parse(localStorage.sv_studio_maps_v1).find(m=>m.id===MAPID)
```

## L. 캐릭터 시트·자동화 (2026-08-20 · 세션 6차)

**L-1. ⭐ 숨은 탭에서는 시트 생성이 멈춘다 ★★★★★**

Cast Editor 의 `Generate` 가 **`4/15` 같은 숫자에서 멈춘 채 영영 안 끝난다.**
오류도 없고 콘솔도 조용하다. 프레임 캡처가 렌더링에 의존하는데
**숨은 탭은 캔버스를 합성하지 않기** 때문이다.

```js
document.visibilityState   // "visible" 이어야 한다. "hidden" 이면 멈춘다
```

- `requestAnimationFrame` 을 `setTimeout` 으로 갈아끼워도 **안 된다**(실측).
- 탭이 하나뿐이어도 **크롬 창 자체가 뒤에 있으면** `hidden` 이다.
- 해결: 크롬 창을 화면 앞으로. `computer-use` 의 `open_application` 으로 가능하다
  (브라우저는 read 티어라도 **창 띄우기는 허용**된다).
- **작업 전에 사용자에게 "창을 덮지 마세요"라고 알릴 것.**

**L-2. ⭐ Export 는 파일명과 내용이 서로 다른 캐릭터를 가리킨다 ★★★★★**

A-4 를 정확히 다시 쓴다. "직전 캐릭터가 내려온다"가 아니라:

| | 따르는 것 |
|---|---|
| **파일명** | **다운로드 시점**에 선택된 캐릭터 |
| **내용** | **생성(Generate) 시점**의 캐릭터 |

실제로 `폴짝이_idle_sheet.json` 안에 **꾸벅이** 시트가 들어 있었다.

→ **`characterName` 을 읽어 저장하는 도구를 쓴다**(`proto/tools/` 에 두는 것이 낫다).
생성과 다운로드 사이에 **선택을 절대 바꾸지 말 것.**

**L-3. ⭐ 시트 프레임 가장자리에 1px 테두리 선이 있다 ★★★★★**

캐릭터가 프레임의 **67%(68×86 / 128×128)** 만 채우는데, 테두리 때문에
바운딩박스를 재면 **항상 128×128 이 나온다.** 그대로 그리면 시트 캐릭터가
초상 캐릭터의 **절반 크기**로 보인다.

```js
const IN = 3, A = 40;                    // 바깥 3px 무시, 알파 40 기준
for (let y = IN; y < fh - IN; y++) ...   // 이렇게 재야 68x86 이 나온다
```

`proto/src/sprite.js` 의 `내용영역()` 이 이 처리를 한다.
⚠ **"고쳤다"와 "효과가 있다"는 다르다.** 1차 수정 때 bbox 값을 안 찍어 보고
넘어갔다가 그대로 실패했다. 반드시 값을 출력해 확인할 것.

**L-4. SPUM 은 걷기를 `move`, 우리는 `walk` 이라 부른다**

`loadClips(slug, ["idle","walk"])` 는 `{slug}-walk.png` 를 찾는데
Export 파일은 `{slug}-move.png` 다. `sprite.js` 의 `파일이름` 맵이 잇는다.

**L-5. React UI 에 값을 넣는 규칙**

- `el.value = x` 는 **무시된다.** 네이티브 setter + `dispatchEvent` 를 써야 한다.
- **`<select>` 는 되돌려진다.** 값을 넣어도 React 가 원래 값으로 복구한다.
  → 격자처럼 `<select>` 와 숫자칸이 짝인 경우 **숫자 입력칸에 직접** 넣으면 먹는다.
- Object Editor 본문은 **iframe 안**이다. `contentWindow` 의 prototype 을 써야 한다
  (부모의 `HTMLInputElement.prototype` 을 쓰면 안 먹는다).

```js
const w = document.querySelector("iframe").contentWindow;
Object.getOwnPropertyDescriptor(w.HTMLInputElement.prototype, "value").set.call(el, v);
el.dispatchEvent(new (w.Event)("input", { bubbles: true }));
```

**L-6. `canvas-size-input` 은 격자가 아니라 캔버스 픽셀 크기다**

64×40 을 넣었더니 **64×40 픽셀짜리 캔버스**가 됐고, 생성 후 1024×1024 로 되돌아갔다.
격자는 `Map Theme Settings` 의 `GRID` 옆 숫자칸이다. 이름이 비슷해 헷갈린다.

**L-7. 새 SMO 는 격자 16×16 · 품질 Low 로 시작한다**

`New SMO` 로 만든 테마는 기본값이 낮다. **생성 전에 둘 다 확인**할 것.
(격자는 L-5 대로 숫자칸에, 품질은 `<select>` 에 `high`.)

**L-8. `josa()` 는 조사만이 아니라 단어+조사를 돌려준다**

```js
josa("오물오물", "이/가")   // → "오물오물이"   (조사만 아님)
```
앞에 이름을 또 붙이면 `오물오물오물오물이` 가 된다. 실제로 그렇게 냈다.

## M. 통행 판정 — 픽셀로 가르려 하지 말 것 (2026-08-20 · 해커톤 세션 7차)

**M-1. ⛔ 우주선 테마는 벽과 바닥이 같은 회색이다 ★★★★★**

셰어하우스가 잘 갈린 건 **벽이 두꺼운 갈색 나무**였기 때문이다. 재질이 달랐다.
금속 테마는 벽·바닥·기계가 전부 무채색 회색이라 **색으로도 분산으로도 안 갈린다.**

실패한 지표(전부 오버레이까지 그려서 눈으로 확인함):

| 지표 | 결과 |
|---|---|
| 국소 분산(`flat`) | 임계 40 에서도 통행 25% — 셀(16px)이 그림의 바닥 타일(16px)과 같은 크기라 **셀마다 이음선이 들어간다** |
| 최빈색 점유율(`uni`) | 통행 18%, 최대 덩어리 60칸 — **복도가 토막남** |
| 팔레트 커버리지 | 벽 회색(72)이 바닥 후보로 뽑혀 **벽이 통행 가능**해짐 |
| 영역 분할 + 두께 | 허용오차에 극도로 민감. 낮으면 바닥이 타일마다 쪼개지고, 높으면 벽과 합쳐짐 |

→ **교훈: 지표를 15번 갈아 끼우는 것보다 그림을 바꾸는 게 빠르다.** 그리고 그림을
바꿔도 안 될 때가 있다(아래 M-3).

**M-2. ★ SPUM Slice 가 셀마다 role 을 붙여 준다 — 이걸 쓸 것 ★★★★★**

Object Editor 에서 `Slice` 를 누르면 `resourceSliceResult` 에 이게 들어온다:

```js
const s = JSON.parse(localStorage['spum-map-theme-source-state:<SMO_ID>']);
s.resourceSliceResult.tileMap        // [행][열] → 그룹 id (64x64)
s.resourceSliceResult.resourceGroups // 그룹마다 role: floor|water|detail|object|wall
```

`floor`+`water` = 통행, `detail`+`object` = 장애물로 보면 내 지표 전부보다 낫다
(우주선 실측: 통행 2300 · 최대 덩어리 1517). **직접 만들지 말고 이걸 읽어라.**

⚠ 단 `classification.movement` 는 **쓸 수 없다** — 전부 `passable`/`slowed` 로만 나오고
`wall` 은 0개다. 벽을 인식하지 못한다. **role 만 쓸 것.**

⚠ `Slice` 는 **기준 이미지(`sliceBaseAssetId`)** 를 쓴다. refs 카드를 클릭해 활성으로
만들어도 기준은 안 바뀐다(J-1 과 반대 방향의 함정). 새 그림을 슬라이스하려면 기준을
바꿔야 하는데, 방법은 아직 못 찾았다 ★★☆☆☆.

**M-3. ★ 문·벽토막은 프롬프트로 못 막는다 — 마스크에서 뚫어라 ★★★★★**

`no doors` 를 금지 목록에 넣고 3회 생성했고 **3회 다 일부가 남았다.** 긍정 서술
("입구는 벽이 3칸 없는 빈 구멍")로 바꿔도 남았다. 그 토막 하나가 방을 **폐쇄 공간**으로
만든다.

해법은 `tools/carve-doors.mjs`:
1. 통행 칸 덩어리를 구하고 제일 큰 것을 본체로 잡는다
2. 본체에서 **0-1 BFS**(통행칸 0 · 막힌칸 1) — 각 칸까지 "지나야 하는 벽 수"
3. 고립 덩어리마다 비용이 제일 싼 칸에서 되짚어 올라가며 **지나온 벽만** 연다
4. 벽이 `MAX_WALL`(기본 4)칸보다 두꺼우면 안 뚫는다 — 배 밖으로 새는 걸 막는다

우주선 실측: **26군데 · 그중 24군데가 벽 1칸** · 폐쇄 공간 0개.
~~뚫은 자리가 마침 "문처럼 생긴 벽 토막"이라 **화면에서는 문으로 들어가는 것처럼 보인다.**~~
⛔ **이 줄은 틀렸다** — 재 보지 않고 적은 인상이었다. 실제로는 **문이 막히고 벽이 뚫렸다.**
   2026-08-26 에 다섯 무대에서 확인했다. **M-24** 를 볼 것.

**M-4. 본체 밖 자투리는 반드시 막을 것 ★★★★☆**

뚫고 난 뒤 본체에 못 붙은 작은 통행 칸을 그대로 두면, 스폰이 거기 떨어져
**게임 시작부터 갇힌다.** 실제로 「부엌」이 그랬다(`build-world-map.mjs` 의
스폰 연결성 검사가 잡았다 — 이 검사를 빼지 말 것).

**M-5. ⚠ `node --check` 는 ES 모듈 오류를 못 잡는다 ★★★★☆**

`phase.js` 에 파라미터 `world` 를 넣었는데 그 파일엔 이미 `const world = ([tx,ty]) => ...`
(타일→월드 좌표)가 있었다. **`SyntaxError: Identifier 'world' has already been declared`**.

`node --check src/phase.js` 는 **통과했다.** 기본이 CommonJS 스크립트로 검사하기 때문이다.
브라우저에서 모듈로 로드하고 나서야 터졌고, 그 사이 `window.__game` 이 통째로 없었다.

→ 문법 검사만으로 끝내지 말고 **실제로 페이지를 띄워 콘솔을 볼 것.** (§7 "만든 즉시 적용해서
눈으로 확인한다"가 이 경우엔 콘솔 확인이다.) 이름을 새로 넣을 땐 그 파일에서 먼저 `grep` 한다.

**M-6. ✅ SPUM `Play` 는 CDP 실클릭이면 먹는다 — 사람이 누를 필요 없다 ★★★★★**

지난 세션에 `Play` 를 눌러도 **`actors 0`** 이 되어 "사용자 제스처가 필요한 것 같다"고
적었다. 틀렸다. 원인은 **JS 로 만든 합성 클릭**(`el.click()` / `dispatchEvent`)이었다.

브라우저 도구의 `computer{action:"left_click"}` 은 CDP 로 진짜 입력 이벤트를 보내므로
`sim on · actors 6` 이 정상적으로 뜬다. 지시 입력도 `type` + `key Return` 으로 그대로 된다.

→ **SPUM 조작은 전부 실클릭 경로로 할 것.** `javascript_tool` 은 *읽기*(로그 요약·상태 확인)
   전용으로 쓴다. 쓰기·조작에 쓰면 조용히 무시된다.

**M-7. ⚠ 시뮬레이션을 켜 놓고 잊으면 SSAM 이 계속 나간다 ★★★★★**

`Play` 상태면 캐릭터가 대화할 때마다 과금된다. 실측 **6인 9분 = 165 SSAM**
(자율 대화가 붙으면 분당 250까지 올라간 적 있다 — §4-29).

→ **작업이 끝나면 반드시 `Pause`.** 확인 방법은 두 가지를 같이 본다:
   버튼이 `Play` 로 돌아왔는지 + Event Log 헤더가 **`sim off`** 인지.
   하단 상태줄에 `World simulation paused` 가 뜨면 확실하다.

**M-8. ⛔ 배경 탭 throttle 은 "보기 나쁨"이 아니라 **게임이 멈추는** 버그다 ★★★★★**

타이핑 연출을 넣자 관전 모드가 배경 탭에서 **통째로 멈췄다.**
`setTimeout` 이 초당 1회로 묶여(공통함정 8-4) 한 글자에 1초 → 50자 한 줄에 40초.
그동안 다음 차례가 안 돌아 20초에 발언이 0건이었다.

```
고치기 전   배경 탭 20초 → 발언 0건    (초당 1.3자)
고친 뒤     배경 탭 12초 → 발언 5건
```

→ **연출을 setTimeout 체인으로 만들 때는 `document.hidden` 을 반드시 본다.**
   보는 사람이 없으면 연출을 건너뛰고 진행을 살린다. `visibilitychange` 로
   배경 전환 순간 치던 줄도 즉시 끝낸다 — 안 그러면 그 한 줄이 다음 차례를 막는다.

> 8-4 는 "FPS 0 이 떠도 코드 문제가 아니다"라고만 적혀 있었다. **부족했다.**
> 렌더링은 멈춰도 되지만 **진행 로직이 타이머에 얹혀 있으면 게임이 죽는다.**

**M-9. ⛔ 조건부 키가 **조용히 실패**하면 플레이어는 고장으로 읽는다 ★★★★★**

`F`(냉장고)는 `밤` + `부엌 3칸 이내` 두 조건을 다 만족해야 동작했다.
조건 밖에서는 `if` 가 통째로 걸러져 **아무 반응이 없었다.**

플레이어에겐 "지금은 안 되는 키"와 "고장난 키"가 **구분되지 않는다.**
32×32 맵에서 부엌이 어딘지도 안 알려 주니 밤이 탐색이 아니라 길찾기가 됐다.

→ **조건부 동작은 조건을 밖에서 검사하지 말고, 함수 안에서 검사하고 반드시 응답한다.**

```js
function 냉장고() {
  if (state.phase !== "night") { say("지금은 밤이 아니다."); return; }
  if (!부엌근처())  { say(`여기서는 닿지 않는다. 부엌은 ${부엌방향()} 이다.`); return; }
  ...
}
```

그리고 **"지금 할 수 있는 것"을 한 곳(`src/action.js`)에서 정해** 화면에 띄운다.
키가 흩어져 있어도 플레이어는 한 줄만 읽으면 된다.

> 부수 규칙: **안내에서 약속한 것은 실제로 만들어 둘 것.**
> "미니맵의 노란 표시를 따라가자"라고 써 놓고 표시를 안 만들었다가 잡았다.

**M-10. 체감 렉의 범인을 **추측하지 말고 분리 측정**할 것 ★★★★★**

"게임이 렉 걸린다"는 보고를 받고 렌더링부터 의심했다. 전부 무죄였다.

```
프레임(step+render)   0.5ms      60fps 예산의 3%
길찾기               300프레임 중 5ms 초과 0회
DOM                  200노드
SAM 왕복             1.5~2.5초  ← 범인
```

→ **엔진을 붙잡고 있었으면 하루를 버렸다.** `engine.step()`/`render()` 를 수동으로
   돌려 갱신·렌더를 **따로** 재고, 네트워크는 `fetch` 를 감싸 따로 잰다.
   (배경 탭에서는 rAF 가 멈추므로 FPS 측정은 무의미하다 — 수동 스텝이 정답이다.)

**해법도 엔진이 아니라 연출 쪽에 있었다.** 응답 도착 **직후**(타이핑 시작 전)
다음 요청을 쏘면, 치는 4~6초가 왕복 1.5~2초를 통째로 덮는다.

**M-11. LLM 발언을 인용할 때 「가장 최근 줄」은 대개 쓸모없다 ★★★★☆**

「모순 짚기」가 상대의 최근 발언을 인용하게 만들었더니
`"어? 오물오물, 넌 왜 갑자기 그런 걸 묻는"` 을 짚었다. 내 질문에 대한 **반문**이다.
모순은 **주장끼리** 부딪혀야 성립한다.

→ 시각·장소가 든 문장을 **주장**으로 보고, 그중 **가장 먼저** 한 것을 든다.
   그리고 문장 전체가 아니라 **그 절만** 뽑는다 — 앞머리를 자르면 감탄사가 인용된다.

```
"어? 오늘 진짜 조용했네! 다들 뭐 했어? 나는 5호실에서 책 읽다가 밤 11시쯤 잤어"
  → 인용: "나는 5호실에서 책 읽다가 밤 11시쯤 잤어"
```

**M-12. 한국어에서 「장소가 나왔다」 ≠ 「거기 있었다」 ★★★★★**

단서 수첩이 `"그럼 혹시 밤중에 부엌 소리 안 들었어?"` 를
**살살이가 부엌에 있었다**는 알리바이로 기록했다. 질문인데도.

세 가지를 다 요구해야 진술이 된다.

```
① 시각 + 장소가 **둘 다** 있을 것
     한쪽만 있으면 대조가 안 되고, "시각 불명" 줄이 화면을 덮는다(실제로 그랬다)
② 처소격 조사가 붙을 것 — `부엌에` `2호실에서`
     "부엌 소리" "부엌 쪽 냄새" 는 전문(傳聞)이지 알리바이가 아니다
③ 질문이 아닐 것
     절을 나눌 때 **물음표를 버리지 말고 붙여 둔다**. 버리면 질문인지 알 수 없다
```

**⛔ `\b`(단어 경계)를 한글에 쓰지 말 것.** `\w` 가 ASCII 기준이라 한글 뒤에서
경계가 잡히지 않아 정규식이 통째로 실패한다. 값이 0건이면 이걸 먼저 의심한다.

**부수:** 물건은 장소가 아니다. `냉장고`·`소파`를 장소 목록에 넣었더니
모두가 냉장고 얘기를 해서 수첩이 "냉장고"로 도배됐다.

**M-13. 무대를 바꾸려면 **모델 출력까지** 치환해야 한다 ★★★★★**

우주선 무대에 어휘 치환(`셰어하우스→화물선` 등)을 걸어 두고 안심했는데,

치환은 **우리가 쓴 프롬프트**에만 걸려 있었다. 모델은 프롬프트에 없던 말도 새로 지어낸다.

→ **응답에도 `localize()` 를 걸어야 한다.** (`ask` · `askGroupTurn` 반환부)
   그리고 치환 대상이 무대 이름 3개뿐이면 부족하다 —
   `냉장고→냉동고` `호실→번 선실` `복도→통로` 처럼 **생활 어휘**를 같이 옮긴다.

**M-14. ⛔ 한글·이스케이프가 섞인 치환을 스크립트로 하지 말 것 ★★★★★**

**M-15. Node 서버는 핫리로드가 없다 — 고치면 **재시작** ★★★★☆**

**M-16. ⛔ Git Bash `curl` 로 한글 payload 를 보내지 말 것 ★★★★☆**

**M-17. ⭐ SPUM 시트는 **다운로드 없이** 가져올 수 있다 ★★★★★**

Cast Export 의 다운로드 버튼은 비동기라 **직전 캐릭터 시트가 내려오는** 함정이 있고
(4-4), 받은 파일을 손으로 옮겨야 한다. 그럴 필요가 없었다.

Export 에서 `Generate` 를 누르면 미리보기가 뜨는데, 그 `<img>` 가
**원본 해상도 그대로의 data URL** 이다.

```js
document.querySelector('img.export-preview__image').src
// → "data:image/png;base64,..."  naturalSize 1024×256 (표시 크기는 180×45지만 원본이다)
```

이걸 로컬 서버로 그대로 POST 하면 파일이 바로 제자리에 꽂힌다(`/api/save-sheet`).
**어느 캐릭터인지 헷갈릴 여지도 없다** — 지금 화면의 것이 곧 그 캐릭터다.

⚠ 교차 출처(https://spum… → http://localhost)라 서버에 두 가지가 다 필요하다.
```
Access-Control-Allow-Origin        일반 CORS
Access-Control-Allow-Private-Network: true   ← 없으면 Chrome 이 **조용히 멈춘다**
```
후자가 없으면 **콘솔에 오류도 안 뜨고** 요청이 pending 으로 남는다. 한참 헤맸다.

**부수 교훈:** 내가 만든 검증 정규식(`^[a-z0-9-]{2,24}$`)이 시험용 slug `_test` 를 막아
"서버 문제"로 오해했다. 실패하면 **내 검증부터 의심**한다.

**M-18. 하드코딩한 인원수는 사람이 늘면 **조용히 겹친다** ★★★★☆**

모이는 자리를 원형으로 나눌 때 각도를 `i / 4` 로 계산했다. 처음엔 NPC 가 4명이었다.
나중에 5명, 관전이면 6명이 되면서 **다섯 번째가 첫 번째와 정확히 같은 칸**으로 갔다.

오류도 경고도 없다. 화면에는 캐릭터 둘이 겹쳐 서서 **렌더 버그처럼** 보인다.

```js
const ang = (i / 4) * Math.PI * 2;   // ✗ 4가 어디서 왔는지 아무도 모른다
const ang = (i / n) * Math.PI * 2;   // ○ n = 실제 인원
```

→ **배치·분배 계산에 상수를 쓰면 그 상수가 곧 인원 상한이 된다.**
   반지름도 인원에 비례시키고(둘레÷인원≈일정), 스냅 결과가 겹치면 옆칸을 찾게 한다.

**검증 요령:** 배경 탭에서는 엔진 루프가 멈춰(8-4) **이동을 볼 수 없다.**
움직임 대신 **배정된 목표 좌표**가 서로 다른지를 본다 — 결정론적이고 즉시 확인된다.

**M-19. 줌아웃 하한은 `min` 이 아니라 `max` ★★★★☆**

"맵이 화면에 다 들어오는 배율"을 하한으로 잡으려고 `Math.min(w/맵w, h/맵h)` 를 썼다.
그러면 **짧은 변만 맞고 긴 변에 검은 여백**이 생긴다.

```
min → 맵 전체가 화면 "안에" 들어온다 (레터박스 생김)
max → 맵이 화면을 "덮는다"          (여백 없음)   ← 카메라가 clamp 되는 게임은 이쪽
```

우리는 `FollowCamera` 가 맵 밖을 못 보게 가두고 있어서, 여백이 보이는 순간
화면이 어긋난 것처럼 보인다. **덮는 쪽(max)이 맞다.**

**M-20. 값이 바뀔 때마다 UI 를 다시 그리면 **드래그가 끊긴다** ★★★★☆**

설정 슬라이더에 "값이 바뀌면 패널을 다시 그린다"를 붙였더니,
끄는 도중 `input` 요소가 파괴돼 드래그가 중간에 멈췄다.

→ **자기가 일으킨 변경에는 다시 그리지 않는다.** 플래그 하나로 구분한다.
   외부에서 바뀐 경우에만 라벨을 맞춘다.

**M-21. SPUM Cast Export 자동화 — 되는 순서와 안 되는 것 ★★★★★**

캐릭터 4명분 시트를 뽑으며 정리한 절차. 순서를 지키지 않으면 조용히 실패한다.

```
① 캐릭터 생성 후 **Animation → Auto Map 을 반드시 한 번** 돌린다
   신규 캐릭터의 기본 클립이 `ChosunGun_idle0`(조선 총병)이다. 안 돌리면 그게 그대로 나온다
② Export 탭에서 ANIMATION 을 JS 로 바꾼다 (select 프로토타입 setter + input·change 둘 다)
③ **`Generate` 는 실클릭이어야 한다** — JS `.click()` 은 "No sheet generated" 로 끝난다
   (Play 버튼과 같은 패턴. 8-1 계열 함정)
④ 이미지는 **늦게 붙는다.** 클릭 직후엔 `.export-preview` 가 비어 있고
   `document.body.innerText` 도 "No sheet generated" 로 보인다. 10초 이상 기다린 뒤 다시 본다
⑤ 시트 img 는 `document.querySelectorAll('img')` 에서 **naturalWidth 1024** 로 찾는다.
   클래스명이 상황에 따라 다르다(`export-preview__image` ↔ `export-preview__empty` 로 교체됨)
```

⚠ **`Generating` 에서 멈추는 경우가 있다.** 여러 캐릭터를 연속으로 뽑으면 재현된다.
   재클릭해도 안 풀리면 그 캐릭터는 나중에 다시 한다 — 게임은 시트가 없어도 돈다.

⚠ **CDP `Runtime.evaluate` 는 45초 제한**이다. 폴링 루프를 JS 안에 길게 넣으면 통째로 타임아웃난다.
   전역 변수에 결과를 담고 **짧게 여러 번 조회**한다.

**M-22. ⛔ 맵 **바깥 테두리**가 통행 가능하면 캐릭터가 집 밖으로 돈다 ★★★★★**

"캐릭터가 벽을 뚫고 다닌다"는 제보를 받고 방 사이 벽을 뒤졌는데, 진짜 원인은
**맵 최상단·최하단 행이 통째로 통행 가능**했던 것이다. 그 줄이 집 전체를 두르는
숨은 복도가 되어, 벽 그림 위를 걸어 다녔다.

```
막기 전  y0 행: ##............#...#.............   ← 거의 다 통행 가능
막은 뒤  테두리 4변 전부 obstacle
```

→ **맵을 만들 때 테두리 한 줄은 무조건 막는다.** 그림에 벽이 있어도 데이터가 비면 소용없다.

**부수 발견:** 테두리를 막자 새침이 방과 (우주선) 두리번이·부엌이 **고립**됐다.
그 방들은 **테두리 복도를 통해서만** 연결돼 있었다 — 정식 문이 없었던 것이다.
0-1 BFS 로 가장 얇은 벽에 문을 뚫어 연결했다(집 2칸·우주선 2칸).

⚠ **막은 뒤에는 반드시 전 스폰 연결성을 다시 검사**한다. 안 하면 캐릭터가 방에 갇힌다.

**M-23. 기능을 만들었으면 **여는 길**을 눈에 보이게 둔다 ★★★★☆**

설정 화면을 만들어 놓고 여는 방법이 `O` 키뿐이었다. 사용자는 "설정 만든다더니 어디 있냐"고 물었다.
**만든 것과 닿을 수 있는 것은 다르다.**

→ ESC 로 들어가는 **일시정지 허브**를 두고(계속·설정·조작키·새 판·나가기),
   화면에 버튼도 놓고, 각 항목에 단축키를 같이 적어 자연스럽게 익히게 한다.
   (테라리아·코어키퍼가 하는 방식)

**M-24. ⛔ `carve-doors` 가 뚫은 자리는 **문이 아니었다** — 그리고 그렇게 적어 두었다 ★★★★★**

M-3 끝에 *"뚫은 자리가 마침 문처럼 생긴 벽 토막이라 화면에서는 문으로 들어가는 것처럼
보인다"* 고 적혀 있다. **틀렸다. 재 보지 않고 적은 문장이었다.**

2026-08-26 주영님이 산장에서 *"문 옆 벽으로 지나다닌다"* 고 지적했고, 해변 리조트를
세어 보니 똑같았다:

| | x=10 열(왼쪽 침실 4개의 벽) |
|---|---|
| 그림에 **나무 문**이 그려진 칸 (y 5·14·22·28) | **전부 막힘** |
| 실제로 뚫려 있던 칸 (y 1·10·21·24·27) | 벽 한가운데 |

게다가 구멍은 옆벽만이 아니라 **방 위·아래 벽에도** 있었다(y 8·10·24).
`carve-doors` 는 「제일 얇은 곳」을 뚫는다 — 문이 어디인지는 **보지 않는다.**

→ **교훈 두 가지.**
> ① 눈으로 확인하지 않은 인상을 **작업 규칙에 사실처럼 적지 마라.** 그 한 문장 때문에
>    같은 결함이 다섯 무대에 남은 채 「문처럼 보인다」로 넘어갔다.
> ② 「방에 들어갈 수 있다」와 「문으로 들어간다」는 **다른 명제**다. 연결성 검사는 앞엣것만
>    본다. 뒤엣것은 **문을 막았을 때 못 들어가야** 증명된다(`tools/regress.mjs` 의 해변 8항목).

**M-25. 벽을 다시 그릴 수 없을 땐 **열기만 해라** ★★★★★**

심해·해변·궤도의 통행 판정은 방 안쪽까지 통째로 벽이었다(막힘 59% · 54% · 46%).
산장처럼 좌표로 다시 그리려 했지만 이 무대들은 방이 **팔각형·대각선**이라 사각형으로
옮기면 지금보다 더 틀린다.

→ 대신 **칸을 열기만 했다**(`tools/map-rooms.mjs`). 열기는
> · 이미 이어진 곳을 끊지 못하고(합치기만 한다),
> · 여는 대상이 「바닥 색인 칸」뿐이라 **벽에 새 구멍이 안 난다.**

막힘 48% · 28% · 38% 로 내려갔고 스폰 연결성은 그대로다. **막는 것은 근거가 확실한 곳
(해변의 그려진 문)에서만** 했다.

**M-26. 방 범위는 **색 번짐 + 손으로 그린 울타리**가 제일 낫다 ★★★★☆**

M-1 이 「색으로 못 가른다」고 결론지었지만, 그건 **맵 전체를 색으로 가르려** 했을 때다.
**스폰 칸에서 시작해 같은 색으로 번지면** 이야기가 다르다 — 시작점을 알기 때문이다.

| 무대 | 칸 최빈색 점유(중앙) | 번짐 결과 |
|---|---|---|
| 궤도 정거장 | **0.81** | 방 11개 전부 정확 |
| 심해 연구기지 | 0.29 | 초록 방이 복도로 새어 209칸 |
| 해변 리조트 | 0.20 | 체크무늬 바닥이라 잘 안 퍼짐 |
| 셰어하우스·산장 | 0.18 | 못 가름 |

→ 새는 방은 **손으로 읽은 사각을 울타리로** 씌우면 임계를 넉넉히 줘도 안전하다.
   바닥이 진짜 직사각형인 무대(해변)는 울타리 안을 통째로 열면 된다.
   **손 판독은 `tools/map-grid.mjs`** (칸마다 좌표를 찍은 확대 그림), **확인은
   `tools/map-overlay.mjs`** (통행 판정을 그림 위에 빨갛게).

**M-27. 스폰 이름이 가리키는 곳을 **한 번은 봐라** ★★★★☆**

해변 리조트는 `방7` 스폰이 **부엌 한가운데**를, `부엌` 스폰이 **침실 안**을 가리키고
있었다 — 정확히 서로 바뀌어 있었다. 연결성 검사도, 게임도 통과한다. 이름만 틀렸으니까.
그림에 얹어 보고서야 알았다. 회귀에 「부엌 스폰이 부엌 좌표 범위 안인가」를 넣었다.

## N. LLM 대사 품질과 측정 (2026-08-21~22 · 발표 당일과 그 뒤)

> 발표 직전 이틀간 마피아 판을 고치면서 얻은 것들. **프롬프트를 고쳐도 안 되던 문제들의 진짜 원인**이 여기 있다.

**N-1. 값을 옮길 땐 **끝까지 따라가서** 확인한다 ★★★★★**

`round.js` 가 발언마다 사람별로 다른 「태도」(몰아가기·되받기·편들기…)를 만들어
요청 본문에 실어 보냈다. 그런데 **`server.mjs` 가 그걸 `askMafiaTurn` 으로 안 넘겼다.**
프롬프트에 **한 번도 들어간 적이 없다.**

증상은 "AI들이 말투만 다르고 같은 말을 한다"였고, 프롬프트를 몇 번을 고쳐도 안 나아졌다.
당연하다 — 고친 프롬프트에 그 값이 애초에 없었으니까.

→ **클라가 보낸다 ≠ 서버가 넘긴다 ≠ 프롬프트에 들어간다.**
   새 필드를 추가하면 **최종 프롬프트 문자열을 직접 찍어서** 그 문자열이 들어있는지 본다.
   ```js
   node -e "import('./engine.mjs').then(m=>{const p=m.mafiaTurnPrompt('오물오물',{태도:'X'});
            console.log(p.includes('X'))})"
   ```

**N-2. LLM 되풀이는 프롬프트로 못 막는다 — 받은 뒤에 거른다 ★★★★★**

누가 "내가 마피아야"라고 하면 **그 말이 너무 강렬해서** 전원이 거기에만 반응한다.
"오물오물이 뭐하는 거야ㅋㅋ 진짜 마피아라고?" 가 다섯 줄 쌓였다.
"같은 말 하지 마라"를 프롬프트에 아무리 세게 써도 안 막혔다.

→ **모델을 설득하는 대신 출력물을 검사한다.** 글자 2-gram 겹침 55% 이상이면 되풀이로 보고,
   교정 지시를 붙여 **한 번만** 다시 받는다. 그래도 닮았으면 **말하지 않는다** —
   억지로 밀어 넣는 것보다 조용한 편이 낫다.
   (`src/similar.js`. 실제로 나온 되풀이 4/4 차단, 오탐 1/7 — 그것도 사실상 같은 말이었다.)

**N-3. 파이프라인이 대사를 똑같게 만든다 ★★★★★**

속도를 위해 **다음 사람 요청을 앞사람이 타이핑하는 동안** 미리 쏘고 있었다.
그런데 그 요청이 **앞사람 말이 대화록에 들어가기 전**에 나갔다.
둘이 **같은 문맥**을 보니 **같은 반응**이 나온다.

→ 미리 쏘되, **대화록에 그 줄이 들어간 직후**에 쏜다. 타이핑 4~6초가 왕복을 그대로 덮으므로
   속도는 그대로고 문맥만 맞는다. (프롬프트 문제로 착각하기 쉬운 **구조 문제**다.)

**N-4. 측정기는 게임과 **같은 부품·같은 호출 방식**을 써야 한다 ★★★★★**

평가 하네스를 만들어 처음 돌렸더니 응답 실패율 **27.8%** 가 나왔다.
그런데 게임(`groupchat.js` `요청()`)은 **실패하면 0.4초 뒤 한 번 더 부른다.**
측정기는 그걸 안 했다 — **플레이어가 겪지도 않는 실패율**을 보고한 것이다.
되풀이율 50% 도 마찬가지로 필터를 안 거친 원수치였다.

→ 측정기가 게임과 다르게 동작하면 **그 숫자는 아무 말도 하지 못한다.**
   · 판정기·목록은 **공용 모듈**로 빼서 양쪽이 같은 것을 쓴다(`src/similar.js`·`src/mafia/attitudes.js`)
   · 재시도·필터 같은 **호출 습관**까지 흉내 낸다
   · 원수치와 보정 후 수치를 **둘 다** 보고한다 (앞은 SAM 상태, 뒤는 체감 품질)

**N-5. 평가지표는 「무작위 기준선」과 비교해야 뜻이 생긴다 ★★★★☆**

"시민이 마피아를 33% 맞혔다"는 그 자체로는 아무 뜻이 없다.
생존 4명이면 자기는 못 찍으니 **무작위도 33%** 다. 같으면 **토론이 아무 정보도 안 만든 것**이다.

→ 적중률은 항상 `1/(생존-1)` 과 나란히 적는다. 차이가 곧 "대화가 만든 정보량"이다.
   ⚠ 표본이 작으면 판단하지 말 것. 첫 측정은 6표뿐이라 결론을 못 냈다(그렇게 보고했다).

**N-6. 합성 대화록으로 추리력을 재면 안 된다 ★★★★☆**

투표만 따로 재려고 대화록을 지어 넣으면, **내가 심어 둔 단서**를 찾는지 재는 꼴이 된다.
→ **토론을 실제로 굴린 뒤 그 대화록으로 투표**시킨다. 그래야 "대화가 단서를 만드는가"를 잰다.

### N-7. 쏠림을 보고 원인을 단정하지 마라 — **대조군을 만들어라** (2026-08-24)

AI 시민들의 표가 한 캐릭터에 80% 몰렸다. 원인을 **두 번 틀리게** 짚었다.

| 시점 | 주장 | 실제 |
|---|---|---|
| 1차 | "토론이 오히려 방해가 된다" | **429 로 대화가 굶었다.** 발언이 판당 2~4줄뿐 |
| 2차 | "캐릭터 성격 태그로 찍는다" | **대사 한 줄을 옮기자 표가 따라갔다.** 성격 무관 |

가른 방법(`tools/bias-probe.mjs --swap`) — **변수 하나만 바꿨다:**
주도적 제안("일단 서로 뭐 했는지부터 얘기해 보자")을 다른 캐릭터에게 옮겼다.
결과: 오물오물 80.0% → **꾸벅이 80.0%.** 표가 대사를 따라 통째로 이동.

**진짜 기제: AI 는 「대화를 주도하는 사람」을 의심한다.**

- ⛔ **한 조건에서만 재고 원인을 붙이지 마라.** 숫자가 선명할수록 설명이 그럴듯해져
  대조 실험을 건너뛰게 된다. 그게 두 번 다 일어난 경로다.
- 측정 도구의 **판정 문구가 원인을 말하면 그 자체가 함정**이다. bias-probe 는
  "성격 편향이다"라고 찍고 있었다 — 도구가 나를 틀린 방향으로 밀었다.
  → 도구는 **관찰까지만** 말하고, 원인은 대조군이 말하게 고쳤다.

### N-8. 편향은 프롬프트로 못 막는다 — **세 번째 확인** (2026-08-24)

N-7 의 기제를 알고 나서 지목 규칙에 직접 넣었다:
`⛔ 먼저 나서서 「이렇게 하자」고 제안한 사람을 그 이유로 찍지 마라.`

| | 최다 득표 | 근거번호 유효율 |
|---|---|---|
| 방어 전 | 80.0% | 20% |
| 방어 후 (14표) | **85.7%** | 71% |
| 방어 후 (18표) | **83.3%** | 44% |

**쏠림은 안 줄었다. 근거를 대는 비율만 올랐다.**
→ AI 는 **근거를 성실히 인용하면서 같은 사람을 찍는다.**
근거가 결론을 만든 게 아니라, **정해진 결론에 붙는 설명**이었다.

이로써 프롬프트로 못 막은 것이 셋이다: **길이(63.8% 위반) · 되풀이(21.7%) · 지목 편향.**
고칠 수 있었던 둘은 전부 **받은 뒤 코드가 검사하고 되묻는 방식**이었다(N-2).
지목 편향은 검사할 정답이 없어서 그 수법이 안 통한다 → **게임 설계로 완충해야 한다.**

### N-9. 세다 만 표본으로 비율을 내지 마라 (2026-08-24)

왜 줄었는지 알 수 없었다. 파서 버그일 수도, 모델이 기권한 것일 수도 있었다.

("어... 뭐 어떻게 봐야 하나?"). 파서는 멀쩡했다.

- **집계에서 빠진 것은 버리기 전에 눈으로 본다.** 15% 넘게 빠지면 비율을 결론으로 쓰지 않는다.
  (`bias-probe.mjs` 에 관문으로 넣었다. `eval.mjs` 유효성 게이트와 같은 원칙.)

### N-10. 이 게임에는 **과거가 없다** — 알리바이를 만들게 하지 마라 (2026-08-24)

한 판 돌려 본 뒤 저녁 대화를 살리려고 프롬프트에 이렇게 적었다:

> 어제 뭐 했는지, 방이 어딘지, 누가 늦게 자는지 — 내일 알리바이가 될 것들을 물어 둬라

**바로 걷어냈다.** 이 게임에는 과거가 없다 — `saw` 는 매 밤 비워지고
**살해 목격만** 담긴다. 그러니 "어제 늦게 잤어" 같은 말은
① 아무도 확인할 수 없고 ② 단서가 되지 않으며 ③ **순전한 지어내기**다.

⚠ **`round.js` 가 이미 같은 이유로 밤 조우 기록을 걷어냈었다**
("주어진 알리바이가 없다 — 사람들은 시각을 대조하지 않고 말투와 태도로 찾는다").
코드가 배운 교훈을 **프롬프트로 되살린 셈**이었다.
→ 저녁은 「사실 캐기」가 아니라 **「입장 밝히기 + 떠보기 + 반응 기억」** 이다.

**교훈:** 이미 걷어낸 설계를 **다른 계층에서 다시 넣지 않았는지** 본다.
코드에서 지운 것을 프롬프트가 되살릴 수 있다.

### N-11. 첫마디 습관은 되풀이 필터가 못 잡는다 (2026-08-24)

### N-12. 편향을 없애려 하지 말고 **잣대를 나눠 줘라** (2026-08-24)

표의 80~93% 가 한 사람에게 몰렸다. 원인은 「대화를 주도한 사람을 의심한다」였다.

|---|---|---|
| 모두 같은 잣대 (4회) | 80.0% · 85.7% · 83.3% · 82.4% | 2~3명 |

금지는 세 번 다 실패했고(길이·되풀이·편향), 분산은 한 번에 통했다.
⚠ 대화 다양성도 같은 방법으로 이미 풀려 있었다(`시민태도`) — **같은 해법을 지목에는
안 쓰고 있었다.** 투표 단계에는 태도를 아예 안 넘기고 있었던 것이 원인이다.

### N-13. 같은 코드 모양이 두 곳에 있으면 **치환은 앞엣것을 잡는다** (2026-08-24)

초대 코드 차감을 `/api/mafia-turn` 에 넣으려 했는데 **`/api/group-turn`(케이크 판)에 붙었다.**

- ⚠ `node --check` 통과, 모듈 로드 통과. **실제로 불러 보고서야** 알았다

→ 회귀에 「차감이 **코드 변수와 같은 블록**에 있나」를 넣었다(중괄호로 블록을 잘라서 본다).

**교훈:** 엔드포인트·함수가 비슷하게 생겼으면 **범위를 먼저 자르고** 그 안에서 치환한다.

## O. 도구·환경 함정 (2026-08-21~22)

**O-1. ⛔ 파이썬으로 파일을 고칠 땐 **임시 파일 경유** — 원본이 0바이트가 된다 ★★★★★**

`io.open(P, "w")` 는 **여는 순간 파일을 비운다.** 그다음 `write()` 가 인코딩 오류로 죽으면
**내용이 사라진 빈 파일**만 남는다. 실제로 `engine.mjs`(38KB)가 0바이트가 됐다.
(원인은 BMP 밖 이모지를 `\uD83E\uDDD1` 처럼 서로게이트로 적은 것 — Python 문자열에선 안 합쳐진다.)

→ 항상 이 형태로 쓴다:
```python
tmp = P + ".tmp"
io.open(tmp, "w", encoding="utf-8", newline="\n").write(s)
os.replace(tmp, P)          # 원자적 교체 — 실패해도 원본은 그대로
```
→ 커밋된 파일이면 `git checkout -- <파일>` 로 즉시 복구된다. **작업 전 커밋해 두는 게 안전망이다.**

**O-2. 콘솔 인코딩 — `PYTHONIOENCODING=utf-8` 을 붙인다 ★★★★☆**

윈도우 기본 콘솔은 cp949 라 `print("— 화살표")` 같은 문자에서 스크립트가 죽는다.
**쓰기는 끝났는데 출력에서 죽어** "실패한 줄 알았는데 사실 됐다"가 나온다.

**O-3. 윈도우는 **어떤 프로세스의 현재 폴더**도, 그 조상 폴더도 이름 바꾸지 못한다 ★★★★★**

`git mv` 가 `Permission denied` 로 실패했다. 권한 문제가 아니다.
**그 폴더 안(자기 자신 또는 하위 아무 데나)을 현재 폴더로 삼은 프로세스가 있으면** 막힌다.

> ⚠ **2026-08-23 정정.** 처음엔 "그 폴더가 세션의 작업 디렉터리라서"라고 적었는데 **틀렸다.**
> 세션 앵커는 개명 대상의 **부모**(`90_hackathon`)였다. 진짜 범인은 거의 확실히
> **`proto/` 에서 띄워 둔 백그라운드 개발 서버**(`node server.mjs`)다 — 하위 폴더도 똑같이 막는다.
> 결정적 반증: **이 세션이 열려 있는 채로 다른 세션이 개명에 성공했다.**
> 세션을 닫을 필요가 없었다는 뜻이다.

→ **진단법:** 자식 폴더는 개명되는데 그 폴더만 안 되면 잠금이다.
```powershell
Rename-Item "$대상\docs" "docs_t"    # 되면 → 잠금은 그 폴더(또는 하위)에 걸린 것
```
→ **해결(순서대로):**
   ① **백그라운드 프로세스부터 끈다** — dev 서버·watcher. `netstat -ano | grep LISTENING` 로 확인.
     이것만으로 대개 풀린다.
   ② 그래도 막히면 그 폴더 안을 안 쓰는 **다른 세션**이 한다.
   ③ 폴더 개명 작업은 **애초에 그 폴더 밖에서** 시작한다.

**O-4. `grep -r` 대신 `git grep` ★★★★☆**

레포 루트에서 `grep -r` 을 돌리면 `vendor/`·`node_modules/` 를 훑느라 **2분 타임아웃**이 난다.

(`proto/server.mjs` 는 루트가 `proto/` 라 `pitch/`·`docs/` 는 못 준다.)

**O-6. 공개 레포 점검은 **이력까지** 본다 ★★★★★**

작업 파일만 보면 절반만 본 것이다. 지운 것도 이력에 남는다.

**O-7. ⛔ 「커밋 제외」한 의존성은 **복구 경로까지** 갖춰야 한다 ★★★★★**

**O-8. 미러링 스크립트가 조용히 실패하던 두 가지 ★★★★☆**

`mirror.mjs` 를 고치면서 나온 것. 둘 다 **에러 없이 0개를 받고 끝나** 알아채기 어려웠다.

1. **Git Bash 가 `/` 로 시작하는 인자를 윈도우 경로로 바꾼다**(MSYS 경로 변환).
   `node mirror.mjs /packages/spum-world/index.js` 의 인자가
   `C:/Program Files/Git/packages/...` 가 되어 있었다.
   → 인자는 **패키지 이름**으로 받는다(`node mirror.mjs spum-world`). 경로를 인자로 주지 않는다.
2. **import 에 캐시 무력화 쿼리가 붙어 온다** — `./WorldAIState.js?v=world-...-20260616-1`.
   그대로 파일명으로 쓰면 윈도우가 `?` 를 못 써서 죽는다.
   → 저장 전에 `?`·`#` 뒤를 잘라낸다.

**O-9. 「고쳤다」와 「고쳐진 경로가 돈다」는 다르다 ★★★★★**

O-8 을 고치고 **각 원인을 따로 확인**한 뒤 끝난 줄 알았다. 사용자가 "다 해결한 거야?"
라고 물어 **최종 경로(`serve.sh`)를 실제로 돌려 보니 여전히 안 됐다.** 두 가지가 더 있었다.

1. **고친 곳이 호출부가 아니었다.** `mirror.mjs` 를 이름 인자로 바꿨는데
   `serve.sh` 는 여전히 경로(`/packages/...`)를 넘기고 있었다 — 같은 MSYS 함정에 그대로 걸렸다.
2. **실패가 실패로 안 끝났다.** `mirror.mjs` 가 0개를 받고도 **종료코드 0** 이라
   `node mirror.mjs || { exit 1; }` 안전장치가 통째로 무력화됐다.
   아무것도 안 받은 채 서버가 떴다.
   → `if (ok === 0) process.exit(1)`. **"조용히 실패"는 스크립트 안에서 끊는다.**

→ 부품을 고쳤으면 **사용자가 실제로 밟는 경로**를 그대로 한 번 돌린다.
   부품 검사는 부품이 맞다는 것만 말해 준다.

⚠ 그리고 **기본 진입점 하나만 받으면 안 된다.** `mirror.mjs` 기본값은 `spum-engine` 인데
   `src/npctalk.js` 는 `spum-world` 를 쓴다 — 하나만 받으면 거기서 깨진다. **둘 다** 받는다.

### N-15. 없앨 것을 이름으로 부르면 오히려 나온다 (2026-08-25)

세 번 다 방 입구에 문짝이 그려졌다. 문장을 **「벽이 끊기고 그 사이는 맨바닥」**이라는
긍정 서술로 바꾸니 그 뒤 두 장에서 **한 짝도 안 나왔다.**

**적용:** 이미지 프롬프트에서 무엇을 빼고 싶으면, 그 자리에 **무엇이 있는지**를 대신 쓴다.
금지 목록은 보조로만 둔다. (텍스트 프롬프트에서도 같은 경향을 이미 봤다 — N-8 프롬프트 방어 실패.)

### N-16. 화면에 뜬 잔액은 늦게 따라온다 — 한 번 재고 단가라 하지 말 것 (2026-08-25)

이미지 생성 직후 SSAM 표시를 읽고 **「1장 = 46」**이라고 문서에 적었다. 8장을 뽑고
총액으로 나누니 **115** 였다. 표시가 갱신되기 전에 읽은 값이었다.

**적용:** 단가·소요시간처럼 **누적으로 재야 맞는 값**은 1회 측정으로 확정하지 않는다.

### N-17. 자동 점수 기준이 눈보다 못할 때가 있다 — 그러면 눈을 쓴다 (2026-08-25)

평면도 통행 임계값을 자동으로 고르려고 점수 기준을 **세 번** 바꿨다.
넓이만 → 주방에 침실 배치 / 방 간 거리만 → 빈 방에 배치 / 방 후보 개수 → 엉뚱한 조합.
결국 **미리보기에서 「방마다 초록 네모 하나」를 확인하는 것**이 유일하게 맞는 기준이었다.

**적용:** 탐색기는 **후보를 추리는 데까지** 쓰고 최종 판단은 사람이 본다.
기준을 계속 고쳐 맞추기 시작하면 그건 **기준이 없다는 뜻**이다 — 그때는 멈추고 보고한다.

### N-18. 항목을 늘렸으면 **비율을 다시 세라** (2026-08-25)

「열 중 여덟은 문서 한 줄이면 안 막혔을 것」은 10건짜리 표를 세어 낸 값이었다.
그 표에 SAM·엔진 항목을 붙여 **16건**으로 늘리면서 **비율 문장은 그대로 옮겼다.**
다시 세니 **문서 6 · 코드 9 · 인프라 1** — 결론이 뒤집혔다.

**적용:** 표를 늘리거나 줄이면 그 표를 근거로 한 **모든 요약 문장을 다시 계산**한다.
숫자를 옮겨 적는 순간 그건 이미 「실측」이 아니다.

### N-19. 유리한 표본만 세지 마라 (2026-08-25)

이미지 프롬프트 개선 효과를 적으면서 **잘 나온 두 장만 인용**하고,
같은 프롬프트로 문짝이 다시 나온 한 장을 뺐다.
바로 앞 절에서 「AI 는 이미 정한 결론에 근거를 붙인다」고 지적해 놓고 같은 짓을 했다.

**적용:** 효과를 주장할 땐 **분모를 먼저 적는다**(「넉 장 중 세 장」).
반례가 있으면 그 자리에 같이 적는다. 반례를 뺀 주장은 상대가 원본을 보면 바로 무너진다.

### N-20. 「사양이라 문제 아님」으로 지운 게 실은 함정이었다 (2026-08-25)

Object Editor 의 refs 10장 상한을 피드백에서 **「사양이지 문제가 아니다」로 뺐다.**
그 직후 **바로 그것 때문에 30분을 태웠다** — 10/10 에서 `Generate` 를 누르면
상태줄이 `queued` 인 채 끝나지 않고 **오류도 안 뜬다.** 로그인 만료인 줄 알고 두 번 헛짚었다.
새 테마를 만드니 같은 프롬프트가 곧바로 돌았다.

**적용:** 「사양이냐 버그냐」로 가르지 말고 **「조용히 실패하냐」**로 가른다.
사양이어도 **말없이 멈추면 함정**이다. 반대로 시끄럽게 실패하면 사양은 사양일 뿐이다.

### N-21. 프롬프트의 **강조는 예산이 있다** (2026-08-25)

정거장 평면도에서 「방 중앙을 비워라」를 ★로 올려 강조했더니, 잘 지켜지던
**「방마다 다른 바닥색」이 통째로 사라져 전부 회색**이 됐다. 지운 적이 없는 문장이다.

다음 판에서 **둘 다 맨 위에 1·2번으로 적고**, 본문에서 각각 「(repeat — 위 1번)」으로
다시 짚으니 둘 다 지켜졌다.

**적용:** 새 요구를 강조할 때 **이미 지켜지던 것이 밀려나지 않았는지** 결과에서 확인한다.
중요한 게 둘 이상이면 **번호를 매겨 맨 앞에 모아** 두고 본문에서 되짚는다.

### N-22. ⛔ **안 도는 코드를 보고 「고장」이라 하지 마라 — 원래 뺀 것일 수 있다** (2026-08-25)

「밤에 자다가 깼는데 X가 Y 쪽으로 가는 걸 봤다」는 코드가 `round.js` 살해() 에 있었다.
재 보니 **어느 맵에서도 한 번도 안 터진다.** 나는 이걸 **「8일 동안 죽어 있던 규칙」**이라
부르고, 되살리는 방법 세 가지를 제안했다.

**틀렸다.** 애초에 **밤 목격자 시스템을 안 두기로 한 설계**였다(주영님 확인).
이 게임에는 과거가 없다 — 사람들은 시각을 대조하지 않고 말투와 태도로 찾는다(N-10).
남아 있던 코드가 **잔재**였던 것이지 고장이 아니었다.

**N-10 과 똑같은 실패를 반대 방향에서 반복했다.** 그때는 코드가 지운 것을 프롬프트가
되살렸고, 이번엔 **설계가 뺀 것을 내가 되살리려 했다.**

**적용:** 발동하지 않는 규칙을 찾으면 고치기 전에 **「이게 원래 있어야 하는 것인가」를 먼저 묻는다.**
`docs/` 와 코드 주석에 **왜 뺐는지**가 적혀 있을 수 있다(실제로 N-10 에 적혀 있었다).
그리고 **잔재는 지운다** — 안 도는 코드를 남겨 두면 다음 사람이 또 「고장」으로 읽는다.
→ 목격 코드를 걷어냈고, `regress.mjs` 에 **되살아나면 잡는 검사**를 넣었다.


### N-23. 금지를 쌓으면 모델은 **안전한 화제로 도망간다** (2026-08-26) ★★★★★

관전 1판을 녹화했더니 저녁 대화 18줄에서 **여섯 명이 전부 「게임 규칙이 뭐냐」를 물었다.**

> 「근데 진짜 누가 죽는다는 게 뭐야?」 · 「밤에 누가 안 보이면 그 사람이 죽은 건가?」
> 「죽는다는 게 진짜 죽는 건가, 게임 규칙상 죽는 건가?」
> 「게임이 어떻게 도는 건지부터 명확히 해야 할 것 같은데...」

캐릭터가 **게임 속 인물이 아니라 규칙을 모르는 참가자**처럼 말한다. 몰입이 통째로 깨진다.

**원인은 금지 자체가 아니라 금지의 총량이다.** 저녁 프롬프트에는 이런 것들이 쌓여 있었다.

| 금지 | 넣은 이유 |
|---|---|
| 마피아가 있다는 사실을 화제로 삼지 마라 | 전원이 그 얘기만 해서 |
| 없는 과거를 지어내지 마라 | 이 게임에 과거가 아예 없어서 |
| 말버릇을 지적하지 마라(메타 대화) | 하나 나오면 전원이 따라 해서 |
| 낼 근거가 없으면 한 마디로 끝내라 | 대사가 길어서 |

**하나하나는 다 옳다.** 그런데 합쳐 놓으면 **할 말이 남지 않는다.**
할 얘기로 준 것은 「자기 입장 밝히기 · 떠보기 · 농담」 셋뿐이었고,
모델은 그 셋으로 여섯 명 × 세 바퀴를 못 채우자 **금지 목록에 없는 화제**를 찾아냈다 —
그게 「게임 규칙」이었다. 금지 목록에 없으니 규칙 위반도 아니다.

→ **금지를 하나 추가할 때마다 「그럼 무엇을 말하나」를 같이 준다.**
   금지는 공간을 좁히고, 좁아진 공간이 비어 있으면 모델은 반드시 **바깥**을 찾는다.
→ 점검법: 금지 항목 수와 「할 것」 항목 수를 세어 본다. 금지가 더 많으면 위험 신호다.
   2026-08-26 시점 저녁 프롬프트는 **금지 4 : 할 것 3** 이었다.

### N-24. 「길이」는 프롬프트로 못 지킨다 — 그리고 자르개도 안 잘랐다 (2026-08-26) ★★★★★

대사가 길어 읽기 피로하다는 지적을 받고(주영님) 두 가지를 넣었다.
① 프롬프트에 「길이: N~M자」를 캐릭터·상황별로 명시  ② 자르개 상한을 그 값에 연동

**둘 다 실패했다.** 목표 평상시 상한 평균 32자, **실측 평균 53자 · 25자 이하 0줄 · 최대 78자.**
고치기 전(41자)보다 **오히려 늘었다.**

**왜 ①이 안 먹나 — 모델은 글자 수를 못 센다.**
「25자로 써라」는 지시를 모델이 따를 방법이 없다. 세면서 쓰지 않기 때문이다.
주석에 그렇게 적어 놓고도 프롬프트에 의존했다.

**왜 ②가 안 먹나 — 자르개가 첫 문장을 통과시킨다.**
`대사줄이기` 는 「첫 문장 하나는 아무리 길어도 남긴다」로 되어 있다.
낱말 중간에서 자르면 더 흉하다는 **옳은 판단**이었는데,
그 결과 **한 문장으로 길게 말하면 상한이 몇이든 그냥 통과한다.**
78자가 한 문장이면 78자가 그대로 나간다.

→ 길이를 진짜로 제어하려면 **문장 단위가 아니라 어절 단위로 자르거나**,
   상한을 넘긴 응답을 **재요청**해야 한다(3인칭 가드가 그렇게 해서 11/11 로 먹었다).
→ ⛔ **「고쳤다」와 「효과가 있었다」는 다르다.** 이번엔 회귀 11항목이 전부 통과했는데
   (프롬프트에 지침이 들어갔는지 · 단계별로 바뀌는지 · 사람마다 다른지)
   **정작 나온 대사는 더 길어졌다.** 검사한 것은 「지침이 전달되었나」이지
   「대사가 짧아졌나」가 아니었다. **결과를 재는 검사를 따로 두어야 한다.**

**재는 법(SAM 을 더 안 쓰고):** 녹화 파일 하나면 된다.
```js
const 말 = 자료.사건.filter(e => e.종류 === "말");
const 길 = 말.map(e => e.말.length);
// 평균 · 최대 · 25자 이하 개수 · 사람별 평균(편차가 없으면 「전원이 똑같이 길다」)
```
2026-08-26 실측: 새침이 42 · 오물오물 47 · 꾸벅이 56 · 살살이 59 · 두리번이 61 · 폴짝이 65.

**⚠ 그리고 이 도구가 내 결론을 하나 뒤집었다.** 나는 「길이 제어가 통째로 실패했다」고
적었는데, 두 판을 나란히 재 보니 그렇지 않았다.

| | 고치기 전(08-24) | 고친 뒤(08-26) |
|---|---|---|
| 평균 | 42자 | **53자** (나빠졌다) |
| 사람별 평균 **편차** | 13자 | **24자** (좋아졌다) |

`말수`(적음/보통/많음)와 MBTI 축은 **실제로 먹었다** — 새침이(적음) 42자와
폴짝이(많음) 65자로 갈렸다. 실패한 것은 **절대 길이**뿐이다.
「전원이 똑같이 길다」는 고쳐졌고, 「전체가 길다」가 남았다.

→ **한 지표로 성패를 말하지 마라.** 평균만 봤으면 「전부 실패」로 적고 끝났을 것이고,
   실제로 먹은 부분(편차)까지 되돌릴 뻔했다. 목표가 둘이면 지표도 둘을 본다.

### N-25. 「사람이라면 이렇게 하겠지」가 **손해**일 때가 있다 — NPC 경찰 조사 (2026-08-26) ★★★★★

NPC 경찰이 조사 대상을 **`Math.random()`** 으로 고르는 것이 결함처럼 보였다.
사람이라면 **마을이 의심하는 사람**을 조사할 테니까. 고치려다 **먼저 쟀다.**

`tools/balance.mjs` 에 `경찰전략` 옵션을 넣고 각 20,000판:

| 구성 | 무작위 조사 | 의심추종 | 차이 |
|---|---|---|---|
| 4인 마1·경1·의1·시1 | **53.6%** | 45.6% | **-8.0p** |
| 6인 마2·경1·의1·시2 | **29.8%** | 20.5% | **-9.3p** |
| 8인 마3·경2·의1·시2 | **22.0%** | 11.0% | **-11.0p** |
| 10인 마3·경1·의1·시5 | **28.7%** | 19.9% | **-8.9p** |

**전부 나빠졌다.** 이유는 산수다 —
마을의 처형 정확도는 **23.5%** 인데, 무작위 조사의 마피아 적중률은
`마피아수 / 조사후보수` 라 **37~50%** 다. **마을보다 무작위가 두 배 정확하다.**
마을 의심을 따라가면 경찰이 **마을만큼 못 맞히게** 된다.

> **교훈.** 「직관적으로 더 똑똑해 보이는 행동」이 승률을 8~11%p 깎을 수 있다.
> 고치기 전에 재라. **이번엔 안 고치는 것이 답이었고, 그 근거가 이제 남았다.**
> 옵션은 `balance.mjs` 에 남겨 뒀다 — 언제든 다시 잴 수 있다.

**N-26. 「미측정」이라 적어 둔 것이 실은 이미 측정돼 있었다 (2026-08-26) ★★★★☆**

`balance.mjs` 머리에 *"우리 AI 가 사적 정보를 쓰는지는 아직 미측정"* 이 두 곳에 남아 있었다.
그런데 `round.js` 경찰 주석에는 이미 답이 있었다 — `bias-probe --saw` 로
**지목률 5.6~15.0%(기준선) → 72.2%** 를 재 놓았다.

한쪽에서 측정하고 **다른 쪽 문구를 안 고쳤다.** 그 사이 이 문구를 읽은 사람(나)은
「안 재 봤구나」로 판단하고 같은 걸 다시 재려 했다.

→ **값이 바뀌면 그 값을 말하는 자리를 전부 따라가라**(N-1 의 문서판).
   특히 「미측정」·「확인 필요」 같은 **상태 표기**는 측정이 끝나는 순간 거짓이 된다.

**왜 놓쳤나 — 셋 다 원인이 같다.** 관련 있어 보이는 파일만 grep 하고 **폴더를 안 봤다.**
- 재생: `main.js`·`setup.js`·`mafia.html` 만 훑었다. `replay.html` 은 형제 파일인데 안 봤다.
- 함수: `api/` 폴더가 있는지 `ls` 한 번이면 됐다. `mkdir -p api` 를 먼저 쳤다.
- 문서: **`docs/README.md` 문서 지도를 안 봤다.** CLAUDE.md §1 이 「기록 전에 이 표를 본다」고
  적어 둔 바로 그 표다. 규칙이 있었는데 발동을 안 시켰다.

**피해가 났다.** `vercel.json` 을 덮어써서 `buildCommand` 를 날릴 뻔했다 —
그게 `vendor/` 를 미러링하므로 지웠으면 **배포본이 흰 화면**이 된다.

### 규칙

1. **만들기 전에 `ls` 를 친다.** grep 은 「내가 상상한 이름」만 찾는다. 폴더는 실제를 보여 준다.
2. **파일을 새로 만들 때는 `docs/README.md` 문서 지도를 먼저 본다.** 지도에 자리가 없으면
   ① 기존 문서에 합치거나 ② **지도에 줄을 추가하고** 만든다. 지도에 없는 문서는 반드시 중복이 된다.
   (`DEPLOY.md` 가 지도에 없어서 이번 중복이 났다 — 그래서 등재했다.)
3. **이미 있는 것을 고칠 때는 원본을 먼저 읽는다.** 덮어쓰기 전에 무엇이 사라지는지 본다.

### N-27. **전제가 거짓이면 금지·예시를 아무리 고쳐도 안 낫는다** (2026-08-27) ★★★★★

저녁 대화가 「우리 지금 뭐 하는 거야?」로 새는 것을 두 번(N-23) 고쳤는데도
2026-08-27 관전 판에서 **여섯 명 중 여섯이 또** 그렇게 시작했다.

원인은 금지도 예시도 아니었다. **상황문이 거짓이었다.**

```
프롬프트: "밤이 오면 누군가 죽는다.  너희는 이 규칙을 이미 다 안다."
실제 규칙: 첫날 밤에는 아무도 죽지 않는다  (round.js · 밸런스 실측으로 넣은 규칙)
```

저녁은 **첫날에만** 열린다. 그러니 이 문장은 **한 번도 참인 적이 없었다.**

무너지는 순서가 이랬다.

1. 「죽는다」고 들었는데 뭘 해야 할지는 모른다 → 「지금부터 뭘 해야 돼?」
2. 다음 날 아침, **아무도 안 죽어 있다** → 「마피아가 쉬었냐?」 · 「왜 안 죽인 거야?」
3. 2일차 토론 표본이 통째로 그 얘기였다

**교훈 셋.**

- **「너는 이미 다 안다」고 못박을 거면 주는 내용이 사실이어야 한다.**
  전제를 강하게 박을수록 그 전제가 틀렸을 때 피해가 커진다. N-23 의 「모를 수가
  없게 만든다」는 옳았지만, **틀린 것을 모를 수 없게 만들면** 더 나빠진다.
- **「사실이 없다」와 「사실이 틀렸다」는 증상이 같다.** 둘 다 모델이 딴 데로 샌다.
  그래서 N-23 에서 원인을 「금지 과다」로만 짚고 끝냈다. **상황문 자체를 규칙과
  대조하지 않은 것**이 진짜 누락이었다.
- **부정 정보에도 이유를 붙인다.** 「아직 아무도 죽지 않았다」만 주면 모델이 이유를
  지어낸다(「마피아가 봐줬나」). 2일차 무사망은 **규칙**, 그 뒤는 **의사** — 이유가
  다르므로 `day` 로 갈라서 준다.

**검증:** 회귀 217 → **224**. 저녁·2일차·4일차 프롬프트를 SAM 없이 직접 찍어 확인한다.

> ⚠ **이걸 잡은 건 내가 아니라 주영님이다.** 나는 대사 표본을 뽑아 놓고
> `/규칙|룰|처음이라/` 로 세어 「규칙 질문 0건」이라고 보고했다. 정작 표본에는
> 「우리 여기서 뭐 하는 거지?」가 줄줄이 있었다 — **낱말로 세고 뜻을 안 읽었다.**
> `dpr` 로 검색해 「빠졌다」고 했다가 본문엔 `devicePixelRatio` 로 적혀 있던 것과
> **같은 실수다.** 표본을 뽑았으면 **세기 전에 읽는다.**

### N-28. **프롬프트는 쌓이면 무력해진다 — 정기적으로 걷어내라** (2026-08-27) ★★★★★

주영님 질문에서 시작했다. *"결함 찾을 때마다 스택한 프롬프트가 너무 쌓여서
오히려 말을 안 듣는 경우가 있을 수 있나?"* — **재 보니 그랬다.**

**정리 전 (토론 프롬프트)**

```
3,448자 · 93줄 · 13절 · 금지 26개 · **강조 42개** · ★ 절 8개
```

그런데 ⛔ 로 못박아 둔 것을 실제로 이만큼 어겼다(78줄 표본):

| 금지 | 위반 |
|---|---|
| 「"근데"로 시작하지 마라」 | **23%** |
| 「되묻기만 하지 마라」 | **23%** |
| 「말버릇 지적하지 마라」 | 17% |

**금지를 26개 쌓아 놓고 넷을 대놓고 어긴다.** N-21 이 「강조는 예산이 있다」고
적어 뒀는데, 42개면 예산 초과가 아니라 **예산 개념이 없는 상태**다.

**중복이 실제로 있었다.** 결함을 찾을 때마다 *가장 가까운 자리에* 한 줄을
붙여 왔기 때문이다 — 이미 다른 절에 같은 말이 있는지 보지 않았다.

| 금지 | 몇 곳에 |
|---|---|
| 자기를 3인칭으로 부르지 마라 | `[나]` + `[말버릇]` = **2곳** |
| 되풀이하지 마라 | 「이미 나온 말」·「그대로 베끼지」·「이미 확인된 사실」·「남 표현 따라」 = **4곳** |
| 되묻기만 하지 마라 | 상황문 + `[말할지 말지]` = **2곳** |

**정리 후**

```
2,729자 · 81줄 · 금지 17개 · 강조 2개 · ★ 절 2개     (-21% 길이, -35% 금지, -95% 강조)
```

**규칙 넷.**

1. **금지를 새로 붙이기 전에 「이미 어딘가에 있나」를 찾는다.**
   같은 금지를 네 곳에 두면 네 곳 다 약해진다. 있으면 **그 자리를 고친다.**
2. **강조는 예산이다(N-21 강화).** `**`는 프롬프트당 **5개 이하**, `★` 절은 **2개 이하**.
   남길 것은 「어기면 게임이 끝나는 것」뿐이다 — 역할 선언과 말투.
3. **위반율이 높은 금지는 프롬프트에서 빼고 코드로 옮긴다(N-2).**
   「근데 금지」는 23%가 어겼다 → `첫마디다듬기()` 로 **받은 뒤에 깎는다.**
   되물어보지 않으므로 **SAM 호출이 늘지 않는다.**
4. **회귀로 상한을 못박는다.** 줄 수·금지 수·강조 수에 상한 검사를 걸어 뒀다.
   여기서 더 붙이려면 **뭔가를 빼야** 통과한다. 이게 없으면 또 쌓인다.

**검증:** 회귀 **224 → 246**, 실패 0.

> ⚠ **아직 안 고친 것이 있다.** 「추리할 재료를 전부 금지해 놓고 추리를 시킨다」 —
> 시각·알리바이·동선이 다 금지라 남는 수단이 「분위기와 말투」뿐이고,
> 그래서 **말버릇 지적이 아무리 막아도 돌아온다.** 금지가 약해서가 아니라
> **그것 말고 할 게 없어서**다. 이건 프롬프트가 아니라 **게임 설계** 문제다.

### N-29. **고정 문자열 목록은 모델을 못 잡는다 — 틀 × 대상의 곱으로 본다** (2026-08-27) ★★★★☆

`메타지적인가()` 가 「말버릇 지적」을 걸러 내라고 만든 판정기인데, 목록이
**고정 문자열 14개**(`"왜 자꾸 물어"`·`"같은 말만"` …)였다. 결과:

```
78줄 중 14줄이 실제로 메타 대화였는데  →  판정기는 0건이라고 답했다
```

모델은 같은 뜻을 **매번 다르게** 말한다. 목록에 없는 표현만 골라 쓴 게 아니라,
그냥 자연스럽게 쓰다 보니 목록을 다 비껴갔다.

> 「왜 **아까부터 그냥 물어만** 봐?」 · 「**아까부터 듣기만** 하네」
> 「남 말에 계속 **맞장구만** 쳐」 · 「왜 자꾸 **음만** 내」 · 「**자꾸 나 보네**」

**→ 낱말을 세지 말고 「틀 × 대상」의 곱으로 본다.**

```
틀   = 자꾸 · 계속 · 아까부터 · 왜 다들 · 왜 아무도 · ~만 하네     (되풀이를 지적하는 말)
대상 = 말 · 얘기 · 묻다 · 듣다 · 조용 · 맞장구 · 반복 · 음만       (발화 자체)
둘이 같이 있을 때만 잡는다 →  12/12 검출 · 오탐 0
```

**⚠ 이 판정기의 진짜 어려움은 「잡는 것」이 아니라 「안 잡는 것」이다.**

```
"왜 자꾸 부엌에 갔어?"   → 틀 O · 대상이 행동   → 통과해야 한다 (정상 추리)
"왜 자꾸 물어만 봐?"     → 틀 O · 대상이 발화   → 잡아야 한다
```

**「자꾸」 하나로 자르면 게임이 죽는다.** 회귀에 통과 케이스를 잡는 케이스만큼
넣어 뒀다 — 다음에 목록을 넓힐 때 여기서 걸린다.

**곁가지로 알게 된 것:** 검출된 27줄 중 **5줄이 꾸벅이의 「음...」에 대한 반응**이었다.
알맹이 없는 한 줄이 **메타 대화를 다섯 줄 만든다.** 필터를 넓히는 것보다
**원천에서 「음...」을 안 말한 것으로 치는 쪽이 싸다** — 되묻지 않으니 SAM 도 안 든다.
