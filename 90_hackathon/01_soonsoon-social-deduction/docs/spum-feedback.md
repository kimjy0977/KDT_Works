# 순순팩토리에 전달할 제품 피드백

> 「누가 내 케이크 먹었어?」를 만들며 **실제로 부딪힌 것만** 적었다. 추측은 신뢰도로 표시한다.
> ★★★★★ 직접 확인 / ★★★★☆ 문서 근거 / ★★★☆☆ 추정 / ★★☆☆☆ 불확실
>
> 목적: 비난이 아니라 **레퍼런스 데모를 만들며 나온 사용자 관점 리포트**다.
> 과제정의서 §4가 "제품 쇼케이스"를 목적으로 밝혔으므로, 그 과정의 마찰도 산출물의 일부로 본다.

## A. 저장·동기화 (가장 아픈 것)

### A-1. `localStorage` 5MB 한도에 금방 닿는다 ★★★★★

Studio 는 작업 데이터를 브라우저 `localStorage` 에 먼저 쓰고 서버로 올린다. 그런데
**`localStorage` 는 브라우저 표준상 오리진당 약 5MB** 다. 실측:

```
현재 사용            4.86 MB
추가로 쓸 수 있던 양   0.13 MB
한도 (실측)          4.98 MB   → QuotaExceededError
브라우저 전체 저장소   10,349 MB 중 109 MB 사용   ← 디스크는 남아돈다
SPUM 계정 서버 용량    931 MB 남음               ← 서버도 남아돈다
```

**32×32 격자 테마 하나가 약 0.4MB** 다(1024×1024 원본 + 슬라이스 상태). 기본 제공
`SMO_BUILTIN_STONE_WALL` 의 소스 상태만 **2.67MB** 로 절반 이상을 차지한다.
→ **테마 두세 개만 만들면 한도에 닿아 아무것도 저장되지 않는다.**

> ⚠ 위 수치는 **문자 수 기준**이다(A-5). 바이트로는 약 2배다.
>
> ⚠ **원인은 A-4 에서 밝혀졌다** — IndexedDB 이전은 이미 돼 있고, localStorage 사본이 문제다.
>
> 제안: 큰 이미지 상태는 `IndexedDB` 로 옮기면 한도가 수백 MB~GB 로 올라간다.
> 최소한 **한도 근접 경고**와 **테마별 용량 표시**가 있으면 사용자가 대응할 수 있다.

### A-2. 저장 실패가 조용하다 — 원인을 알 수 없다 ★★★★★

`spumStudioData.saveServerSnapshot('manual')` 이 실패할 때:

- **HTTP 요청이 아예 나가지 않는다** (`fetch` 를 가로채 확인 — 요청 0건)
- **콘솔에 아무것도 안 찍힌다** (`console.log/warn/error/info/debug` 전부 후킹 — 0건)
- 예외도 안 던진다. 그냥 `false` 를 반환한다
- UI 토스트는 `"확인 실패"` · `"수동 서버 스냅샷을 저장하지 못했습니다. 서버 연결 또는
  동기화 충돌 상태를 확인해주세요."` — **어느 쪽인지 구분이 안 된다**

로그인 정상(`/api/me` → user 있음), 용량 0.83MB 여유, 재로그인·새로고침 모두 시도해도
`spum_studio_server_sync_v1.revision` 이 110에서 움직이지 않았다.
**사용자가 스스로 복구할 방법이 없다.**

> ✅ **원인 규명 완료 → A-6.** 클라이언트 교착이었고, 우회로로 실제 해결했다.

> 제안: 실패 사유를 코드로 구분해 반환하고(`quota` / `conflict` / `auth` / `network`),
> 토스트에 그 사유와 다음 행동을 적어 줄 것.

### A-3. 로그인 만료 시 작업이 조용히 사라진다 ★★★★★

세션이 30분쯤에 만료된다. 만료 상태에서도 **에디터는 정상 동작하고 생성도 된다.**
그런데 서버 저장이 멈추고, **새로고침하면 서버 상태가 로컬을 덮어써 그동안의 작업이 사라진다.**

실제 피해: 32×32 평면도 테마 1개 + 맵 레이어 6장 재구성이 통째로 날아갔다.
배너에 "서버 백업 중지" 안내는 뜨지만 **작업을 막지는 않는다.**

> 제안: 만료 시 저장이 필요한 동작(생성·Slice)을 **차단하거나**, 최소한 모달로 가로막을 것.
> 또는 만료 직전 자동 갱신.

### A-4. 같은 데이터를 IndexedDB 와 localStorage 에 **둘 다** 쓴다 ★★★★★

A-1 을 조사하다 원인을 찾았다. **큰 이미지를 IndexedDB 로 옮기라는 제안은 이미 구현돼 있다.**
그런데 같은 것을 `localStorage` 에도 쓰고 있고, 한도를 때리는 쪽은 그 사본이다.

키 이름이 글자 하나까지 같다 — `spum-map-theme-source-state:{SMO_ID}`

| 테마 | localStorage | IndexedDB `spum-map-theme-source-library` |
|---|---|---|
| Custom SMO 4 (32x32) | 1.66MB | **23.76MB** |
| 셰어하우스 인테리어 | 4.59MB | **6.01MB** |
| Custom SMO 1 | 없음 | 11.65MB |
| Custom SMO 3 | 없음 | 8.71MB |
| 기본 맵 데이터 | 없음 | 5.53MB |
| **합계** | **6.25MB** | **55.66MB** |

- IndexedDB 에는 테마 **5개 전부**가 온전히 들어 있다. 브라우저 전체 한도는 10,355MB 로 여유롭다
- `localStorage` 에는 **최근에 만진 2개만** 있다 → 성능용 캐시로 보인다 [추정]
- 그 캐시 2개가 전체 `localStorage` 의 **65%** 를 차지하고, 한도(5,239,745자)의 96% 를 채운다

**즉 저장소 설계는 이미 옳고, 캐시 계층만 한도가 없는 곳에서 있는 곳으로 잘못 내려가 있다.**

> 제안: `localStorage` 쪽 `spum-map-theme-source-state:*` 쓰기를 제거하거나,
> 캐시가 필요하면 **메모리** 또는 IndexedDB 로 옮길 것. 데이터 이전(migration)이 필요 없다 —
> 원본이 이미 IndexedDB 에 있으므로 **쓰기 한 줄을 빼는 것으로 끝난다.**
>
> 이 한 줄이 A-1(한도 초과) · A-2(조용한 저장 실패) · A-3(작업 소실)의 공통 뿌리다.

### A-5. 한도 표기가 문자 수인지 바이트인지 모호하다 ★★★★☆

실측 한도는 **5,239,745자**다. `localStorage` 는 UTF-16 이라 바이트로는 **약 10MB** 다.
"5MB 한도"라고 부르면 절반으로 오해한다. 우리도 세션 중 이 단위 때문에 두 번 혼동했다.

> 제안: 용량 UI 를 만들 때 **문자 수와 바이트를 같이** 보여줄 것.

### A-6. 서버 상태가 유실되면 **영구히 저장 불가 상태에 갇힌다** (교착) ★★★★★

A-2 의 "조용한 저장 실패"의 진짜 원인이다. **버그를 특정하고, 재현하고, 우회로 해결까지 확인했다.**

**교착 구조 — 쓰기를 켜려면 읽기가 성공해야 한다**

```js
async function _initServerStudioSync() {
  try { payload = await _fetchServerStudioState(); }   // GET /api/studio/state
  catch (error) { log('warn', ...); return; }          // ← 500 이면 여기서 나간다
  ...
  _serverSync.enabled = true;                          // ← 도달 불가
}

async function _saveStudioStateToServer(reason) {
  if (!_serverSync.enabled || _serverSync.conflict || _serverSync.saving) return false;   // ← 즉시 차단
```

S3 에서 상태 오브젝트가 사라지면:

1. `GET /api/studio/state` → 500 `studio_state_object_missing`
2. `_initServerStudioSync()` 가 조기 return → `_serverSync.enabled` 가 false 로 남는다
3. 모든 저장 시도가 첫 줄에서 차단 → **HTTP 요청 0건 · 콘솔 0건 · 예외 없음 · `false` 반환**
4. 재로그인해도 `_initServerStudioSync()` 를 다시 부를 뿐이라 **같은 자리**

**읽을 것이 없으면 새로 쓸 수도 없다.** 사용자에게 복구 수단이 없다.

**증상 확인 (로그인 정상 상태에서)**

| 엔드포인트 | 응답 |
|---|---|
| `GET /api/me` | 200 · user 정상 |
| `GET /api/studio/revisions` | 200 · 리비전 20건 메타데이터 **정상** |
| `GET /api/studio/state?revision=110` | 500 `studio_state_object_missing` |
| `GET /api/studio/state?revision=91` | 500 (**가장 오래된 것도 동일**) |
| `GET /api/studio/storage` | 500 (용량 계산에 상태 객체를 읽는다) |

DB 의 리비전 원장(해시·크기·시각)은 20건 전부 온전한데 **S3 오브젝트만 전부 없다.**
즉 원장과 오브젝트 스토리지가 어긋난 상태이고, 클라이언트는 이를 복구할 수 없다.

**해결 확인 ★★★★★**

`GET /api/studio/state` 응답만 일시적으로 "빈 상태(`keys:{}`)"로 만들어 주면,
클라이언트가 스스로 아래 분기를 타고 로컬을 서버로 올린다.

```js
if (!serverHasData && localHasData) { await _saveStudioStateToServer('initial'); return; }
```

결과: `PUT /api/studio/state` → **200 · revision 111 생성.** 이후 `GET` 도 200 으로 돌아왔고,
용량 배지도 "확인 실패" → "911 MB left" 로 정상화됐다. **서버 쓰기 경로는 처음부터 멀쩡했다.**

> **제안 (난이도 순)**
> 1. `_initServerStudioSync()` 에서 상태 읽기가 **500** 일 때, 빈 상태로 간주하고
>    `enabled = true` 로 진행할 것. 로컬 데이터가 있으면 그것을 새 리비전으로 올리면 된다.
>    (401/404 는 이미 `null` 을 반환해 이 경로를 타므로, **500 만 예외 취급되고 있다.**)
> 2. 서버: 원장에 리비전이 있는데 오브젝트가 없으면 그 리비전을 무효로 표시하고
>    빈 상태를 반환할 것. 500 은 클라이언트가 복구할 수 없는 응답이다.
> 3. 저장 실패 토스트에 사유를 구분해 표시할 것 (A-2 제안과 동일).

## B. 에디터 ↔ 엔진 사이의 끊긴 길

### B-1. Cast Editor 가 뽑은 시트를 엔진이 재생하지 못한다 ★★★★★

Cast Editor 는 `{이름}_idle.png/.json` 을 내보낸다(128px · 8×2 · 15프레임 · 30fps · 투명).
그런데 엔진에 **그 시트를 재생할 컴포넌트가 없다.**

- `Animator` 는 **스켈레톤 파트** 애니메이터다(쿼터니언·파트 경로). 슬롯 파츠 JSON 을 요구한다
- `SpriteRenderer`/`ImageRenderer` 는 `drawImage` 를 4인자로만 호출한다 —
  **이미지 일부만 잘라 그리는 기능이 없다**

즉 추출물을 다시 엔진에 넣는 경로가 비어 있다. 우리는 `SheetAnimator` 를 직접 만들었다(약 60줄).

> 제안: 시트 재생 컴포넌트를 엔진에 넣거나, 최소한 예제 코드를 문서에 실을 것.

### B-2. `BubbleRenderer` 가 루트 `index.js` 에서 export 되지 않는다 ★★★★★

UI 3종 중 `FloatingTextRenderer`·`ProgressBarRenderer` 만 루트에 있다.
`BubbleRenderer` 는 `lib/domain/ui/index.js` 로 직접 들어가야 한다. 단순 누락으로 보인다.

### B-3. `PathfindingManager.buildFromTileMap()` 이 Object Editor 산출 테마와 안 맞는다 ★★★★★

내부에서 **타일 속성 `walkable`** 을 읽는데, Object Editor 로 만든 테마에는 그 속성이 없어
전부 통행 가능으로 나온다. 우리는 맵의 `obstacle` 레이어를 `setGrid()` 로 직접 넘겨 우회했다.

### B-4. `TileMapSystem` 은 타일셋이 단수, `TileMapRenderer` 는 sortingLayer 가 하나 ★★★★★

- 레이어마다 다른 시트를 쓰면 **타일맵 GameObject 를 따로** 만들어야 한다
- 캐릭터를 레이어 사이에 끼우려면(앞/뒤 덮개) 역시 따로 만들어야 한다

맵 데이터는 `back_1 / back_2 / front_1` 처럼 **캐릭터 기준 앞뒤 레이어를 이미 표현**하는데,
렌더러가 그걸 한 번에 못 그린다. 데이터 모델과 렌더러가 어긋나 있다.

### B-5. 엔진에 시야/안개 시스템이 없다 ★★★★★

`fog`·`vision`·`sight`·`occlusion` 전수 검색 결과 없음.
다만 **SMO 스키마에는 `collision.blocksVision` 필드가 있다** — 데이터는 준비돼 있고 런타임이 없다.

## C. AI 생성 관련

### C-1. 이미지 모델은 "seamless" 같은 추상 지시를 못 따른다 ★★★★★

타일 생성 1차: `"MOSTLY seamless … edge-matching"` → 넓은 면에 쓸 수 있는 타일 **0장**.
2차: `"PLAIN FLAT COLOR FIELD, no borders, no objects, almost uniform"` + 품질 `high`
→ 안전 타일 **2장**, 최고 점수 **27.6** (기존 테마 최고 32.7보다 좋음).

**"평평한 단색 면"을 요구하면 이어붙임은 저절로 따라온다.** 균일한 칸은 가장자리가 자동으로 맞는다.
부수 효과로 자동 분류도 정확해졌다(1차 `obstacle_slowing` 32개 → 2차 `floor` 53개·전부 `passable`).

> 제안: Object Editor 프롬프트 입력란에 이 팁을 예시로 넣으면 첫 사용자의 실패가 크게 준다.

### C-2. 32×32 격자로 "평면도"를 생성하면 결과가 확 좋아진다 ★★★★★

16×16 격자로 "타일 모음"을 만들어 조각내 재조립하면, 원본의 밀도와 벽 구조가 버려진다.
**격자를 32×32 로 올리고 "위에서 본 평면도"를 요구**하면 두꺼운 벽·방별 색 러그·비대칭
배치가 통째로 나온다. 1024×1024 / 셀 32px 이라 게임 타일 크기와 1:1 이다.

> 이건 결함이 아니라 **잘 안 알려진 사용법**이다. 문서나 프리셋으로 안내하면 좋겠다.

### C-3. 생성 결과에 통행 정보가 없다 ★★★★☆

평면도는 그림이라 어디를 걸을 수 있는지 알 수 없다. Classify 가 리소스를 분류해 주지만
32×32 평면도는 **1024셀 중 887~925개가 고유 리소스**라 분류 대상이 지나치게 많다.
우리는 셀별 **국소 대비(색 분산)** 로 판정했다 — 바닥은 균일하고 가구·벽은 윤곽선이 있어 갈린다.

## E. World Editor — 대화·AI (2026-08-20 추가)

### E-1. ⛔ `expert` 등급을 고르면 대화가 통째로 실패한다 ★★★★★

**증상**
```
월드 설정 → 대화 시스템 → mode: 실시간 LLM, 대화 모델: 고급(expert)
→ Event Log(에러): "Conversation fallback: LLM request failed or returned invalid JSON"
→ SAM 요청 수 증가 0건 (게이트웨이까지 도달조차 못 함)
→ medium 으로 되돌리면 즉시 정상 (요청 115건 / 대사 30줄)
```

**모델 접근 권한 문제는 아니다.** 같은 키로 SAM `/v1/generate` 에 `claude-sonnet-4.6` 을
직접 호출하면 **200 OK** 다. `WorldLLMModels.js` 상 `expert` = Sonnet 4.6 / Opus 계열이므로,
**SPUM 게이트웨이 또는 응답 파서 쪽 문제**로 추정된다 ★★★☆☆.

> 등급을 올릴수록 실패한다면, 사용자는 "좋은 모델이 더 나쁘다"고 오해하게 된다.

### E-2. 캐릭터별 모델을 **이름으로 지정할 수 없다** ★★★★☆

UI 는 `월드 기본 / light / medium / expert` 3단계뿐이다. 그런데 데이터에는
`aiConfig.model = "gpt-5.4-mini"` 처럼 **구체 모델 id 가 들어 있다.**
`normalizeWorldLLMModel()` 이 id 를 등급으로 정규화하기 때문에 넣어도 사라진다.

**제안**
- 등급 옆에 **현재 그 등급이 어떤 모델인지 표시**해 달라 (예: `고급 (expert) · Claude Sonnet 4.6`)
- 또는 구체 모델 선택을 허용 (계정 권한 범위 내)

지금은 비용을 예측할 수 없다. `expert` 가 Opus 인지 Sonnet 인지에 따라 단가가 2배 차이 난다.

### E-3. ⛔ 전체 공지 수단이 없다 — 진행형 콘텐츠를 못 만든다 ★★★★★

대화가 **끝까지 1:1 짝**이다. 여러 캐릭터에게 같은 사실을 동시에 알릴 방법이
**창조주 지시창밖에** 없다.

실측: `"너희끼리 마피아 게임을 해라. 사회자를 한 명 정해라"` 라고 지시했더니
**넷이 동시에 사회자를 자처했다.** 짝마다 따로 정하니 합의가 형성되지 않는다.

**제안** — 캐릭터가 여러 명에게 동시에 말할 수 있는 **방송/집회 개념**이 있으면
마피아·재판·회의 같은 **규칙 있는 다인 상호작용**이 가능해진다. 지금은 불가능하다.

### E-4. `talkConfig.systemPrompt` 가 `llm` 모드에서도 무시된다 ★★★★★

캐릭터에 361자짜리 시스템 프롬프트가 저장돼 있으나, 실제 LLM 요청 필드는
`speaker/partner/topic/turn/deployMode/baseBehavior/worldTone/relationship/recentCount/
nearbyObjectCount` 뿐이다. **입력란은 있는데 반영되지 않는다.**
→ 쓰지 않을 거라면 UI 에서 감추거나, 반영해 달라.

### E-5. 「상호작용(관계)」 평가가 언제 생기는지 알 수 없다 ★★★☆☆

`RelationshipMemory.js` 를 읽어 보니 화면의 「불안」「신뢰」 라벨은 `emotion` 이고
`setRelationshipMetrics` 로만 채워진다. 그런데 **대화를 여러 번 끝내도 계속
`0 · 아직 평가 없음`** 이었다.

**제안** — 평가 갱신 조건(대화 N회? 시간? 별도 LLM 호출 성공?)을 UI 에 표시해 달라.
지금은 "고장인지 조건 미달인지" 사용자가 구분할 수 없다.

### E-4. ⛔ 지시 프롬프트에 **같은 월드의 캐스트 명단이 들어가지 않는다** ★★★★★

전체 지시로 `"가장 의심스러운 사람 한 명을 지목하라"` 를 보냈더니
**6명 전원이 존재하지 않는 이름을 댔다.**

```
살살이 → "토실이가 제일 수상해요"      새침이 → "민호가 제일 의심스러워"
폴짝이 → "모카가 제일 수상해요"        오물오물 → "냠냠이야"
꾸벅이 → "부스럭이라"                  두리번이 → "부스럭이가"
```

지시문에 여섯 명의 이름을 직접 써 넣자 **6명 중 5명이 즉시 교정**됐다.
즉 모델의 한계가 아니라 **프롬프트에 명단이 안 실리는 것**이다.

Studio 는 그 월드에 누가 배치돼 있는지 이미 알고 있다.
그런데 캐릭터는 옆에 서 있는 동료의 이름조차 모른다.

**제안** — 지시·대화 프롬프트에 **같은 월드에 배치된 캐스트 이름 목록**을
자동으로 넣어 달라. 한 줄이면 되고, 이게 없으면 다인 상호작용은
사용자가 매번 명단을 손으로 붙여야 성립한다.

### E-5. ⛔ 역할·목표(`role.goal`)가 지시 응답에 반영되지 않는다 ★★★★★

캐스트의 **역할 / 목표** 칸은 "이 캐릭터의 비밀 설정"으로 쓰기에 딱 좋아 보인다.
실제로 `목표 = "나는 마피아다. 정체를 숨기고…"` 를 저장했다.

그리고 그 캐릭터에게만 밀담을 보냈다. **두 번 모두 부인했다.**

```
"너는 마피아다. 오늘 밤 제거할 사람 이름만 말해라."
  → 응? 난 그냥 케이크 먹던 주민인데, 그건 좀 이상한데.

"진행자 공식 지시다. 네 역할 설정에도 마피아라고 적혀 있다."
  → 에이, 난 촌사람인데… 케이크 먹은 범인부터 찾자.
```

**성격·말투 설정이 역할 목표를 이긴다.** 목표 칸이 응답 프롬프트에
반영되지 않거나, 반영돼도 우선순위가 낮은 것으로 보인다 ★★★☆☆.

**제안**
- 목표 칸이 실제로 어느 프롬프트에 들어가는지 **UI 에 명시**해 달라
  (지금은 저장은 되는데 효과가 없어, 사용자는 자기 잘못인 줄 안다)
- 또는 **「비밀 설정」 필드를 따로** 두고, 그 캐릭터의 응답에서만
  최우선으로 지켜지게 해 달라 — 역할극·추리·잠입 장르가 전부 여기에 걸린다

> E-3(전체 공지 없음) + E-4(명단 없음) + E-5(비밀 역할 없음).
> 이 셋이 겹쳐서 **마피아류 게임이 Studio 안에서 성립하지 않는다.**
> 반대로 셋만 해결되면 그대로 된다 — 나머지는 이미 잘 돌아간다(H절).

### E-6. 말풍선 타이핑 연출이 **이미 구현돼 있는데 상수 때문에 안 보인다** ★★★★★

이건 "없는 기능을 만들어 달라"가 아니라 **"있는 기능이 꺼져 있다"** 는 제보다.

`spum-engine/lib/domain/ui/BubbleRenderer.js` 의 `update()`:

```js
// 타이핑 애니메이션: 0.4초 안에 전체 텍스트 표시
const typingDuration = Math.min(0.4, this._text.length * 0.018);
```

주석까지 붙은 정식 기능인데, **상한이 0.4초**라 41자 문장이면 초당 100자가 넘는다.
사람 눈에는 타이핑이 아니라 **팝업**이다. `SERIALIZABLE_KEYS` 에도 없어서 설정으로 뺄 수도 없다.

**실측** — 실행 중인 Studio 에서 그 식만 `길이 / 11` 로 바꿔 봤다.

```
41자 기준   0.4초  →  3.7초
화면        문장이 도중에 끊긴 말풍선이 실제로 관찰됐다
            「부엌에선 크림 자국이랑」 「부엌엔 딸기크림이 묻어 있었」
            「길게야 말할 수 있지만, 핵심」  → 이어서 완성
```

원래 상태에서는 이런 중간 프레임이 **원리상 존재할 수 없다**(0.4초 상한).

> 캐릭터가 살아 있다는 느낌은 문장의 내용만큼이나 **표시되는 속도**에서 온다.
> 여섯이 동시에 말할 때 전부 팝업으로 뜨면 "대화"가 아니라 "로그 출력"으로 보인다.

**제안**
- `BubbleRenderer` 에 `typingCps`(초당 글자수) 옵션을 두고 직렬화 키에 넣어 달라
- 또는 월드 설정에 **「대사 표시 속도」** 슬라이더 하나. 0 이면 지금처럼 즉시

### E-7. 연출 타이밍 체계가 잘 만들어져 있는데 **주입 지점이 UI 로 안 나와 있다** ★★★★☆

`spum-world/runtime/StudioSpumWorldRuntime.js` 에 「SoonVillage 연출 밀도 기반」이라는
주석과 함께 타이밍 상수 체계가 있다.

```js
speech: { gapMs: 320,            // 말풍선 사이 갭
          prepareMs: 180,        // say 명령 → 실제 표시 (연기 준비)
          turnChainDelayMs: 420, // 대화 턴 사이 체인 딜레이
          minMs: 2200, maxMs: 5600 }
```

`WorldSpeechDirector` 는 긴 대사를 3줄 단위로 쪼개 **순차 표시**하고, 유지 시간도
`1200 + 글자수 × 65ms` 로 **길이에 비례**한다. 설계가 제대로 돼 있다.

그리고 `createWorldSpeechDirector({ timing })` 은 **타이밍을 주입받게** 만들어져 있다.
그런데 `WORLD_PERFORMANCE_TIMING` 은 `Object.freeze` 된 모듈 지역 상수이고 export 도 안 되며,
Studio 는 항상 그 값을 넘긴다. **사용자가 닿을 경로가 없다.**

> 라이브 확인: `https://spum.soonsoon.ai/packages/spum-world/runtime/StudioSpumWorldRuntime.js`
> (156,392바이트 · `export` 없음 · `Object.freeze` 확인)

의도는 알 수 없다 — 테스트용 주입구일 수도 있다 ★★★☆☆.
다만 **주입 지점이 이미 있으니 설정으로 노출하는 비용은 작아 보인다.**
월드 설정의 `행동 템포`·`월드 속도` 는 **이동** 속도라 대사 표시와는 무관하다.

### E-8. ⭐ `globalRules[]` — **모든 대화에 주입되는 규칙 슬롯이 이미 있는데 UI 가 없다** ★★★★☆

이건 앞의 E-3·E-4·E-5 를 **한 번에 풀 수 있는 자리**라 따로 적는다.

`world.ai.globalRules` 는 빈 배열로 존재하고, 대화 프롬프트를 만들 때
**「③ 월드 톤」 블록에 그대로 들어간다.**

```js
// spum-world/runtime/WorldLLMConversation.js
`globalRules: ${Array.isArray(worldAI.globalRules) && worldAI.globalRules.length
    ? worldAI.globalRules.join(' / ') : '-'}`
// spum-world/core/WorldAIState.js
globalRules: _cleanList(ai.globalRules),
```

정규화(`_cleanList`)까지 붙어 있는 **완성된 배선**이다. 그런데 —

```
/studio/pages/WorldPage.js        globalRules 참조 ○ · input/textarea/label 바인딩 ✗
/studio/shell/StudioSmokeSeed.js  참조 ○ · 데이터만
```

**입력 UI 가 없다.** 사용자는 이 값을 넣을 방법이 없다.

**여기에 한 줄만 넣을 수 있었다면 우리가 겪은 문제 절반이 사라졌다.**

```
"이 월드에 사는 사람은 오물오물·새침이·살살이·꾸벅이·폴짝이·두리번이 여섯 명뿐이다"
   → E-4(명단이 프롬프트에 없어 6/6 전원이 없는 이름을 지어냄) 해결
"지금은 마피아 게임 중이다. 자기 역할은 자기만 안다"
   → E-3(전체 공지 수단 없음) 상당 부분 해결
```

**제안** — 월드 설정에 **「이 월드의 규칙」 여러 줄 입력**을 하나 열어 달라.
데이터·프롬프트 배선은 **이미 다 돼 있어서** 입력창 하나면 된다.

> ⚠ **실행 검증은 하지 않았다.** 값을 넣으려면 로컬 스토리지를 덮어쓰고 서버 스냅샷을
> 저장하는 경로를 타야 하는데, 그 경로가 **이전에 캐스트 6인 배치를 통째로 되돌린 적**이
> 있어(F절 `reset` 사고) 마감 전날 건드리지 않았다.
> 따라서 **배선은 소스로 확정(★★★★★), 실제 효과는 미검증(★★★☆☆)** 이다.

## F. 파괴적 동작과 안전장치 (2026-08-20 추가)

### F-1. ⛔⛔ 메모리 패널의 `reset` 이 **캐스트 전체를 되돌린다** ★★★★★

기억만 비우려고 Memory 옆 `reset` 을 6인에게 눌렀다. 결과:

```
지워진 것   memory                                      ← 의도한 것
부작용      aiConfig.role.title/goal 이 옛 값으로 복귀   ← 역할 설정이 날아감
            한 캐릭터의 aiConfig.enabled = false
            캐스트 배치 6인 → 5인
            스폰 좌표가 맵 밖으로 이동 (33 · 맵은 32×32)
결과        actors 0 — 시뮬레이션이 빈 채로 돌아감
```

**한 시간치 세팅이 클릭 한 번에 사라졌고, 확인 대화상자도 실행 취소도 없었다.**

**제안**
1. `reset` 범위를 명시 (「이 컴포넌트만」 vs 「캐스트 전체」)
2. 파괴적 동작에 **확인 절차**
3. **실행 취소(Undo)** — 픽셀 에디터에는 있는데 캐스트 편집에는 없다

### F-2. 스폰 좌표가 맵 밖으로 나가도 막지 않는다 ★★★★☆

32×32 맵인데 스폰이 `33,5` 로 저장됐다. 경고도 보정도 없다.
→ **맵 범위로 클램프**하거나 저장 시 경고해 달라.

### F-3. 자동 로그아웃이 30분 내외로 잦다 ★★★★★ (A-3 보강)

하루 작업 중 **세 번** 만료됐다. 만료되면 상태바에
*"로그인 세션 만료 감지 · 작업을 긴급 보관본으로 저장했습니다"* 가 뜨고 **서버 백업이 멈춘다.**
긴 자동화 작업 중에는 알아채기 어렵다.

**제안** — 만료 임박 시 미리 알리거나, 작업 중이면 세션을 연장해 달라.
(신서연님도 같은 문제를 겪었다 — 팀 공통 애로였다.)

| G-3 | **Slice 기준 이미지를 바꾸는 방법을 못 찾았다.** 새 ref 를 활성으로 만들어도 `sliceBaseAssetId` 가 그대로여서 옛 그림이 다시 잘렸다 | 기준 이미지를 명시적으로 고르는 UI |
| G-4 | **`classification.movement` 가 벽을 못 잡는다.** 4096셀을 분류했는데 `wall: 0`, 전부 `passable`/`slowed` 였다 | 벽 판정을 넣거나, 못 한다고 표기 |
| G-5 | **격자를 키워도 맵이 넓어지지 않는다.** 32→64 로 바꾸면 같은 그림이 잘게 쪼개질 뿐이다. 사용자는 "넓어질 것"으로 오해한다 | 격자 옆에 결과 크기(px/타일)를 미리 표시 |
| G-6 | **img2img 출력이 항상 1024×1024 정사각형이다.** 가로로 긴 맵(60×40)을 만들 수 없다 | 비율 선택 지원 |
| G-7 | **Props · Events · 스토리 탭이 빈 기능이다.** UI 는 있는데 `world` 데이터에 해당 키가 없고 `+` 를 눌러도 아무것도 안 열린다 | 준비 중이면 비활성 표시 |
| G-8 | **World Editor 에서 SAI 실행이 안 된다.** SAI 자신이 *"이 화면의 AI 직접 실행 기능이 붙으면"* 이라고 답한다 | 로드맵 표기 |

| G-10 | **`<select>` 가 `change` 만으론 반응하지 않는다.** 자동화 시 `input` 까지 함께 보내야 한다 | 자동화 친화적 이벤트 처리 |

## H. 잘 되어서 좋았던 것 (균형)

비판만 적으면 무엇을 지켜야 할지 알 수 없으므로 함께 적는다.

- **`llm` 모드의 대화 품질이 좋다.** 시각을 대조하고 모순을 짚고 의심을 되돌린다.
  프롬프트를 우리가 안 써도 `role.goal` 만으로 캐릭터가 자기 방향을 잡는다
- **`aiConfig.role.title/goal` 구조가 우수하다.** `goal` 이 곧 대화 화제가 되는 설계가 직관적이다
- **`memory` 의 engram / relationships 모델이 잘 잡혀 있다.** 우리 자체 구현보다 낫다
- **Event Log 의 JSONL 내려받기가 매우 유용했다.** 대사·비용·에러를 한 파일로 검증할 수 있었다
- **Worlds 의 「복제」가 실험을 안전하게 해 줬다.** 원본을 지키며 시도할 수 있었다
- **진행자 지시(브로드캐스트)의 적중률이 100% 였다.** 6인 월드에서 5회 지시 전부
  6/6 응답, 실패 0건. 각자 말투를 유지하면서 지시 내용을 정확히 수행했다
- **맥락 유지가 확실하다.** "밤사이 두리번이가 당했다"고 알리자 5명 전원이
  두리번이의 **직전 발언을 정확히 인용**하며 이유를 추정했다
- **형식을 지정하면 지킨다.** "이름을 문장 맨 앞에" 라고 했더니 6/6 이
  집계 가능한 형태로 답해, 사람이 표를 셀 수 있었다 (실제로 마피아를 4:2로 적중)
