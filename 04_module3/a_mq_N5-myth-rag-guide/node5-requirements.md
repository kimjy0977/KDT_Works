- 빈칸은 `[결정 필요]`로 남긴다(제출 전엔 닫는다).
- 수용 기준 예: 소개에 출처 표시 / 대표 질문에 **[ID] 근거를 가진 스트리밍 답변** / 도메인 밖 질문에 **refusal=true** / 모든 답변에 판정 배지 / **API 키 없어도 로컬 자기평가 시도** / **판정 실패해도 UI 안 무너짐** / 상대시간은 질문 시점 KST / **출처 칩에서 원문 열림** / Ollama 꺼지면 **배너와 재시도** / CORS 설정 뒤 github.io에서도 동작
- "로컬 judge는 같은 2B 모델이므로 독립 평가가 아니며 **교육용의 거친 신호**로 읽어야 한다" — 이 한계를 밝힐 것

## 3강 — 자료 수집과 청크

- 청크 = 출처를 가진 레코드. 필드 `id, text, url, section, vector`.
- **최소 120자**의 사실 단위. 경계 3확인: ①한 청크에 하나의 중심 사실 ②단독으로 읽어도 주어·맥락 충분 ③요약했으면 URL·섹션 더 엄격히.
- "**실제로 열어 보지 못한 URL을 만들어 내지 말라**" / 확인 못 하면 `[검증 필요]`
- ID 규칙: `MC-001`처럼 일정한 규칙. "한 코퍼스 안에서 규칙을 바꾸지 않는다."
- 실습: 자기 도메인에서 **8~15청크**. (37은 목표 수가 아님)
- "URL이 빠진 청크는 검색 점수가 높아도 사용자가 검증할 수 없고, section이 빠진 청크는 나중에 원문을 고칠 때 무엇을 다시 임베딩해야 하는지 알기 어렵다."

## 4강 — 임베딩과 벡터스토어

- 모델 `onnx-community/embeddinggemma-300m-ONNX`, **768차원**.
- 첫 방문 약 200MB, 첫 로드 **5~15초** → "화면은 멈춘 것처럼 보이지 않게 **진행 상태와 캐시 여부**를 보여 주어야 합니다."
- 캐시: HF resolve URL이 서명된 CDN으로 리다이렉트되어 HTTP 캐시가 불안정 → **원래 URL을 키로 Cache Storage에 직접 보관**, 적중 시 캐시 사용 여부 즉시 알림. 실패 시 1회 재시도 후 다운로드 경로 유지.
- pipeline() 기본 q4/q8는 GatherBlockQuantized 미지원 → **토크나이저(AutoTokenizer)와 ORT 세션 분리**, `model_no_gather_q4.onnx` + WASM 공급자.
- **mean pooling(attention_mask 반영) + L2 정규화**. 0으로 나누기 방어.
- 384 vs 768 혼재 금지. "차원이 우연히 같아도 서로 다른 모델의 공간을 섞으면 가까움의 뜻이 보장되지 않는다."
- 문서 벡터 생성 시 조건: `dtype:"q4", pooling:"mean", normalize:true`, 생성 후 **모든 vector가 768차원인지 검사**.
- **스팟체크**: 예상 질문으로 top-1/top-3 확인. 문서 범위 밖 질문이 억지로 정답처럼 보이지 않는지도 관찰.

## 5강 — 하이브리드 검색

- 코사인 **상위 10** + (중복 제외) BM25 **상위 5**.
- BM25 원점수를 **해당 검색의 최고 점수로 나누어 0~1 정규화**.
- 반환마다 `chunk, score, method("vector"|"bm25")` 보존 → "사용자가 어떤 근거 청크가 어떤 경로로 들어왔는지 확인할 수 있어야".
- 0.55 미만이면 **버리지 말고 약한 근거 상태 반환** + 프롬프트 보수화 + UI 경고.
- "임계값은 숨은 자동 판정기가 아니라 **답변의 태도를 조절하는 공개된 경계**여야 한다."
- top-1이 기대와 다르면 임계값부터 만지지 말고 역순 점검.

## 6강 — 프롬프트 조립과 스트리밍

- buildPrompt 순서: 자료 소개 → 근거 원칙 → **[ID] 표시 요구** → **KST 현재 시각** → [자료] → [질문]
- 약한 근거 분기 문구 보존: "근거에 있는 내용만 짧게 답하고 자료에 없는 부분은 없다고 말합니다."
- KST: "'지금', '올해', '다음 주' 같은 상대 표현은 이 시각을 기준으로 해석"
- Ollama: `POST /api/chat`, `stream:true, think:false`. 줄바꿈 구분 JSON 조각을 **줄 단위 파싱**. **AbortSignal**로 취소.
- `GET /api/tags`로 연결 상태 확인 → 배너·재시도.
- OLLAMA_ORIGINS 설정(OS별) 후 앱 재시작. **Pages 주소에서 상태 확인과 스트리밍을 함께 점검**.
- Chrome·Edge 권장, **Safari 불안정 안내를 시작 화면에 명시**.
- ★UI 상태 명세: "로컬 엔진 선택 상태, Ollama 연결 여부, **임베딩 준비 상태**, 검색 진행 상태, **생성 중지 동작**, 출처 칩, 약한 근거 경고"
- "**스트리밍이 중단되어도 이미 받은 답변 청크를 지우지 않고**, 출처 칩은 **ID, section, 검색 방법, 점수**를 보여 주며 원문으로 연결"

## 7강 — LLM-as-a-Judge

- 6필드 JSON: `grounded, noHalluc, cited, refusal, score(0-100), comment`
- 로컬 판정 설정: `stream:false, think:false, format:"json", temperature:0`
- 한계 공개: 답변 모델과 평가 모델이 같은 2B → **독립 심사 아님**. "화면과 기록에서 숨기지 않아야".
- 방어: `score ≤ 5`면 `(score/5)×100` 환산. JSON 파싱/호출 실패 시 **judgeError 배지만 남기고 답변·UI 유지**.
- **사람의 좋아요/싫어요**가 판정과 같은 방향인지 어긋나는지 함께 읽는다.
- 실습: 무근거 질문("내일 날씨 어때?")로 `refusal:true` 확인. 질문 원문·답변 핵심 문장·배지·평어를 **기록에 함께** 적는다.

## 8강 — 자기 루브릭 실험

- 지표 **3~5개** 선택, 각 지표가 어떤 판정 필드/사람 검토와 연결되는지 적는다.
- 표: 지표 / 측정 방법 / 목표값 / 지금 값
- 고정 질문: 정상·경계·무근거 **각 최소 3개**를 Q1~Q9로 고정. **질문 원문과 실행 순서를 기록 파일에 그대로**.
- **한 번에 하나의 변수만.** 검색 축(top-k, 0.55 문구, 벡터·BM25 구성) / 프롬프트 축(근거 원칙 문구, 길이 지시, [ID] 규칙, 시간 컨텍스트).
- 각 답변에서 `grounded, noHalluc, cited, refusal, score, comment` 수집.
- README에: 실험 이름, 바꾼 변수, 고정 질문, 각 질문의 판정, 관찰한 근거, **채택 또는 되돌림 결정**. "실패한 답도 지우지 않아야".
- "판정 배지가 자동 채점 도구라 해도, 배지의 true와 false가 실제 답변 및 근거 청크의 관계를 잘 설명하는지는 **학생이 다시 확인**해야 합니다."
