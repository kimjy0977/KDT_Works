# 도구 정의서 — MYTH GALLERY 가이드 챗봇

> 모듈3 노드4 과제 · 도구 4개 (읽기 3 + 쓰기·이관 1)
> 각 도구를 **6항목**으로 정의한다. 특히 **'쓰는 때·안 쓰는 때'** 와 **'실패 뒤 행동'** 을 빠짐없이 적는다.
> 원칙: **도구 하나 = 동작 하나.** 조회와 변경을 한 도구에 섞지 않는다.

## 도구 목록 한눈에

| 도구 | 권한 | 하는 일 |
|---|---|---|
| `search_artworks` | 🔵 읽기 | 신화·모티프·키워드로 작품 검색 |
| `get_artwork_detail` | 🔵 읽기 | 특정 작품 1점의 상세 정보 조회 |
| `get_myth_context` | 🔵 읽기 | 신·신화·모티프의 배경 설명 조회 |
| `submit_inquiry` | 🟠 쓰기(접수·이관) | 사람 처리가 필요한 문의를 접수 |

**권한 분리:** 읽기 도구 3개는 기본 허용. 쓰기 도구 `submit_inquiry`는 **상태를 바꾸므로** 접수까지만 하고 **판단·확정은 사람(담당자)** 이 한다.

---

## 1. `search_artworks` 🔵 읽기

| 항목 | 내용 |
|---|---|
| **이름** | `search_artworks` (동사+대상) |
| **하는 일 한 문장** | 신화·모티프·키워드로 갤러리 작품을 검색해 **목록**을 돌려준다. 읽기 전용이며 어떤 데이터도 변경하지 않는다. |
| **★쓰는 때** | 사용자가 그림·주제·신·모티프를 **찾을 때**. "제우스 나오는 그림", "북유럽 신화 작품", "뱀 모티프" 같은 요청. |
| **★안 쓰는 때** | ① 이미 특정 작품 1점이 정해져 상세만 필요할 때 → `get_artwork_detail`<br>② 작품이 아니라 **신화 배경 설명**만 필요할 때 → `get_myth_context`<br>③ 문의·요청 접수 → `submit_inquiry`<br>④ **6개 신화 밖**(예: 로마 이전 켈트, 일본)을 물을 때 → 호출하지 않고 취급 범위를 안내 |
| **인자 스키마** | `query` (문자열, 필수, 2~100자)<br>`mythology` (enum, 선택: `greco-roman`·`norse`·`egyptian`·`mesopotamian`·`hindu`·`chinese`)<br>`motif` (문자열, 선택)<br>`limit` (정수, 선택, 기본 5, 최대 20) |
| **반환 형식** | 작품 배열 — `id`·`title`·`mythology`·`motif`·`thumbnail_url`·`detail_path`<br>**원문 데이터 덤프 금지.** 내부 DB 식별자·관리자 필드는 반환하지 않는다. |
| **★실패 뒤 행동** | `NO_RESULT` → **결과를 지어내지 않는다.** "찾지 못했습니다"라고 답하고 관련 신화/모티프를 제안한다.<br>`INVALID_MYTHOLOGY` → 취급하는 6개 신화를 알려 주고 다시 선택을 요청한다.<br>`QUERY_TOO_SHORT` → 어떤 신·주제를 찾는지 확인 질문 1개를 돌려준다.<br>`TEMPORARY_ERROR` → **1회만** 재시도하고, 실패하면 중단 후 일시 오류를 안내한다. 추정 답변을 만들지 않는다. |

## 2. `get_artwork_detail` 🔵 읽기

| 항목 | 내용 |
|---|---|
| **이름** | `get_artwork_detail` |
| **하는 일 한 문장** | 작품 ID 하나를 받아 그 작품의 **신화·모티프·설명·출처**를 조회한다. 읽기 전용. |
| **★쓰는 때** | 검색 결과나 사용자가 **특정 작품 1점을 지목**했고 그 작품의 정보가 필요할 때. |
| **★안 쓰는 때** | ① 아직 어떤 작품인지 **정해지지 않았을 때** → 먼저 `search_artworks`<br>② 작품이 아니라 신화 자체의 배경 → `get_myth_context`<br>③ 고해상도 파일·이용 허락 요청 → `submit_inquiry`<br>④ **ID 없이 제목만** 있을 때 → 임의로 ID를 만들지 말고 검색부터 |
| **인자 스키마** | `artwork_id` (문자열, 필수, 갤러리 발급 ID 형식) |
| **반환 형식** | `id`·`title`·`mythology`·`motif`·`description`·`source`(출처·소장 정보)·`detail_path`<br>내부 관리 필드·미공개 메모는 반환하지 않는다. |
| **★실패 뒤 행동** | `INVALID_ID` → **ID를 추측해 재호출하지 않는다.** 작품명을 확인하는 질문을 돌려주거나 `search_artworks`로 되돌아간다.<br>`NOT_FOUND` → "해당 작품을 찾지 못했습니다"라고 답한다. 비슷한 작품 정보로 대체해 답하지 않는다.<br>`TEMPORARY_ERROR` → 1회 재시도 후 중단·안내. |

## 3. `get_myth_context` 🔵 읽기

| 항목 | 내용 |
|---|---|
| **이름** | `get_myth_context` |
| **하는 일 한 문장** | 특정 신·신화·모티프의 **배경 설명**을 조회한다. 읽기 전용. |
| **★쓰는 때** | "제우스가 누구야?", "이 뱀 모티프는 무슨 뜻이야?"처럼 **작품이 아니라 신화 지식**을 물을 때. 작품 설명에 배경 보충이 필요할 때. |
| **★안 쓰는 때** | ① 특정 그림을 찾는 요청 → `search_artworks`<br>② 특정 작품의 정보 → `get_artwork_detail`<br>③ **갤러리가 다루지 않는 신화**를 물을 때 → 호출하지 않고 취급 범위(6개 신화)를 안내<br>④ 사실 확인이 필요한 **학술적 단정**을 요구받을 때 → 조회 결과 범위를 넘어 확정하지 않는다 |
| **인자 스키마** | `mythology` (enum, 필수: 6개 신화 중 하나)<br>`entity` (문자열, 선택 — 신·인물·모티프명) |
| **반환 형식** | `mythology`·`entity`·`summary`·`related_motifs`·`source`<br>출처 없는 설명은 반환하지 않는다. |
| **★실패 뒤 행동** | `NOT_FOUND` → **일반 지식으로 메우지 않는다.** 갤러리 자료에 없다고 밝히고, 관련 신화를 제안한다.<br>`OUT_OF_SCOPE` → 취급하는 6개 신화를 안내한다.<br>`TEMPORARY_ERROR` → 1회 재시도 후 중단·안내. |

## 4. `submit_inquiry` 🟠 쓰기 (접수·이관)

| 항목 | 내용 |
|---|---|
| **이름** | `submit_inquiry` |
| **하는 일 한 문장** | 사람 처리가 필요한 문의를 **접수**한다. 상태를 바꾸는 유일한 도구이며, **접수까지만** 하고 판단·확정은 담당자가 한다. |
| **★쓰는 때** | ① 고해상도 이미지 요청 ② 전시·인쇄·상업적 이용 문의 ③ 작품 정보 오류 제보 ④ **읽기 도구로 해결되지 않아 사람 판단이 필요한** 모든 요청 |
| **★안 쓰는 때** | ① **읽기 도구로 답할 수 있는 단순 조회** — 먼저 검색·상세·배경을 시도한다<br>② 사용자가 **접수를 원하지 않을 때** — 반드시 접수 여부를 먼저 확인<br>③ 연락처 등 **필수 정보가 없을 때** — 임의로 채워 접수하지 않는다<br>④ **저작권·이용 가부를 챗봇이 확정하는 용도로** — 접수는 하되 결론은 내지 않는다 |
| **인자 스키마** | `inquiry_type` (enum, 필수: `high_res`·`usage_rights`·`exhibition`·`data_correction`·`other`)<br>`message` (문자열, 필수, 10~1000자)<br>`artwork_id` (문자열, 선택)<br>`contact` (문자열, 필수 — 사용자가 직접 제공한 것만) |
| **반환 형식** | `inquiry_id`·`status`(접수됨)·`expected_response`(담당자 회신 안내)<br>**다른 사용자의 문의 내역은 절대 반환하지 않는다.** |
| **★실패 뒤 행동** | `MISSING_CONTACT` → **연락처를 지어내지 않는다.** 사용자에게 연락처를 요청한다.<br>`MESSAGE_TOO_SHORT` → 어떤 문의인지 한 문장 더 요청한다.<br>`RATE_LIMITED` → 중복 접수를 막고, 이미 접수된 건이 있음을 안내한다.<br>`TEMPORARY_ERROR` → **자동 재시도하지 않는다**(중복 접수 위험). 실패를 알리고 다시 시도할지 사용자에게 묻는다. |

## 도구 경계가 겹치지 않는가 (자체 점검)

| 상황 | 올바른 도구 | 겹칠 뻔한 도구 | 가르는 기준 |
|---|---|---|---|
| "제우스 그림 보여줘" | `search_artworks` | detail | **대상이 아직 안 정해짐** |
| "이 작품 설명해줘" (ID 있음) | `get_artwork_detail` | search | **작품 1점으로 확정됨** |
| "제우스가 누구야?" | `get_myth_context` | search | **작품이 아니라 지식** |
| "이 그림 고화질 주세요" | `submit_inquiry` | detail | **상태 변경·사람 처리 필요** |

## 권한 요약

| 도구 | 읽기 | 쓰기 | 사람 승인 |
|---|---|---|---|
| `search_artworks` | ✅ | — | 불필요 |
| `get_artwork_detail` | ✅ | — | 불필요 |
| `get_myth_context` | ✅ | — | 불필요 |
| `submit_inquiry` | — | ✅ 접수만 | **필요** — 판단·확정은 담당자 |

> **스키마는 안내일 뿐 권한이 아니다.** 위 enum·길이 제한은 모델이 올바른 요청을 만들도록 돕는 안내이고, 실제 차단은 **서버 실행 계층**이 호출자 신원·허용 범위·중복 여부를 검사할 때 이뤄진다.
