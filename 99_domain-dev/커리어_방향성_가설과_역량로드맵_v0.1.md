# 커리어 방향성 가설과 역량 로드맵

작성일: 2026-08-31  
상태: 초안 v0.1 - 과정 2개월 차 기준의 가설. 6개월 과정 안에서 실험으로 검증한다.

## 1. 이 문서의 결론

현재 가장 가능성이 높은 방향은 아래 한 문장으로 정리된다.

> **시각디자인 기반의 AI 제품 빌더**: 문화·신화·퍼블릭 도메인 소재를 탐색, 창작, 놀이의 디지털 경험으로 바꾸는 사람.

이것은 지금 당장 스스로를 "창업가" 한 단어로 고정하자는 뜻이 아니다.  
당분간은 **디자이너의 감각으로 문제와 경험을 정의하고, AI와 웹 기술로 실제 작동하는 제품을 끝까지 만드는 사람**이 가장 정확한 작업 정체성이다. MYTH 사업화는 이 방향을 검증하는 가장 중요한 장기 프로젝트다.

KDT는 별도 진로가 아니라, MYTH를 만들기 위한 기술 실험실로 둔다.

| KDT에서 배우는 것 | MYTH로 옮길 역량 |
| --- | --- |
| 웹, DB, 배포 | 작품·신화 데이터, 검색, 사용자 흐름 |
| 이미지 생성 | 소재 재해석과 창작 도구 |
| AI 에이전트 | 근거를 제시하고 권리 이슈를 사람에게 넘기는 안내 경험 |
| 게임·공간 AI | 탐험, 수집, 퀘스트, 상호작용 |
| 메인 퀘스트 | 실제 MYTH 기능 또는 검증 가능한 독립 제품 |

## 2. 판단에 사용한 현재 증거

평가는 희망 직업 목록이 아니라 이미 만든 작업의 반복 패턴에서 시작했다.

| 관찰된 작업 | 드러난 강점 |
| --- | --- |
| ORIGIN: 디자인 영감 아카이브, Next.js·Supabase·Claude API | 관심 소재를 웹 제품 구조로 번역하는 능력 |
| 체스 오프닝 트레이너 | 개인 관심사를 명확한 학습 도구로 바꾸는 능력 |
| MYTH GALLERY 안내 에이전트 | 도구 분리, 오류·권리 이관, 대화 검증까지 설계하는 능력 |
| AI 마피아 게임과 화투 로그라이크 기획 | 서사·규칙·AI 상호작용을 게임 경험으로 묶는 능력 |
| 이미지 생성·포즈 제어 과제 | 생성 결과를 조건과 재현성 관점에서 다루는 태도 |
| MYTH 디자인 토큰·공유 계약 | 브랜드 감각과 시스템 설계를 함께 보는 관점 |

반복되는 소재는 **문화, 신화, 게임, 옛 이야기, 퍼블릭 도메인의 재창작**이다.  
반복되는 방식은 **관심사에서 출발해 실제 작동하는 웹·AI 경험을 만드는 것**이다.

## 3. 직업 방향 후보 순위

### 점수 기준

각 항목은 5점 만점이며, 총점은 가중치 합계 100점이다.

- 현재 적합도 30: 이미 해 본 일, 즐기는 작업 방식과의 일치
- 6개월 내 증명 가능성 20: 수료 전 포트폴리오 증거를 만들 수 있는가
- MYTH 사업화 연결성 25: 장기 목표에 직접 쌓이는가
- 장기 확장성 15: 기술과 역할이 바뀌어도 남는가
- 시장성 10: 채용, 협업, 외주, 창업 모두에 통하는가

### 해석

1번과 2번은 경쟁 관계가 아니다.

- **내가 만드는 일의 방향**: 문화·신화 기반 AI 제품 빌더
- **채용·협업에서 설명할 역할명**: AI 제품/경험 디자이너 또는 크리에이티브 테크놀로지스트

즉, 남들이 알아듣는 직무 언어는 2번을 쓰고, 실제 포트폴리오와 사업의 고유성은 1번으로 만든다.

## 4. 우선 갖춰야 할 역량

### A. 반드시 깊게 가져갈 역량

| 역량 | 목표 수준 | 지금 가진 증거 | 다음 증거 |
| --- | --- | --- | --- |
| 문제 정의와 UX 설계 | 사용자의 목표·실패·다음 행동을 화면과 흐름으로 설계 | 디자인 전공, ORIGIN, MYTH 디자인 토큰 | 사용자 5명 인터뷰와 흐름 수정 기록 |
| AI 제품 구현 | 모델 호출, 데이터 흐름, 실패 처리, 배포를 스스로 연결 | Claude API, FastAPI, 이미지 생성, 에이전트 설계 | 로그인·저장·검색이 있는 MYTH 기능 1개 배포 |

| 제품 완주력 | 작은 범위를 정해 공개·측정·수정 | KDT 배포물과 과제 | 4주 단위로 공개 가능한 기능 3회 |

### B. 실무에서 경쟁력을 높이는 보조 역량

1. **프론트엔드 제품 구현**: React/Next.js, 상태 관리, API 연결, 반응형 UI. 디자인을 코드로 옮기는 속도를 높인다.
2. **데이터 모델링**: 작품·신화·출처·권리·태그·관계를 설계하는 DB/스키마 능력. MYTH의 장기 자산이 된다.
3. **평가와 품질 관리**: AI 결과의 정답성, 근거, 실패율을 간단한 표와 테스트로 관리한다. "AI를 붙였다"와 "신뢰 가능한 경험"의 차이다.
4. **제품 서사와 데모**: 무엇을 만들었는지보다 누구의 어떤 경험을 바꿨는지 3분 안에 설명한다.
5. **영어 리서치 독해**: 해외 문화 아카이브, 도구 문서, 논문과 라이선스 원문을 읽는 최소 능력.

### C. 당장은 주력으로 삼지 않을 것

- 모델 학습 연구자나 순수 ML 엔지니어를 첫 목표로 둘 필요는 없다.
- 범용 프롬프트 작성만으로 직업을 정의하지 않는다.
- 대형 게임의 모든 개발 직군을 한 번에 맡으려 하지 않는다.

기술은 필요하지만, 현재의 차별점은 **모델을 새로 만드는 것**보다 **문화적 맥락과 좋은 경험을 가진 AI 제품으로 만드는 것**에 있다.

## 7. 90일 행동 순서

### 1~30일: 한 문제에 고정

- MYTH의 첫 사용자 한 종류를 선택한다. 예: 신화·문화 소재를 좋아하지만 어디서부터 탐색할지 모르는 사람.
- 그 사용자가 10분 안에 얻어야 하는 한 가지 결과를 정한다.
- 기존 MYTH 자산에서 그 결과에 필요한 데이터 20~30개만 준비한다.
- 디자인 시안보다 작동하는 흐름을 먼저 배포한다.

### 31~60일: AI를 신뢰 가능한 기능으로 만든다

- 안내 에이전트에 출처, 모름, 사람 연결을 명시한다.
- 5명 이상이 실제로 사용하는 모습을 보고 막히는 지점을 기록한다.
- 실패를 기능 목록이 아니라 "사용자가 원했는데 못한 일" 단위로 분류한다.

### 61~90일: 설명 가능한 결과로 묶는다

- 기능, 사용자 반응, 개선 내용을 한 페이지 케이스 스터디로 만든다.
- GitHub README에 문제, 실행 방법, 기술 선택, 한계, 다음 단계를 쓴다.
- 3분 데모를 녹화한다.
- 다음 KDT 메인 퀘스트가 이 제품의 무엇을 강화할지 결정한다.

## 8. 자기소개 초안

### 짧은 버전

시각디자인을 기반으로 웹과 AI를 활용해 문화·신화·퍼블릭 도메인 소재를 탐색과 놀이의 제품 경험으로 만드는 AI 제품 빌더입니다.

### 협업/포트폴리오 버전

디자인 감각으로 사용자 경험과 브랜드의 맥락을 설계하고, 웹·데이터·AI 에이전트를 연결해 실제 작동하는 제품을 만듭니다. 현재는 MYTH를 통해 출처와 권리를 고려한 문화·신화 탐색 및 재창작 경험을 사업으로 검증하고 있습니다.

## 9. 외부 환경 참고

WEF의 2025 보고서는 앞으로 중요도가 가장 빠르게 커질 기술 역량으로 AI·빅데이터와 기술 문해력을, 함께 커지는 인간 역량으로 창의적 사고·유연성·호기심·분석적 사고를 꼽는다. 이는 디자인과 AI 구현을 함께 가져가는 방향이 단순 유행이 아니라 장기적으로도 유효하다는 근거다. [WEF Skills Outlook](https://www.weforum.org/publications/the-future-of-jobs-report-2025/in-full/3-skills-outlook/)

동시에 WEF는 그래픽 디자이너처럼 산출물 제작만으로 정의된 역할이 생성형 AI의 영향을 크게 받는다고 본다. 따라서 경쟁력은 "이미지나 화면을 잘 만드는 사람"을 넘어, **도메인 맥락을 정하고 신뢰 가능한 경험을 설계하며 실제 제품으로 연결하는 사람**이 되는 데 있다. [WEF Jobs Outlook](https://www.weforum.org/publications/the-future-of-jobs-report-2025/in-full/2-jobs-outlook/)
