# 강의 기록·전달 가이드

> KDTTutor 정본. 강의를 **① 노트에 기록**하고 **② 주영님께 전달**하는 두 작업의 규칙을 한곳에 모은다.
> 여러 세션·시점에 흩어진 지시를 통합했다. 메모리(`feedback-lecture-*`)는 이 파일을 가리키는 포인터로만 둔다.
> 최종 갱신 2026-08-24.

---

## 0. 두 작업을 헷갈리지 않는다

| 작업 | 결과물 | 정본 |
|---|---|---|
| **① 기록** | `강의노트-모두연.html`에 섹션 누적 | 이 파일 1부 |
| **② 전달** | 채팅으로 주영님께 강의/답변 | 이 파일 2부 |

원문(수확한 날것)은 둘 다의 재료다. **날것을 그대로 전달하지 않고, 그대로 노트에 넣지도 않는다.**

# 1부 · 기록 (노트에 넣기)

## 1-1. 수확 (LMS에서 본문 가져오기)

- **접속은 `claude-in-chrome`** (실제 Chrome). 인앱 `Claude_Browser`는 로그인 세션이 없어 못 연다. — 과거에 이걸로 헤맴.
- 세션 만료 시 묻지 말고 「다시 로그인」 버튼으로 복구(가역). [[feedback-spum-auto-relogin]]
- **step URL은 순차다.** `.../node-version/{nv}/steps/{stepId}` 에서 stepId를 +1 하면 다음 강. 커리큘럼 패널 클릭이 불안정하면 URL 직접 이동이 빠르다.
- **JS 안에 `setTimeout` sleep을 넣으면 45초 CDP 타임아웃**에 걸린다. `navigate` → 짧은 확인 JS로 나눠서 실행.
- 본문은 `document.querySelector('main').innerText`. 앞의 "학습 인정을 위해…"와 뒤의 "커리큘럼" 이후는 잘라낸다.

## 1-2. 강 수 세기 — ★[프로젝트] 노드 함정

LMS 진도 표시 **「N / N강」은 「프로젝트 제출」 스텝까지 센다.**
→ **`[프로젝트]` 노드는 표시 강 수 − 1 = 실제 강의 수.** (예: 「10/10강」이면 실제 9강 + 제출)
표기는 `(9강 + 프로젝트 제출)`로 갈라 적는다. **강 수만 세고 제목을 대조하지 않으면 없는 누락을 만든다** — 실제로 "누락 5건"을 착각한 적 있음.

## 1-3. 표기 규약 (전 문서 통일)

| 항목 | 규약 |
|---|---|
| 구조 | `모듈{M} · 노드{N}` → 노드 안에서 `{K}강` (각각 1부터 다시 셈) |
| 노드 머리글(coursehead) | `제목 (N강)` — 노드 번호는 badge·id에 있으므로 제목에 넣지 않는다 |
| 강 제목(본문) | `N강 · 제목` |
| 목차 항목 | `N강 제목` (가운뎃점 없음) |
| 배지(.dur) | 모듈1=소요시간(`00:30`) / 온보딩·모듈2·3=강 성격(`이론`·`실습`·`과제`·`정리`). **원자료가 달라 통일하지 않음** |
| 문체 | 평서체(~다). **인용문·원 강의 제목은 원문 유지** |

## 1-4. 분량·강조

- **요약 금지. 내용 전부**를 가독성 있게 담는다. (전달과 정반대 — 노트는 다 남긴다)
- 강조 3색: `.hl` 노란=핵심 · `.hl2` 초록=안전·중요 · `.hl3` 분홍=주의 + 콜아웃.
- 비전공자 눈높이 재서술 허용 — 어려운 대목은 비유·풀어쓰기. **단 사실·수치·용어는 왜곡 금지.** [[feedback-non-major-rewrite]]
- 각 섹션 끝에 `📚 출처` (저자·라이선스·모듈/노드/강).

## 1-5. 정본 분리

- **운영 규정**(출결·훈련장려금·제적·참여규칙) = `운영안내.html`이 정본. 강의노트엔 요지 + 링크만.
- 같은 내용을 두 곳에 두지 않는다. 한쪽이 반드시 낡는다.

## 1-6. 완료 = commit + push

가역이므로 안 묻고 진행 → 사후 통보. push 전 `git pull`(공유 클론). [[feedback-reversible-autonomy]]
KDT_Works 커밋은 스코프 분리(pre-commit 훅) — 강의노트는 `content` 스코프.

# 2부 · 전달 (주영님께 강의)

## 2-0. 네 모드

| 모드 | 트리거 | 표·기호 | 분량 | 끝맺음 |
|---|---|---|---|---|
| **강의톤** | "강의톤으로" | ✅ 씀 | 핵심 분량대로 | 맨 아래 「참고」 블록(표) |
| **음성듣기** | "음성으로", "들을 거라" | ❌ **전부 제거** | 핵심 분량대로 (2-2) | 없음. 마지막 한 문장 정리 |
| **파트강의** | "파트강의로" | 최소 | 파트당 짧게 | `> 💡 이것만 기억:` 한 줄 |
| **답변** | 그냥 질문 | ✅ | 짧게 | — |

공통: 일타강사 톤(고통·상황에서 시작 → 직관 → 용어 이름표 → 일상 비유 → 핵심 반복). 비전공자 재서술 허용, 사실·수치 왜곡 금지. **음성 파일은 만들지 않는다**(주영님이 읽어주기 버튼 사용). [[feedback-lecture-tone-format]] [[feedback-part-lecture-mode]]

## 2-1. ★분량은 원문이 아니라 "핵심"에서 나온다

압축률을 먼저 정하지 않는다. 원문을 세 등급으로 가르고 **살아남은 분량이 길이를 정한다.**

| 등급 | 무엇 | 처리 |
|---|---|---|
| **A · 원형 유지** | 주장·원칙 / 정의하는 용어 / 수치와 그 조건 / 판단 기준·체크리스트 / **"~는 아니다" 오해 차단 단서** | **100%** |
| **B · 압축** | 같은 주장의 반복 설명 / 부품·절차 나열 / 배경 서술 / 두 번째 이후 예시 | **40% — 한 문장으로** |
| **C · 삭제** | LMS UI 문구 / 이미지 라이선스 / "더 읽기" 링크 / 이미 다룬 내용 재요약 | **0%** |

**A를 가르는 실질 기준:** 이 문장이 빠지면 **주영님이 다음 강의나 퀘스트에서 틀리게 되는가?** → 그러면 A. "~는 아니다"는 무조건 A(강의의 핵심 가치).

## 2-2. 공식

```
전달 분량 ≈ ( A + B×0.4 ) × 1.15
```
`×1.15` = 비전공자용 비유·연결어 가산분.

**핵심이 1,800자면 전달도 ~2,000자 — 강제로 자르지 않는다.**

### 검산 밴드 (압축률을 정하는 표가 아니라, 등급 분류가 틀렸는지 점검하는 표)

| 수확한 날것 길이 | 정상 압축률 | 벗어나면 |
|---|---|---|
| ~3,000자 | 40~70% | 20% 밑 → A를 B로 잘못 내림 |
| 3,000~8,000자 | 20~35% | 50% 넘음 → C를 안 버림 |
| 8,000자~ | 12~25% | 대개 실습·코드 강의 — C가 많다 |

### 상한·하한 (모드를 바꾸는 지점)

- **핵심 < 400자** → 강의로 안 만듦. 그냥 답변 3~4문단.
- **핵심 > 3,000자** → 한 번에 넣지 말고 **파트강의 전환**을 먼저 제안.

## 2-3. 캘리브레이션 기준점 (실측)

감이 흔들리면 여기로 돌아온다.

| 강 | 수확 날것 | 통과한 전달 | 압축 | 낭독 |
|---|---|---|---|---|
| 모듈3 노드1 1강 | 7,625자 | **1,780자** | 77% 삭감 | 약 4분 |

> 참고 실패: 같은 1강을 처음에 5,659자(26%만 삭감)로 보냈다가 "너무 길다" 받음.
> 원문을 거의 안 줄이면 전문 낭독이 된다. **날것 6,000~10,000자대 강의의 통과선은 대략 전달 1,800자 / 낭독 4분.**

## 2-4. 전달 전 한 줄 보고

강의(강의톤·음성)를 보내기 직전, 무엇을 버렸는지 한 줄로 먼저 알린다.
```
3강 · 날것 6,382자 → 핵심 1,600자 → 전달 1,850자 (압축 71%)
버린 것: messages 코드블록 상세, assistant 이력 비용 설명 반복
```
이게 있어야 "그거 왜 뺐어?" 하고 되물으면 그 부분만 다시 보낼 수 있다. 조용히 버리지 않는다.
