## [FIX-2026-08-25-1] 새로 쓴 3개 노드(27강)가 화면에 안 뜨던 문제

**증상**
목차에서 `모듈2 노드8`·`모듈2 노드9`·`모듈3 노드1`을 클릭하면 내용이 안 뜨고
**모듈1 노드1(작업대 마련하기)로 튕겨나갔다.** 목차에는 링크가 멀쩡히 보여서 목록만 봐선 정상으로 보였다.
라이브(GitHub Pages) 페이지에서도 동일했다. 즉 **27강(11+7+9)이 사실상 열람 불가** 상태였다.

**원인**
노드를 추가할 때 `섹션 id` · `TOC 링크` · `data-g` 는 넣었으나
**JS의 `names`(제목 표) 와 `order`(진도순 배열) 두 곳에만 세 노드가 누락**됐다.
페이지 로직이 다음과 같아서, order에 없는 노드는 무조건 첫 노드로 치환된다.

```js
function show(node){ if(order.indexOf(node)<0) node='m1n1'; ... }
```

`git log -S`로 확인한 결과 order/names에 `m2n8`이 들어간 커밋은 **한 번도 없었다** —
넣었다 지워진 게 아니라 처음부터 안 들어갔다.
id 개명(cfec45b) 때는 4집합 정합을 검증했지만, **그 이후 추가한 노드에는 검증을 다시 돌리지 않은 것**이 구멍이었다.

**수정**
`names`에 3개 항목, `order` 끝에 3개 키를 진도순으로 추가했다.

```
order: ... 'm2n7','m2n8','m2n9','m3n1'
names: 'm2n8':'AI가 새로 연 곳들'
       'm2n9':'Main Quest — 도구 학습에서 적용 판단으로'
       'm3n1':'거대 언어모델과 프롬프트'
```

**검증**
- 4집합(coursehead id · data-g · order · names) **22개 완전일치**, 차집합 0
- 브라우저 실측: m2n8·m2n9·m3n1 정상 표시, 페이저가 `m2n8 → m2n9 → m3n1` 진도순 연결
- ⚠ 검증 시 **브라우저 캐시 주의** — 고친 직후에도 옛 파일이 떠서 한 번 오판했다. `?v=` 쿼리를 붙여 강제 리로드할 것.

**재발 방지 (노드 추가 시 필수 체크)**
노드를 새로 기록하면 **다섯 곳**을 모두 건드려야 한다. 하나라도 빠지면 조용히 깨진다.

1. `<section class="coursehead" id="{노드id}">` (노드 머리글)
2. 강 섹션 `id="{노드id}-{강번호}"`
3. 목차 `<a class="tochead" href="#{노드id}">` + `<div class="tocgroup" data-g="{노드id}">`
4. **JS `names`에 `'{노드id}':'제목'`**  ← 이번에 빠진 곳
5. **JS `order`에 `'{노드id}'` (진도순 위치)**  ← 이번에 빠진 곳

작업 후 **4집합 일치 검사**를 돌린다(coursehead = data-g = order = names).
