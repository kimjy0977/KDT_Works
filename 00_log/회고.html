트랜스포머 — 정보를 "얼마나"가 아니라 "어떻게 배치하느냐"

배운 것
  • 이미지(CNN)를 다루던 사람과 언어(RNN)를 다루던 사람이 각자 벽에 부딪히다 어텐션(attention)이라는 한 열쇠로 합류한 역사 (「Attention Is All You Need」)
  • 토큰과 컨텍스트 — 트랜스포머가 BERT·GPT·ViT로 퍼지며 세상을 먹은 흐름
  • 긴 문서를 넣을수록 오히려 답이 흐려지는 Lost in the Middle, 그리고 RAG
어려웠던 것 · 역경
  • 어텐션 개념이 처음엔 너무 추상적이었다. 왜 문서를 길게 넣을수록 답이 나빠지는지 직관이 안 잡혀 한참 헤맸다.
한 활동
  • 토큰 예산표와 컨텍스트 설계 캔버스를 직접 만들어봤다(실습).
얻은 것 · 깨달음

정보를 "얼마나 넣느냐"가 아니라, "어떻게 배치하고 무엇에 집중시키느냐"의 문제다.

  • AI에게 일을 시키는 감각이 생겼다. 프롬프트에서 핵심을 앞·뒤에 배치하는 이유를 이제 안다.
2026 · 07 · 23모듈2 · 노드1 · AI는 어떻게 배우나

AI는 마법이 아니다 — 결국 데이터가 전부

배운 것
  • 학습 원리: 회귀 → 분류 → 파인튜닝
  • 데이터를 숫자로 바꾸기, MNIST 손글씨 분류, softmax, 전이학습(파인튜닝)
  • 왜 내 노트북으론 벅찬가 — GPU와 Colab
어려웠던 것 · 역경
  • 수식과 "학습"이라는 개념이 처음엔 손에 안 잡혔다. 직접 돌려보다 연산이 벅차 GPU의 필요성을 몸으로 느꼈다.
한 활동
  • 가장 작은 학습을 코드로 돌려보고, MNIST 분류를 실습했다.
얻은 것 · 깨달음
  • AI가 마법이 아니라 데이터 + 연산의 결과라는 것.
  • 화려한 모델보다 데이터가 결과를 가른다는 깨달음.

조각을 모아 하나의 서비스로 — ORIGIN을 배포하다

배운 것
  • 지금까지 배운 조각(PRD·하네스·세 겹·저장·배포)을 하나로 꿰는 법. 목표는 "완성"이 아니라 핵심 하나를 처음부터 끝까지 굴리는 것.
한 활동
  • ORIGIN — 영감의 계보를 만들었다: 디자인 원류를 모은 아카이브(37작품·AI 큐레이터·타임라인·검색).
  • Next.js + Supabase(Auth·RLS) + Claude API로 짓고 Vercel에 배포, 구글폼 제출까지.
어려웠던 것 · 역경
  • 처음부터 끝까지 굴러가는 서비스를 혼자 완성하는 게 가장 부담이었다.
  • 오픈 리다이렉트(보안)·API 비용(rate limit)·RLS 같은 실전 이슈에 부딪혔고, 감사 지적을 여러 번 시정했다.
얻은 것 · 깨달음
  • 인증·DB·AI를 실제로 붙여 배포까지 해봤다는 자신감.
  • "완성"보다 "굴러가는 첫 조각"의 의미를 몸으로 익혔다.
