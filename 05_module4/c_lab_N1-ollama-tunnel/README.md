# n8n → 내 Ollama 터널

> 모듈4 노드1 **「자동화와 에이전트」** 실습 · 김주영 (아이펠 KDT AI 에이전트 1기)

## 무엇을 푼 문제인가

노드1에서 **n8n**(워크플로 자동화 툴)으로 에이전트를 붙여 보는데, 문제가 하나 있었습니다.

**n8n 은 «클라우드»에서 돌고 Ollama 는 «내 노트북»에서 돕니다.**
클라우드가 `http://localhost:11434` 를 부르면 **그건 n8n 자기 자신의 localhost** 입니다. 내 컴퓨터가 아닙니다.

→ **cloudflared 터널**로 내 Ollama 를 잠깐 인터넷에 올려 두고, 끝나면 내립니다.

## 쓰는 법

```powershell
.\터널-열기.ps1     # 주소가 화면에 뜬다 → n8n 의 Ollama 노드에 넣는다
.\터널-닫기.ps1     # 끝나면 «반드시» 내린다
```

## ★스크립트가 «먼저 확인하는» 것

터널을 여는 것보다 **여는 데 실패했는데 성공한 줄 아는 것**이 더 위험합니다. 그래서 순서를 정해 뒀습니다.

| 순서 | 확인 | 실패하면 |
|---|---|---|
| 0 | **Ollama 가 살아 있나** (`/api/tags` 호출) | 터널을 열지 않고 멈춘다 |
| 1 | cloudflared 실행 파일이 있나 | 설치 경로를 알려 준다 |
| 2 | 터널 주소가 로그에 «실제로» 찍혔나 | 주소 없이 성공이라 하지 않는다 |

닫기 쪽도 **닫은 뒤 Ollama 가 로컬에서 여전히 살아 있는지**를 확인합니다 —
터널만 내려야지 Ollama 까지 죽이면 안 되기 때문입니다.

## ⚠ 주의 — 열어 두면 «누구나» 부를 수 있다

cloudflared 가 주는 주소는 **인증이 없습니다.** 주소를 아는 사람은 내 Ollama 를 그대로 씁니다.

- **쓰는 동안만 열고 끝나면 바로 닫습니다.**
- 주소를 채팅·문서에 남기지 않습니다. 실행할 때마다 **주소가 새로 바뀝니다.**
- 이건 «실습용 임시 통로»이지 배포 방법이 아닙니다.

> 모듈2 노드3에서 정리한 「데이터가 어느 경계를 넘는가」가 여기서 그대로 걸립니다 —
> 로컬 모델을 쓰는 이유가 「데이터가 기기를 안 벗어난다」였는데,
> **터널을 열면 그 이유가 사라집니다.** 열어 둔 동안에는 로컬이 아닙니다.
