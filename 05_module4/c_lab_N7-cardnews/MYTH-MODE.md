## 왜 모드를 나눴나 — 「주제만 바꾸면」 되지 않았다

`topic` 은 자유 입력이라 「피그말리온과 갈라테이아」를 **넣을 수는** 있었습니다.
그런데 **두 군데가 「뉴스」를 전제**하고 있었습니다.

| 어디 | 뉴스 모드 | 신화에 그대로 넣으면 |
|---|---|---|
| [`workflow.py`](workflow.py) 조사 | *「최근 {days}일 안에 «실제로 게시된» 소식」* 을 웹 검색 | 신화엔 **「최근 7일」이 없다** |
| [`images.py`](images.py) 배경 | 모델이 지은 검색어로 Commons **일반 검색** | 명화가 아니라 **아무 사진**이 온다 |

그래서 **조사·검증·이미지 세 곳**을 갈랐습니다.

| | 뉴스 | **신화** |
|---|---|---|
| 후보가 어디서 오나 | 웹 검색 — **무엇이 나올지 모른다** | **색인 982점에서 «세어» 만든다** |
| 모델의 몫 | 찾기 + 요약 | **이야기하기.** 목록·개수는 모델이 만들지 않는다 |
| 검증할 것 | 「이 소식이 사실인가」 | **「이 그림이 정말 그 작가 것인가」** |
| 판본이 갈리면 | 자료 «오류» | **서로 다른 전승** — 어느 판본이 무엇을 말하는지 적는다 |
| 이미지 검색어 | 모델이 만든다 | **색인의 원제·작가** — 모델이 관여하지 않는다 |

## ★후보를 «세어서» 만든다 — 지어낼 자리를 없앤다

두 인물이 **같은 작품에 함께** 등장하면 그건 하나의 이야기입니다. 그걸 색인에서 셉니다.

```
안드로메다 × 페르세우스   7점   렘브란트, 뷔테발, 티치아노
갈라테이아 × 피그말리온   6점   라그레네, 지로데, 브론치노 …
나르키소스 × 에코        4점   푸생, 워터하우스 …
메두사 × 페르세우스       4점   첼리니, 리치 …
```

모델에게는 이 표를 주고 **요약·원전·고를 이유만** 채우게 합니다.
그리고 돌아온 답에서 **작품 수·작가·인물은 색인 값으로 덮어씁니다.**
(CURATOR 의 `autoRepair` 와 같은 원칙 — **조회는 대신 해 주고, 판단은 대신하지 않는다.**)

실제로 12개 후보 전부에 원전이 붙었습니다 — `오비디우스 「변신 이야기」 10권`,
`아폴로도로스 「비블리오테케」 2권`, `아풀레이우스 「황금 당나귀」 4~6권`.
**이야기가 아닌 후보**(에오스 × 호라이 · 셀레네 × 아르테미스)는 `source` 를 **null 로 비워** 뒀습니다.

## ★★이 모드의 핵심 — 「찾았다」와 「맞는 걸 찾았다」는 다르다

원제만으로 Commons 를 찍으면 **PD 이미지는 5/5 찾는데 작가가 다릅니다.**

| 넣은 것 | 색인상 작가 | **Commons 가 준 것** |
|---|---|---|
| Pygmalion and Galatea | 팔코네 | **제롬** |
| The Birth of Venus | **보티첼리** | **카바넬** |
| Narcissus | 카라바조 | **워터하우스** |

**같은 «이야기»의 다른 «그림»입니다.** 그대로 두면 카드에 「보티첼리」라 적고 카바넬 그림을 싣게 됩니다.
5강의 「요청을 보냈다 ≠ 파일이 생겼다」와 **같은 종류의 함정**입니다.

### 그래서 `match` 를 넷으로 나눴다

| 값 | 뜻 | 카드에 적는 것 |
|---|---|---|
| `exact` | 작가가 **일치** | 색인의 작가·연도 |
| `different-artist` | 작가를 풀었는데 **불일치** | Commons 표기만 |
| `unverified` | ★영문 표기를 **못 얻어 대조 자체를 못 함** | Commons 표기만 |
| `none` | 쓸 이미지가 없다 | — |

> ⚠**처음엔 뒤의 둘을 `same-story` 하나로 묶었습니다.** 그랬더니 **제롬 그림을 제대로 찾고도**
> 「다른 화가」로 내려 적었습니다. **「틀렸다」와 「모른다」는 다른 사실입니다.**
> 섞으면 **성능을 스스로 깎아 보고**하게 됩니다.

화면에도 그대로 보입니다 — `작가 확인됨` / `다른 화가` / `대조 못 함` 배지.

## ★그림을 «어떻게» 고르는가 — 세 경로

### ①순위 · Wikidata 작품 항목의 대표 이미지 (P18)

Wikidata 는 **같은 제목이라도 작가마다 별개 항목**을 둡니다.

```
Pygmalion and Galatea →  Q111577849 (브론치노)  P18=Angelo Bronzino 068.jpg
                         Q17305070  (제롬)      P18=Pygmalion and Galatea MET DT1969.jpg
                         Q17315628  (팔코네)    P18=Falconet - Pygmalion & Galatee (1763)
```

**P170(제작자)로 어느 것인지 가르고**, 그 항목의 P18 을 씁니다.

> **왜 이 경로를 1순위로 올렸나 — 실측**
> Commons 전문 검색으로 브론치노를 찾으니 **「제단의 황소만 크게 잡은 부분 컷」** 이 왔습니다.
> 파일명에 `detail` 이 없어 문자열 규칙으로는 못 걸렀습니다.
> 카드 본문은 *「제단과 인물, 배경까지 담아 이야기를 설명하듯 펼친다」* 였는데 **그림엔 황소만 있었습니다.**
> P18 로 바꾸니 **전체 그림**(2684×3500)이 왔습니다.
> ⛔작가를 모르면 이 경로를 **쓰지 않습니다** — 가릴 수가 없으니까요.

### ②순위 · Commons 검색 + 작가 대조
원제+영문작가 → 영문작가 → 원제 순으로 좁혀 가며, **파일 제목과 Artist 표기 둘 다** 봅니다
(Artist 칸이 빈 파일이 많습니다). 큰 그림을 먼저 고르고 `detail|crop|sketch|study` 는 뒤로 밀칩니다.

### ③최후 · 같은 이야기의 다른 그림
`unverified` 또는 `different-artist` 로 **내려 적고** Commons 표기만 씁니다.

**한 카드뉴스 안에서 같은 파일을 두 번 쓰지 않습니다**(`used` 집합).

## 작가명 한국어 → 영문 · 한 칸 차이로 0건이 난다

`wbsearchentities` 는 **라벨 접두 일치**라 정확히 안 맞으면 그냥 «없다»고 합니다.
(CURATOR 의 `label` / `fulltext` 함정과 같은 종류입니다.)

| 넣은 것 | 결과 | 왜 |
|---|---|---|
| `장 레옹 제롬` | **0건** | 라벨이 **`장레옹 제롬`** — 이름만 붙여 씀 |
| `안뇰로 브론치노` | **0건** | **`브론치노`** 만 넣으면 Q7803 |

→ 변형을 **만들어** 넣습니다: ①원문 ②이름만 붙이고 성은 띄움 ③성만.
→ 그리고 결과가 **사람(예술가)인지** 설명으로 거릅니다 — `제롬` 만 넣으면 **아이다호주의 도시**가 1순위입니다.

**1/6 → 4/6** 으로 올랐고, 나머지 둘은 **`unverified` 로 정직하게** 떨어집니다.

## ★고치는 동안 찾은 «앱 전체»의 결함 셋

신화 모드를 붙이다 **뉴스 모드에도 있던 버그**를 셋 찾았습니다. 셋 다 **오류를 하나도 안 내고 조용히** 틀렸습니다.

### ① `extract_json` 이 모델의 답을 통째로 버렸다 — 가장 큰 것

옛 코드는 `[` 를 **`{` 보다 항상 먼저** 찾았습니다. 모델이 앞에 산문을 한 줄 붙이면
본문에서 처음 나오는 `[` — 즉 **객체 «안쪽»의 배열** — 을 통째로 답으로 집었습니다.

```
원전 대조를 마쳤습니다.                        ← 산문
{"status":"need_input","research":{"verified":[ …   ← 이 `[` 를 집었다
```

결과: `status` 가 사라져 **`need_input` 이 `result` 로 바뀌고**, `research`·`editorial` 이 **전부 None**.
**100초짜리 웹 검증이 통째로 사라졌는데 오류는 하나도 안 났습니다.**

→ 두 후보를 **모두** 파 보고 ①규약 필드를 가진 객체 ②그다음 가장 큰 덩어리 순으로 고릅니다.

### ② `normalize` 가 `need_input` 일 때 본문을 버렸다

모델은 **「질문」과 「검증 결과」를 한 응답에** 담아 보냅니다.
질문만 꺼내고 나머지를 버리면 검증이 사라집니다.
(CURATOR 에서 모델이 `action` 과 `finish` 를 «동시에» 내던 것과 **같은 종류**입니다.)

→ `need_input` 에도 `data` 를 **함께** 싣고, 뒤이은 호출이 **빈 값으로 앞의 결과를 지우지 않게** 했습니다.

### ③ Windows 에서 `os.replace` 가 상태 저장을 터뜨렸다

`PermissionError: [WinError 5]` — 목적지 파일을 **다른 프로세스가 잠깐 열고 있으면** 원자적 교체가 거부됩니다.
**락은 한 프로세스 안에서만 통합니다.**
→ 잠깐 기다렸다 다시 겁니다(6회). 그래도 안 되면 **숨기지 않고** 올립니다.

### ④ (신화 모드 자체의 버그) `NFKD` 가 한글을 지웠다

비교용 정규화에 `NFKD` 만 걸었더니 **한글 음절이 자모로 쪼개져**(피 → U+1111 U+1175)
뒤의 `가-힣` 정규식에 **전부 지워졌습니다.** `find_story()` 가 **매번 None** 을 돌려줬습니다.
→ 쪼갠 뒤 **반드시 `NFC` 로 다시 합칩니다.**

## 아직 못 한 것

|---|---|
