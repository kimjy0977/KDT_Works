- provider / 모델 / 실행 환경: **Ollama · qwen3.5:2b**(2.3B · Q8_0 · tools 지원) · Windows 10 · Python 3.13(uv) · 로컬 `http://localhost:11434` · **비용 0**

- 도구 이름과 실제 실행 결과: `read_file` ok · `write_file` 승인 후 ok · `run_command`(unittest) ok · 경로 이탈 `read_file` **ok:false** · 거절 시 `tool_errors` 증가. 근거 = `.harness/runs/*.jsonl`
- 모델 최종 답과 원문·테스트 대조: 읽기 = 「오후 3시 · 책 한 권, 필기구」 **원문 일치**. 코딩 = 변경 전 2/3 FAIL → 변경 후 **3/3 OK**, 테스트 파일 미변경 확인. ⚠ 다만 모델이 「오후 3시」를 **「저녁 시간대」**라 덧붙이고 **「필구구」** 오타를 냈다 — 판정 기준(시각·준비물)으로는 통과이나 **서술 정확도는 별개로 기록**한다
- 실패·한계와 다음 변경: ①**벤치마크 baseline 0/10**(pass 0 · fail 0 · **error 9** · pending 1) — 「모델이 못 풀었다」가 아니라 **도구 계층에서 깨졌다**. 모델이 넘긴 경로 72건 중 **44건이 `/protected` 같은 이식 전 표기**였고 거부됨(`Path leaves workspace` 35회). ②원인 = Windows에서 `Path("/protected").is_absolute()` 가 **False** 라 「원본 절대경로를 워크스페이스로 매핑」하는 분기를 **타지 않는다**. 시스템 프롬프트가 약속한 계약이 **이 플랫폼에서만 구현되지 않은 것**. ③다음 변경 = 그 매핑을 어휘적으로 적용(improved). **회귀 검사 66통과/7실패로 baseline과 동일** — 새로 깨진 것 없음
API 키, 실제 개인 파일, 민감한 출력은 증거에서 제외한다.

## 학생이 추가할 시나리오
내 사용자 이야기의 정상 사례 하나와 실패 사례 하나를 Given(준비) / When(행동) / Then(관찰할 결과)으로 쓴다. 구현이 우연히 돌려준 결과를 그대로 기대값으로 베끼지 않는다.

## 2026-09-08 실행 기록 (1회차)

- **환경** — Windows 10 · Python 3.13(uv) · ollama `qwen3.5:2b`(tools 지원) · harness-lab v4.0.0
- **provider** — **Ollama 로컬**. OpenAI는 **선불 크레딧 없음**으로 이번 회차 제외(D04 참조)
- **A01~A07 = PASS · A09/A10 = DEFERRED · A08/A11/A12 = NOT_RUN**
- 증거 위치 — `../m4n6-하네스랩/.harness/sessions/*.json` · `.harness/runs/*.jsonl`
- 키·개인 자료는 증거에 넣지 않았다(실습 fixture만 사용)

### 이번 실행에서 「지표가 못 잡은 것」

- 모델이 오후 3시를 **"오늘 저녁 시간대"**라고 덧붙였고 **"필구구"** 오타를 냈다.
  7강 기준(시각·준비물이 맞으면 통과)으로는 **PASS**지만, **소형 모델의 서술 정확도 한계**로 기록한다.
- pytest 7건 실패는 **CRLF·경로 등 Windows 환경 차이**다. 하네스 로직 실패와 **구분해서** 적는다.

## 학생이 추가한 시나리오 (D01의 사용자 이야기에서)

### 정상 — 확정된 일과 미정을 «구별»한다
- **Given** 담당자가 적힌 항목과 **아직 안 정해진 항목**이 섞인 회의록(`fixtures/notes/`)
- **When** "확정된 일과 아직 확인이 필요한 일을 나눠서 알려 줘"라고 요청
- **Then** 두 묶음이 **나뉘어** 나오고, 각 항목이 **어느 파일의 어느 문장**에서 왔는지 함께 보인다

### 실패 — 없는 담당자를 «만들지 않는다»
- **Given** 담당자가 **비어 있는** 항목이 있는 회의록
- **When** "이 항목 담당자가 누구야?"라고 요청
- **Then** **사람 이름을 지어내지 않고** 「미정」이라고 표시한다.
  ★이 시나리오는 **정답이 「모른다」인 통제 문항**이다 — 답을 잘 만들수록 실패다

> 두 시나리오 모두 기대 결과를 **원문에서 미리** 정했다.
> 구현이 우연히 돌려준 결과를 기대값으로 베끼지 않았다(7강).
> **상태: NOT_RUN** — 아직 실행하지 않았다.

## A11·A12 실행 요약 (2026-09-08)

| | 통과 | 실패 | 실행 오류 | 미완료 | 도구 오류율 | `Path leaves workspace` |
|---|---|---|---|---|---|---|
| 기준 baseline | **0/10** | 0 | 9 | 1 | 61% | **41** |
| 개선 improved | **0/10** | 2 | 7 | 1 | 48% | **1** |

- **가설의 기전은 확인됐고 성과로는 이어지지 않았다.** 목표 지표는 41→1로 떨어졌지만 점수는 0/10 그대로다.
- 「오류 9」가 「오류 7 + 실패 2」로 **이동**했다 — 두 문제가 **채점까지 도달**했다는 뜻이다.
- ⚠ **`python-sudoku` 회귀**(채점 10/22 → 2/22). 다만 이 문제는 기준에서 **경로 오류가 0건**이라
  내 변경과 인과를 잇기 어렵다. **n=1 변동**으로 «추정»하나 단정하지 않는다 — 반복 3회가 필요하다.
### ★내 하네스로 돌린 세 번째 실행 (`my-baseline`)

`--agent myharness.bench:solve_task` 로 «내 구현»이 반복을 수행했다.

| | 통과 | 실패 | 오류 | 미완료 | 도구 호출 | 도구 오류율 |
|---|---|---|---|---|---|---|
