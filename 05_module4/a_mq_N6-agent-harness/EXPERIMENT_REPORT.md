## 실패 분석과 개선 가설

**대표 실패의 요청 / 관찰한 도구 실행 / 채점 결과**
`extract-paper-metadata-to-json`(easy). 기준 실행에서 **도구 39회 중 33회 실패**,
에이전트가 `Execution failed (ValueError)` 로 종료. 채점기는 정상 실행되어 13검사 중 0통과.

**추정 원인과 이를 뒷받침하는 기록**
세션 기록에서 모델이 도구에 넘긴 경로 **72건 중 44건이 `/protected`, `/app` 같은
「이식 전 원본 표기」**였고 전부 거부됐다(`Path leaves workspace` 41회).
그런데 시스템 프롬프트는 *"original absolute paths map to this workspace
(/app -> app, /protected -> protected …)"* 라고 **약속**한다.
코드를 읽어 보니 `local_agent.relative_path()` 는 `Path.is_absolute()` 가 True 일 때만
그 매핑을 적용하는데, **Windows 에서 `Path("/protected").is_absolute()` 는 False**다(드라이브가 없어서).
⇒ **약속한 계약이 이 플랫폼에서만 구현되지 않았다.**

> **★처음 세운 가설은 틀렸다.** 「지시문이 절대경로를 주는데 도구가 절대경로를 막는다」고 적었다가,
> 실제로 그 경로를 넣어 보니 **네 경우 모두 통과**했다. 재현으로 기각하고 다시 조사했다.

**변경한 한 가지 요소**
`harness_lab/local_agent.py` 의 `relative_path()` 에서 **문서화된 루트로 시작하는
POSIX 표기의 선행 `/` 를 어휘적으로 제거**한다. `..` 검사는 이 변경 «앞»에 있고
`LocalTools.path()` 의 격리·심볼릭·숨김 검사는 그대로 돈다 → **새 접근 권한을 주지 않는다.**
탈출 4종(`/etc/passwd`·상위이동·숨김·폴더 밖 절대경로)이 여전히 거부됨을 확인했다.

**예상한 영향** — 도구 거부가 줄고, 에이전트가 문제를 «시작»은 할 수 있게 된다.

**실제 변화**

*좋아진 문제*
- `extract-paper-metadata-to-json` — 도구 오류 **33/39 → 10/19**
- `implement-lz77-file-compressor` — 3/11 → **1/7**
- `implement-go-board-analyzer` — 6/8 → 5/12
- `advanced-json-to-rfc4180-csv-converter` · `detect-corrupted-blockchain-transaction`
  — 에이전트 상태가 `failed` → **`completed`**. 즉 **채점까지 도달**했다(그래서 「오류 9」가
  「오류 7 + 실패 2」로 «이동»했다). 채점 통과 수는 그대로.

*나빠진 문제*
- `python-sudoku-solver-backtracking` — 채점 통과 **10/22 → 2/22** ★회귀
- `implement-depgraph-dependency-resolver` — 도구 오류 8/11 → **16/26**
- `recover-encrypted-db-credentials` — 4/5 → 7/9
- `implement-nonogram-puzzle-solver` — 기준은 4/13 통과, 개선은 **결과 없음(미완료)**

> **★sudoku 회귀는 내 변경 탓이라고 보기 어렵다.** 이 문제는 **기준 실행에서 경로 오류가 0건**이었다.
> 경로 매핑을 고친 변경이 영향을 줄 경로가 없다. **n=1 인 소형 모델의 실행 간 변동**으로 본다.
> 다만 «변동이라고 단정»할 근거도 없다 — 반복 3회가 필요하다.

**동일하게 유지한 조건** — 문제 목록·revision·manifest·제공자·모델·반복 수·모든 한도.
**바뀐 조건** — 하네스 소스 1곳(`code_sha256` 만 다르다). 그리고 **실행 시각**(회피 불가).

**결론**
1. **가설의 기전은 확인됐다.** 목표 지표(`Path leaves workspace`)가 **41 → 1**.
2. **성과로는 이어지지 않았다.** 점수 0/10 그대로. 도구 오류율도 61% → **47%**로 **여전히 절반 가까이**다.
3. ⇒ **경로는 병목의 «전부»가 아니었다.** 남은 43건의 도구 오류를 다음 실험의 재료로 삼는다.
4. 이 결과를 «이 변경이 무용하다»로 읽지 않는다 — 채점까지 도달한 문제가 2개 생겼다.

  ★이번에 고친 결함 자체가 **Windows 에서만 드러나는 것**이었다 —
