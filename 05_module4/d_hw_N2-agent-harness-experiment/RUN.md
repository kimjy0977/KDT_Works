# 실행 절차

> **§0~7 = 1차 실험** (작은 저장소 `fixtures/` · 7파일 · 3과업 × 2조건)
> **§8 = 2차 실험** (큰 저장소 `fixtures-large/` · 282파일 · 2과업 × 3조건)
> 지표와 사전 판정식은 두 실험이 **같다**.

각 조건 3회 반복이면 총 18회지만, **먼저 6회(3과업 × 2조건 × 1회)를 돌려 절차를 확인**하고
이상이 없으면 2·3회차를 이어서 돌린다.

---

## 0. 매 실행 전 — 저장소를 초기 상태로

fixture는 T1·T2 과업에서 **읽기만** 하므로 보통 바뀌지 않는다.
다만 에이전트가 파일을 고쳤을 가능성이 있으니 매번 확인한다.

```bash
cd 05_module4/d_hw_N2-agent-harness-experiment
git status --short fixtures/
```

바뀐 것이 있으면 되돌린다.

```bash
git checkout -- fixtures/
```

---

## 1. 세션 규칙

- **과업 1개 = 새 세션 1개.** 앞 과업의 문맥이 넘어가면 비교가 깨진다
- 작업 폴더는 `fixtures/repo/`
- 모델·설정은 6회 내내 **같게**

---

## 2. 조건 A (대조) — 아무것도 넣지 않는다

`fixtures/prompts.md`의 문장을 **그대로** 붙여 넣는다. 앞뒤에 아무것도 더하지 않는다.

```
이 저장소에 핸드오프 문서가 있는지 확인하고, 있으면 경로를 알려 줘.
```

---

## 3. 조건 B (처치) — 경로 목록을 「먼저」 붙인다

`fixtures/tree.txt`의 내용을 **그대로** 붙이고, 빈 줄 하나 뒤에 같은 과업 문장을 붙인다.

```
README.md
docs/INSTALL.md
docs/OPERATIONS.md
docs/internal/ops/handoff/HANDOFF-tutor.md
services/api/config/settings.toml
services/worker/config/settings.toml
src/config/settings.toml

이 저장소에 핸드오프 문서가 있는지 확인하고, 있으면 경로를 알려 줘.
```

> **주의** — 목록에 설명을 붙이지 않는다. "이건 파일 목록이야" 같은 문장을 더하면
> **조작 항목이 「경로 목록」이 아니라 「목록 + 안내 문장」**이 된다.

---

## 4. 무엇을 세나

실행이 끝나면 화면을 보고 네 가지를 센다.

| 지표 | 세는 법 | 주의 |
|---|---|---|
| **존재 부정 오류** | "없습니다 / 존재하지 않습니다 / 찾을 수 없습니다"로 **단정**한 횟수 중, **실제로는 있는** 것 | "못 찾겠는데 더 찾아볼까요"는 **단정이 아니다** → 0 |
| **탐색 호출** | `Glob`·`Grep`·`Bash(find/ls/tree)` 호출 **횟수** | `Read`는 세지 않는다(탐색이 아니라 열람) |
| **정답** | 최종 답이 `prompts.md`의 정답과 같은 뜻인가 | 표현이 달라도 **뜻이 같으면 O** |
| **턴** | 도구 호출을 포함한 왕복 수 | |

시간은 대략(초 단위)이면 된다.

`results/template.md`를 복사해 **시행 1건당 파일 하나**로 남긴다.

## 8. 2차 실험 — 큰 저장소 (fixtures-large/) · 6회

### 8-1. 저장소를 만든다

1차와 달리 저장소를 **커밋해 두지 않는다.** 실행 전에 스크립트로 만든다.

```bash
python3 fixtures-large/make.py
```

난수를 쓰지 않으므로 **누가 돌려도 같은 282파일**이 나온다.
`tree.txt` 도 이때 함께 갱신된다 — 목록과 실제 저장소가 어긋날 수 없다.

출력이 아래와 같아야 한다.

```
파일 282개 · 최대 깊이 7
정답 파일: docs/internal/team/ops/handoff/2026/HANDOFF-tutor.md (깊이 7)
settings.toml: 5개
handoff 이름 포함: 4개
tree.txt 282줄
```

**매 시행 전에 다시 돌린다.** `make.py` 는 기존 `repo/` 를 지우고 새로 만들기 때문에
앞 시행이 파일을 고쳤더라도 초기 상태로 돌아간다.

### 8-2. 조건이 셋이다

| 조건 | 과업 문장 앞에 붙이는 것 |
|---|---|
| **A** 대조 | 없음 |
| **B** 처치 · 목록 | `fixtures-large/tree.txt` 282줄 + 빈 줄 하나 |
| **C** 처치 · 지시 | `탐색 범위를 임의로 좁히지 마라. 저장소 전체를 확인해라.` + 빈 줄 하나 |

**비교는 A vs B, A vs C 두 쌍으로만 한다.** B vs C 는 두 항목이 동시에 다르므로 비교하지 않는다.

과업 문장은 `fixtures-large/prompts.md` 에서 **글자 그대로** 가져온다.

### 8-3. 무엇을 세나

1차와 **같은 지표·같은 판정식**을 쓴다(§4·README §5). 결과를 본 뒤 기준을 바꾸지 않는다.

다만 2차에서 **지표가 놓친 실패 유형**이 하나 드러났다(README §9 관찰 ④) —
「전수 열거했다」면서 **총계를 틀리는** 집계 오류다. 3차에서는 이것도 센다.

### 8-4. 기록

파일 이름 앞에 `L-` 를 붙인다. `summarize.py` 가 이 접두사로 두 실험을 갈라 집계한다.

```
results/L-T1-A-1.md    2차 · L-T1 · 조건 A · 1회차
results/L-T1-B-1.md
results/L-T1-C-1.md
results/L-T2-A-1.md
results/L-T2-B-1.md
results/L-T2-C-1.md
```

### 8-5. 집계

```bash
python3 results/summarize.py
```

두 실험의 표와, **A vs B · A vs C 두 쌍의 사전 판정식 대조**를 함께 출력한다.
