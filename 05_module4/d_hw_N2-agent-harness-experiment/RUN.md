# 실행 절차 — 6회

각 조건 3회 반복이면 총 18회지만, **먼저 6회(3과업 × 2조건 × 1회)를 돌려 절차를 확인**하고
이상이 없으면 2·3회차를 이어서 돌린다.

---

## 0. 매 실행 전 — 저장소를 초기 상태로

fixture는 T1·T2 과업에서 **읽기만** 하므로 보통 바뀌지 않는다.
다만 에이전트가 파일을 고쳤을 가능성이 있으니 매번 확인한다.

```bash
cd 05_module4/d_hw_N2-agent-harness-experiment
git status --short fixtures/
```

바뀐 것이 있으면 되돌린다.

```bash
git checkout -- fixtures/
```

---

## 1. 세션 규칙

- **과업 1개 = 새 세션 1개.** 앞 과업의 문맥이 넘어가면 비교가 깨진다
- 작업 폴더는 `fixtures/repo/`
- 모델·설정은 6회 내내 **같게**

---

## 2. 조건 A (대조) — 아무것도 넣지 않는다

`fixtures/prompts.md`의 문장을 **그대로** 붙여 넣는다. 앞뒤에 아무것도 더하지 않는다.

```
이 저장소에 핸드오프 문서가 있는지 확인하고, 있으면 경로를 알려 줘.
```

---

## 3. 조건 B (처치) — 경로 목록을 「먼저」 붙인다

`fixtures/tree.txt`의 내용을 **그대로** 붙이고, 빈 줄 하나 뒤에 같은 과업 문장을 붙인다.

```
README.md
docs/INSTALL.md
docs/OPERATIONS.md
docs/internal/ops/handoff/HANDOFF-tutor.md
services/api/config/settings.toml
services/worker/config/settings.toml
src/config/settings.toml

이 저장소에 핸드오프 문서가 있는지 확인하고, 있으면 경로를 알려 줘.
```

> **주의** — 목록에 설명을 붙이지 않는다. "이건 파일 목록이야" 같은 문장을 더하면
> **조작 항목이 「경로 목록」이 아니라 「목록 + 안내 문장」**이 된다.

---

## 4. 무엇을 세나

실행이 끝나면 화면을 보고 네 가지를 센다.

| 지표 | 세는 법 | 주의 |
|---|---|---|
| **존재 부정 오류** | "없습니다 / 존재하지 않습니다 / 찾을 수 없습니다"로 **단정**한 횟수 중, **실제로는 있는** 것 | "못 찾겠는데 더 찾아볼까요"는 **단정이 아니다** → 0 |
| **탐색 호출** | `Glob`·`Grep`·`Bash(find/ls/tree)` 호출 **횟수** | `Read`는 세지 않는다(탐색이 아니라 열람) |
| **정답** | 최종 답이 `prompts.md`의 정답과 같은 뜻인가 | 표현이 달라도 **뜻이 같으면 O** |
| **턴** | 도구 호출을 포함한 왕복 수 | |

시간은 대략(초 단위)이면 된다.

## 5. 기록

`results/template.md`를 복사해 **시행 1건당 파일 하나**로 남긴다.

```
results/T1-A-1.md      T1 과업 · 조건 A · 1회차
results/T1-B-1.md
results/T2-A-1.md
...
```

**화면 원문(최종 답변과 도구 호출 목록)도 함께 붙인다.** 숫자만 남기면 나중에 재검토가 안 된다.
