# DESIGN — 디자인을 «하기 전에» 정한 것

> 2026-09-10 · 김주영
> ⛔**이 문서가 먼저다.** 색을 칠하고 나서 대비를 재면 이미 다 칠해 놓고 되돌려야 한다.
> 아래는 «정할 것을 나열»한 것이 아니라 **정한 결과**다. 근거와 실측값을 같이 적는다.

---

## 0. 왜 다시 하는가 — 1차가 «디자인»이 아니었던 이유

1차(2026-09-10 오전)에는 폭·터치 44px·포커스 링만 고쳤다. **그건 접근성이지 디자인이 아니다.**
그래서 화면이 여전히 「텍스트를 박스에 넣은 것」으로 보였다. 재 보니 원인이 셋이었다.

| 원인 | 실측 |
|---|---|
| **서체를 «안 정했다»** | 시스템 폰트(맑은 고딕)에 기대고 있었다. 어떤 화면이든 「기본값」으로 보인다 |
| **팔레트가 «없었다»** | 갈색 하나 + 의미색. 위계를 만들 중립 계조가 없었다 |
| **타입 스케일이 «뒤집혀» 있었다** | 제목 15px < 본문 16px |

⇒ **먼저 정하고 나서 그린다.**

## 1. 제품 정의

| | |
|---|---|
| **무엇** | 그림 한 점의 «제목과 작가»로 등재 레코드 초안을 만들어 **사람의 승인 앞에** 놓는 도구 |
| **누구** | ①아카이브 운영자(주) ②소규모 아카이브·전시 기획자 ③채점자·동료 |
| **맥락** | 데스크톱 브라우저. **한 번에 한 점.** 급하지 않고 «정확해야» 한다 |
| **성격** | 소비형이 아니라 **작업형(work tool)**. 화려함보다 **판단을 돕는 것**이 우선 |

---

## 2. 디자인 원칙 — 넷

1. **사실이 먼저 보인다.** 장식이 데이터를 가리지 않는다.
2. **모르는 것은 «모른다»고 보인다.** 빈 칸은 비워 두고 그렇게 적는다.
   `unverified`·`different-artist` 를 한 색으로 합치지 않는다.
3. **되돌리기 어려운 자리는 «눈에 띈다».** 승인 지점은 화면에서 가장 강한 요소다.
4. **화면이 코드와 같은 말을 쓴다.** 단계 이름은 `PHASES`, 숫자는 «세어서» 넣는다.

## 3. 정보 구조 (IA)

★**앱 셸** — 「머리 + 탭 + 가운데 한 줄」은 «문서»의 틀이다. 작업 도구는
**목록 ↔ 상세가 한 화면에** 있어야 한다. (LangSmith · Linear · Sentry 가 쓰는 형태)

```
┌──────────────┬──────────────────────────────────────┐
│ CURATOR      │                                      │
│              │                                      │
│ 작업          │        작업 영역 (고른 실행)           │
│  1 실행       │                                      │
│  2 트레이스   │   히어로 / 새 실행 / 트레이스 /        │
│  3 승인       │   승인 / 결과 / 평가 / 문서           │
│  4 결과       │                                      │
│              │                                      │
│ 근거          │                                      │
│  5 평가       │                                      │
│  · 문서       │                                      │
│              │                                      │
│ 실습          │                                      │
│  ↗ 카드뉴스   │                                      │
│              │                                      │
│ ★실행 기록    │   ← «상주»한다. 전에는 ①실행 탭       │
│  · Venus     │      «맨 아래»에 표로 묻혀 있었다.     │
│  · Sabine    │      다른 실행으로 옮기려면 탭을        │
│  · …         │      되돌아가 스크롤해야 했다.         │
└──────────────┴──────────────────────────────────────┘
```

**왜 이렇게 갈랐나**
- **작업**(1~4) — 한 실행을 «따라가는» 순서. 번호가 있으므로 숫자로 표시
- **근거**(5·문서) — 실행과 무관한 «참고». 작업과 섞으면 순서가 헷갈린다
- **실습** — 형제 폴더(c_lab)로 나가는 문. 점선으로 «다른 곳»임을 표시
- **실행 기록** — 목록. 상세(오른쪽)와 짝을 이룬다

깊이는 **2단을 넘지 않는다.** 뒤로 가기가 필요한 흐름을 만들지 않는다.

## 4. 핵심 플로우

```
제목·작가 입력 → 실행 → [에이전트 루프 5~13스텝] → ★사람 승인 → 레코드 확정 → 가져가기
                                    ↓ 게이트 차단
                              «막힌 이유»를 보여 주고 멈춘다
```

**사람이 끼어드는 지점은 하나** — 승인. 그 앞은 자동, 그 뒤는 사람 몫.
⇒ 화면에서 **승인만 1차 강조**를 받는다. 나머지는 2차 이하.

## 5. 디자인 토큰

### 5-1. 색 — 갤러리 중립 + 아카이브 강조

**근거** — ui-ux-pro-max `--domain color` 1순위 **Museum/Gallery**(갤러리 블랙 + 흰 여백).
아카이브·전시 도구의 표준 팔레트다. 여기에 기존 브랜드 강조색(따뜻한 갈색)을 얹는다.
**중립을 갤러리 계조로 바꾸는 것이 핵심** — 위계를 만들 계조가 없던 게 1차의 병이었다.

| 토큰 | 라이트 | 다크 | 쓰는 곳 |
|---|---|---|---|
| `--bg` | `#FAFAFA` | `#0C0C0E` | 페이지 바닥 |
| `--surface` | `#FFFFFF` | `#161618` | 카드 |
| `--surface-2` | `#F4F4F5` | `#1F1F23` | 입력칸·표 머리·안쪽 블록 |
| `--ink` | `#18181B` | `#F4F4F5` | 본문 |
| `--dim` | `#52525B` | `#A1A1AA` | 보조 글자 |
| `--faint` | `#71717A` | `#8A8A93` | 흐린 글자 |
| `--line` | `#E4E4E7` | `#27272A` | **장식 구분선** |
| `--control` | `#8A8A93` | `#71717A` | ★**컨트롤 경계**(입력·버튼) |
| `--accent` | `#8A5A20` | `#D8B47A` | 강조·링크·현재 위치 |
| `--ok` / `--warn` / `--bad` | `#15803D` / `#A16207` / `#B91C1C` | `#4ADE80` / `#FBBF24` / `#F87171` | 의미색 |

### ★대비를 «계산해서» 정했다 (WCAG 2.1)

| | 라이트 | 다크 | 기준 |
|---|---:|---:|---|
| 본문 | **17.72:1** | **16.44:1** | 4.5 |
| 보조 글자 | 7.73:1 | 7.05:1 | 4.5 |
| 흐린 글자 | 4.83:1 | 5.28:1 | 4.5 |
| 강조색 글자 | 5.89:1 | 9.23:1 | 4.5 |
| 강조 버튼 (글자 on 배경) | 5.89:1 | 9.23:1 | 4.5 |
| 성공 / 경고 / 오류 | 5.02 / 4.92 / 6.47 | 10.37 / 10.83 / 6.53 | 4.5 |
| **컨트롤 경계** | **3.42:1** | **3.74:1** | **3.0** (1.4.11) |

> ⚠**처음 고른 경계색이 미달했다.** `#D4D4D8` → **1.48:1**.
> 눈에는 「연한 회색 테두리」로 멀쩡해 보였다. **계산하지 않았으면 못 잡았다.**
> `#8A8A93`(3.42:1)로 바꿨다.
>
> ⚠그리고 **검사기가 두 가지를 섞고 있었다** — WCAG 1.4.11 의 3:1 은 «컨트롤»의 경계에 걸리지
> **장식 구분선에는 걸리지 않는다.** 그래서 토큰을 `--line`(장식)과 `--control`(컨트롤)로 **갈랐다**.

### 5-2. 타이포

**근거** — `--domain typography` 1순위 **Korean Modern / Noto Sans KR**.
⇒ **1차의 가장 큰 병이 이것이었다.** 시스템 폰트에 기대면 어떤 화면도 「기본값」으로 보인다.

| | 값 |
|---|---|
| 서체 | `Noto Sans KR` 300·400·500·700 (Google Fonts) → 폴백 `-apple-system, Segoe UI, Malgun Gothic` |
| 스케일 | **12 · 13 · 14 · 15 · 17 · 20 · 26 · 34** (1.2~1.25 비율) |
| 본문 | 15px / 행간 1.7 / 자간 -0.003em |
| 제목 | h1 26~34 · h2 20 · h3 15 — **제목이 본문보다 크다**(1차엔 뒤집혀 있었다) |
| 웨이트 | 본문 400 · 라벨 500 · 제목 700 |
| 숫자 | `font-variant-numeric: tabular-nums` — 표·타이머가 흔들리지 않게 |
| **한국어 줄바꿈** | `word-break: keep-all` — 없으면 **어절 중간에서 끊긴다**(실측) |
| 줄 길이 | 본문 최대 **68ch**, 리드 62ch |

### 5-3. 공간 — 4의 배수

`4 · 8 · 12 · 16 · 24 · 32 · 48 · 64`
컨테이너 `max-width: 1200px` · 좌우 여백 `clamp(16px, 3vw, 32px)`

### 5-4. 반경 · 층(elevation)

| | 값 | 쓰는 곳 |
|---|---|---|
| 반경 | 6 / 10 / 14 / 20 | 배지·입력·카드·히어로 |
| **층 0** | 그림자 없음 + 1px 경계 | 안쪽 블록 |
| **층 1** | `0 1px 2px` | 보통 카드 |
| **층 2** | `0 1px 3px, 0 8px 24px` | 주 작업 카드 |
| **층 3** | `0 2px 8px, 0 20px 48px` | 모달 |

⛔층을 **네 단계 넘게 만들지 않는다.** 다섯 개가 넘으면 어느 것이 위인지 사람이 못 읽는다.

### 5-5. 모션 — 절제(dial 3/10)

| | 값 |
|---|---|
| 짧은 상태 변화 | **160ms** `cubic-bezier(.2,.8,.2,1)` |
| 펼침·접힘 | **200ms** |
| 누름 | `translateY(1px)`, 100ms |
| 비동기 대기 | skeleton shimmer 1.5s (⛔스피너 대신) |
| **금지** | 장식용 애니메이션 · `width/height` 애니메이션 · 500ms 초과 |
| **필수** | `prefers-reduced-motion: reduce` 존중 |

### 5-6. 아이콘 체계

⛔**이모지를 아이콘으로 쓰지 않는다.** 글꼴에 따라 모양이 달라지고 토큰으로 색을 못 준다.

| | 값 |
|---|---|
| 형태 | **인라인 SVG** (외부 요청 0) · `stroke` 방식 · `fill="none"` |
| 선 굵기 | **2** (24×24 viewBox 기준) · 브랜드 마크만 1.8 |
| 크기 | 사이드바 19 · 본문 15 · 배지 13 — **세 단만** 쓴다 |
| 색 | `currentColor` — 부모의 색을 따른다. 아이콘에 색을 «박지» 않는다 |
| 끝·모서리 | `stroke-linecap="round"` `stroke-linejoin="round"` |
| 접근성 | 장식이면 `aria-hidden="true"`, 뜻이 있으면 옆에 **글자를 둔다** |

★**숫자 배지는 아이콘 대신 «숫자»를 쓴다.** 사이드바의 1·2·3·4·5 가 그것 —
단계에 순서가 있으므로 그림보다 숫자가 정확하다.

### 5-7. z 층위 — «정해» 둔다

`--z-base:0` · `--z-sticky:10` · `--z-side:20` · `--z-overlay:40` · `--z-modal:60`

⛔**안 정하면 `9999` 가 늘어난다.** 새 층이 필요하면 이 다섯 중 하나를 고르거나
여기 «한 곳»에 추가한다. 컴포넌트에 숫자를 직접 쓰지 않는다.

## 6. 컴포넌트 인벤토리 — 상태까지 «정한다»

| 컴포넌트 | 상태 |
|---|---|
| 버튼 (primary/ghost/small) | default · hover · active · **focus-visible** · disabled |
| 입력 (text/select/textarea) | default · hover · focus · **error** · readonly |
| 카드 | 보통 · **primary**(주 작업) · quiet(참고) · hero |
| 탭 | default · hover · **current**(밑줄) |
| 배지 | ok · warn · bad · neutral |
| 표 | 머리 고정 · 행 hover · 가로 스크롤 |
| 접기(details) | 닫힘 · 열림 (화살표 회전) |
| 상태 타일 | 보통 · ok · warn · bad |
| 워터폴 막대 | model · tool · **실패(bad)** |
| 단계 칩 | 대기 · 진행 · 완료 |

**빈 상태 / 로딩 / 오류**
- 빈 상태 — 「없음」이라고 **적는다.** 빈 화면을 두지 않는다
- 로딩 — 300ms 넘으면 skeleton. **경과 시간**을 같이 보인다
- 오류 — 원인 + **「다음에 할 수 있는 것」**을 같이 적는다

## 7. 레이아웃 · 반응형

| 폭 | 배치 |
|---|---|
| ~1023 | **1단** — 사이드바가 위로 접힌다(가로 스크롤 아님, 세로로 쌓임) |
| **1024~** | **셸 2단** — 사이드바 264px 고정(sticky, 전체 높이) + 작업 영역 |
| **1180~** | 작업 영역 안이 다시 **2단** (`.grid2` — 1.25fr / 0.75fr) |
| 1200~ | 작업 영역 여백 확대 |

**격자 규칙**
- `.grid2 { align-items: start }` — ★카드가 «자기 높이»만큼만 차지한다.
  `stretch` 면 짧은 카드가 늘어나 **빈 칸이 생긴다**(실측으로 겪었다).
- 한쪽에 카드가 몰리면 **격자를 고치지 말고 «정보 구조»를 고친다** —
  「실행하려면 정할 것」 셋이 세 카드로 흩어져 있어 왼쪽 아래가 비었고,
  한 카드로 모으니 사라졌다.

★**DOM 순서 = 화면 순서.** CSS 로만 자리를 옮기면 키보드·스크린리더는 다른 순서로 읽는다.

## 8. 접근성 기준 — WCAG 2.1 AA

- 대비 본문 4.5:1 · **컨트롤 경계 3:1** (위 표에서 실측 확인)
- 터치 타깃 **44×44** 이상
- `:focus-visible` 링 2px + offset 2px — ⛔절대 `outline:none` 안 함
- 색으로만 뜻을 전하지 않는다 — 배지에 **글자**를 같이 둔다
- `prefers-reduced-motion` · `prefers-color-scheme` 존중
- 모든 입력에 `<label>` 또는 `aria-label`

---

## 9. 콘텐츠 원칙 (보이스 · 톤)

- **결론부터.** 제목이 무엇인지 말하고 설명은 뒤에
- 상태를 **사람이 읽는 말**로 — `awaiting_approval` → 「승인 대기」
- **숫자는 세어서** 넣는다. 손으로 적으면 어긋난다(「도구 6종」이 8종이었다)
- **못 한 것은 못 했다고** 적는다 — ❌·⚠ 를 숨기지 않는다
- 강조 표기 — `«»` 는 **개념 강조**, `★` 는 **놓치면 안 되는 것**, `⛔` 는 **하지 말 것**

---

## 10. 다크모드 전략

- 토큰만 바꾼다. **구조·간격은 동일**
- 다크는 «반전»이 아니다 — 채도를 낮추고 배경을 순검정(#000)으로 두지 않는다(`#0C0C0E`)
- 대비를 **따로 계산**했다(위 표 오른쪽 열)
- `prefers-color-scheme` 자동. 강제 토글은 두지 않는다(설정이 늘면 검증할 조합도 는다)

## 11. 성능 예산

| | 기준 | 지금 |
|---|---|---|
| **서체 요청** | `<link preconnect>` + `display=swap` | ✅ ⛔CSS `@import` 는 «렌더를 막는다» — CSS 를 다 받은 뒤에야 폰트 요청이 시작된다 |
| 외부 요청 | 서체 **한 곳**(Google Fonts)만 | ✅ 그 외 CDN·추적기 0 |
| JS | 프레임워크 **없음** · 순수 ESM | ✅ `ui.js` + `agent.js` + `tools.js` + `llm.js` |
| CLS | 이미지·컨테이너에 크기 예약 | 카드 이미지 `max-height` 지정 |
| 애니메이션 | `transform`·`opacity` 만 | ✅ `width/height` 애니메이션 금지 |
| 데이터 | 색인 1.2MB 는 **필요할 때만** 받는다 | 평가 탭 진입 시 로드 |

| 변형 | 한 단어 형용사 | `.card.primary` `.card.quiet` |
| **상태** | ★**`s-` 접두** | `.dot.s-ok` `.dot.s-warn` |
| 토큰 | `--역할-변형` | `--surface-2` `--accent-bg` |

> ⚠**★제네릭 이름은 반드시 부딪힌다.** 실측 2026-09-10 —
> 상태 점에 `.warn` 을 붙였더니 **경고 «상자»용 `.warn`**(`padding:14px 18px`)을 먹어
> **7px 점이 큰 갈색 타원**이 됐다.
> ⇒ ①상태는 `s-` 접두 ②상자 규칙은 요소를 한정(`p.warn, div.warn`).

## 13. 이 문서를 지키는 방법

- 토큰은 `app/style.css` 맨 위 `:root` **한 곳**에만 정의한다
- 값을 컴포넌트에 직접 쓰지 않는다 (`#8A5A20` 이 아니라 `var(--accent)`)
- 색을 더할 일이 생기면 **먼저 대비를 잰다** — `scratchpad/contrast.py` 와 같은 방식
- 화면에 숫자를 적을 일이 생기면 **센다** — `tools/audit.py` §D 가 검사한다
