## D-01. 실행 엔진 — 로컬 Ollama 를 «기본»으로

| | |
|---|---|
| **고른 것** | 로컬 **Ollama**(`qwen3.5:2b`) 기본 + Anthropic·OpenAI **BYO 키** + **데모 재생** |
| 버린 것 | 내 API 키를 서버에 넣고 누구나 쓰게 하기 |
| **왜** | 배포가 **공개 URL**이다. 키를 넣으면 **누구나 내 계정으로 태울 수 있다.** 호출 상한·레이트리밋을 따로 짜야 하는데, 그건 이 과제의 본론이 아니다 |
| 대가 | 채점자가 **키 없이 «실제 실행»은 못 한다** → **데모 재생 모드**로 메운다 |
| 되돌리려면 | `app/llm.js` 의 `BACKENDS` 에 서버 프록시 백엔드를 하나 더 얹으면 된다 |

## D-02. ★네이티브 tool-calling API 를 «안» 쓴다 — JSON 행동 프로토콜

| | |
|---|---|
| **고른 것** | 모델이 `{"thought":…,"action":{"tool":…,"args":…}}` 를 뱉게 하고 **우리가 판다** |
| 버린 것 | Anthropic/OpenAI 의 `tools` 파라미터, Ollama 의 `tools` 필드 |
| **왜 ①** | 백엔드마다 스키마가 달라 **«세팅을 바꿔 가며 비교»하는 이 과제의 평가가 «불가능»해진다** |
| **왜 ②** | 로컬 소형 모델은 tool-calling 지원이 들쭉날쭉하다. **무료로 돌 수 있는 길을 막고 싶지 않았다** |
| **왜 ③** | 트레이스에 **모델이 «실제로 뱉은 문자열»**이 남아 실패 원인이 보인다 |
| 대가 | **파싱 실패를 우리가 처리해야 한다.** 실제로 필요했다 → `normalize()` (D-07) |

## D-03. 빌드 단계 없음 — 순수 ES 모듈

| | |
|---|---|
| **고른 것** | `<script type="module">` + 순수 `.js`. **번들러·트랜스파일러 없음** |
| 버린 것 | TypeScript + Vite (모듈3 MQ3 에서 쓴 방식) |
| **왜** | GitHub Pages 에 **소스 그대로** 올라가 채점자가 **읽는 코드 = 도는 코드**다. 빌드 산출물과 소스가 갈리지 않는다. 툴체인 고장 위험도 0 |
| 대가 | 타입 검사가 없다 → **시험 84항목**으로 메운다(`verify-*.mjs`) |

## D-04. ★쓰기 도구를 «모델에게 보여 주지 않는다»

| | |
|---|---|
| **고른 것** | 방어 **세 겹** — ①도구 카탈로그에서 제외 ②`callTool` 이 `writes:true` 를 승인 없이 거부 ③도구 자신이 다시 검사 |
| 버린 것 | 프롬프트로 *"emit_record 를 부르지 마세요"* 라고만 적기 |
| **왜** | 실측했다 — **소형 모델은 「반드시」라고 써도 지시를 흘린다**(EVALUATION §6-③). **런타임이 검사하지 않으면 규칙이 아니다** |

## D-05. 안전 게이트 — «모델의 말»이 아니라 «트레이스»를 본다

| | |
|---|---|
| **고른 것** | `finish` 가 오면 루프가 **스스로** 검사: 라이선스가 PD/CC 로 확인됐나 · `archive_search` **호출이 트레이스에 있나** |
| 버린 것 | 모델이 `"dedupeChecked": true` 라고 답한 것을 믿기 |
| **왜** | 모델이 *"확인했습니다"* 라고 «말»할 수 있다. **호출한 «기록»은 지어낼 수 없다** |

## D-06. `autoRepair` — 조회는 대신 해 주고 «판단»은 안 한다

| | |
|---|---|
| **고른 것** | 모델이 중복 확인을 건너뛰면 **시스템이 `archive_search` 를 한 번 대신** 한다(읽기 전용·8ms) |
| **안 한 것** | **라이선스는 자동 보정하지 않는다** |
| **왜** | 중복 확인은 **«조회»** 다 — 답이 정해져 있다. 라이선스는 **«판단»** 이다 — PD 인지 CC 인지 restricted 인지 사람이 봐야 한다 |
| 효과 | 게이트 통과 **13% → 25%**, 차단 14 → 9건 (EVALUATION §5) |

## D-07. 형식이 어긋난 응답을 «받아 준다»

| | |
|---|---|
| **고른 것** | `normalize()` — `{"action":{"tool":"finish"}}`, `{"tool":…,"args":…}` 를 우리 형식으로 맞춘다 |
| 버린 것 | 형식이 틀리면 실패 처리 |
| **왜** | 실측 — `qwen3.5:2b` 가 `finish` 를 **«도구»로 취급**했고, 파서가 안 받자 **5회 같은 응답을 반복**했다. **모델의 해석이 부자연스럽지도 않다**(도구 목록만 준 상태니까). **받아 주는 쪽이 너그러운 편이 훨씬 튼튼하다** |

## D-08. 반복 호출을 «관찰로» 되먹인다

| | |
|---|---|
| **고른 것** | 같은 (도구, 인자) 2회째 → **관찰로 경고** → 3회째 중단 |
| 버린 것 | 즉시 중단 / 그냥 두기 |
| **왜** | 즉시 중단하면 **스스로 빠져나올 기회**를 뺏는다. 그냥 두면 예산만 태운다. **반복분은 실제 API 로 나가지 않는다**(시험으로 확인) |

## D-09. ★평가 — «천장»을 먼저 재고 구간을 갈랐다

## D-20 · 「등재」가 아카이브에 «쓰지 않는다» — 그리고 화면이 그렇게 말하게 했다

**고른 것** — 결과물은 **등재 레코드 JSON**까지. 아카이브 반영은 사람이 한다.

**왜 ①** — 아카이브는 **별도로 배포된 다른 프로젝트**다. 내 프로젝트 경계 밖이고 **읽기만** 한다.
**왜 ②** — 더 중요한 쪽. 이 페이지는 **공개 배포본**이다.
여기에 실제 쓰기 권한을 넣으면 **링크를 아는 누구나 남의 아카이브에 쓸 수 있다.**
「승인 게이트」를 세 겹으로 만들어 놓고 **정작 쓰기 권한을 공개 화면에 두는 것은 앞뒤가 안 맞는다.**

**★그런데 화면이 그 사실을 «안 말하고» 있었다 (2026-09-10 발견)**
버튼은 「승인하고 등재」, 결과는 「등재 레코드」, 경고는 「승인 없이는 아무것도 등재되지 않습니다」.
**읽는 사람은 아카이브에 들어간다고 이해한다.** PRD 는 「레코드 «초안» JSON」이라 적었는데
**화면이 그 단서를 안 옮겼다.** 이 프로젝트가 내내 말한
**「요청을 보냈다 ≠ 파일이 생겼다」와 같은 종류의 어긋남**이다.

→ 고친 것: 버튼을 **「승인하고 레코드 확정」**으로, 승인·결과 화면과 소개·README 에
**「공개 아카이브에 자동으로 써 넣지 않습니다 — 넣는 것은 사람이 합니다」**를 명시.
결과 탭에는 **「지금 이 레코드는 브라우저에만 있습니다」**까지 적었다.

**버린 것** — 「어차피 데모니까 넘어가도 된다」.
**데모라서 더 정확해야 한다.** 채점자가 보는 것이 화면뿐이기 때문이다.
