## 1. 문제 정의

### 1-1. 어떤 반복 업무인가

나는 신화 명화 아카이브([MYTH GALLERY](https://myth-gallery.vercel.app/ko/))를 운영한다.
현재 **982점**이 올라가 있고, 작품마다 **기본정보 · 해설 · 신화배경 · 감상포인트** 네 단이 붙는다.

작품 한 점을 새로 올리는 일은 매번 **같은 순서의 같은 작업**이다.

| # | 하는 일 | 지금 걸리는 시간 |
|---|---|---|
| 1 | 원제·작가를 확정하고 표기를 통일한다 | 5~10분 |
| 2 | 제작연도·매체·크기·소장처를 찾아 대조한다 (출처 2~3곳) | 15~25분 |
| 3 | **퍼블릭 도메인인지 판정한다** — 아니면 올릴 수 없다 | 5~15분 |
| 4 | 어느 신화의 어느 장면인지, 등장인물이 누구인지 확정한다 | 10~20분 |
| 5 | 한국어 해설 네 단을 쓴다 | 30~60분 |
| 6 | 기존 인물·사조 페이지와 연결한다 (중복 등재 확인 포함) | 5~10분 |
| | **합계** | **70~140분 / 점** |

**1~4와 6은 «찾고 대조하는» 일**이라 자동화 대상이고, **5는 초안까지만** 자동화하고 사람이 고친다.
**3은 되돌리기 어려운 판단**이라 반드시 사람이 확인해야 한다 — 저작권이 살아 있는 작품을
공개 아카이브에 올리면 그건 «수정»으로 끝나는 실수가 아니다.

### 1-2. 입력과 결과물

| | 내용 |
|---|---|
| **입력** | 작품 **제목**(원제 또는 한국어) + **작가명**. 선택적으로 Wikimedia Commons 파일명 |
| **결과물** | ① 등재 레코드 초안 **JSON**(원제·작가·연도·매체·소장처·사조·등장인물·해설 4단) ② **근거 링크 목록**(각 필드가 어느 출처에서 왔는지) ③ **라이선스 판정 배지** ④ **중복 등재 경고** |
| **완료의 정의** | 사람이 승인 버튼을 눌러 JSON이 내려받아진 순간. **에이전트가 «끝냈다»고 말하는 것은 완료가 아니다** |

### 1-3. 왜 챗봇이 아니라 에이전트여야 하는가

**실측했다.** 아카이브 작품 20점을 층화 표본으로 뽑아 Wikidata에서 찾아 봤다 (2026-09-09).

| 방식 | 적중 |
|---|---|
| 한국어 제목으로 그냥 검색 | **0 / 20 (0%)** |
| 원제(영문)로 한 번 검색 | **6 / 20 (30%)** |
| + 괄호·부제를 떼고 재질의 | **12 / 20 (60%)** |
| + 작가로 스코프를 좁혀 폴백 | **19 / 20 (95%)** ※ |

> ※ 마지막 줄은 **«작가 엔티티를 찾아 근거를 붙일 수 있었다»는 뜻**이지
> «작품을 정확히 동정했다»는 뜻이 아니다. 본 평가에서는 **작품 동정 성공률로 다시 잰다.**

**한 번 물어보고 끝나는 구조로는 30%다.** 관찰하고 → 실패를 판정하고 → 질의를 바꿔 다시 시도하는
**루프가 있어야 나머지 60%가 열린다.** 이 과제가 에이전트여야 하는 이유가 여기 있다.

## 3. 워크플로 설계

### 3-1. W1 · 등재 (주 목표)

| 단계 | **에이전트가 «판단»할 일** | **도구가 «처리»할 일** |
|---|---|---|
| **P1 계획** | 입력에서 제목/작가를 가르고 **질의 후보를 몇 개 어떤 순서로 낼지** 정한다 | — |
| **P2 동정** | 후보 중 **어느 것이 이 작품인가** — 작가가 맞나, 유형이 작품인가. 아니면 **다음 질의를 고른다** | `wd_search` |
| **P2′ 폴백** | 전부 실패했다고 **판정**하고 작가 스코프로 내려간다 | `wd_sparql` |
| **P3 사실** | 여러 값이 충돌할 때 **무엇을 채택하고 무엇을 «유보»로 남길지** | `wd_entity` |
| **P4 라이선스** | PD / CC / **불명**을 판정. **불명이면 진행을 멈춘다** | `commons_file` |
| **P5 대조** | **이미 등재된 작품인가**, 어느 인물·사조에 붙일 것인가 | `archive_search` |
| **P6 초안** | 한국어 4단 해설 작성. **모르는 것은 «자료 없음»으로 남긴다** | — (모델) |
| **★P7 승인** | — | **사람** |
| **P8 커밋** | — | `emit_record` (승인 게이트 뒤) |

### 3-2. W2 · 전시 큐레이션 (시간이 남으면)

주제 한 줄 → `archive_search` 로 후보 30점 → **선정 12점**(신화·사조·매체 분산 판단) →
동선 3구획 배치 → 벽면 텍스트 초안 → **P7 승인** → `emit_exhibition`.

> **우선순위:** W1을 **끝까지(배포·평가 포함)** 먼저 완성한다. W2는 **W1의 루프·도구·승인·트레이스를
> 그대로 재사용**하므로 추가 비용이 작다. 그러나 **W1이 완성되기 전에는 시작하지 않는다.**

## 4. 도구 계획

**전부 API 키가 필요 없고 CORS가 열려 있다** (2026-09-09 실제 요청으로 확인 — `access-control-allow-origin: *`).

| 도구 | 입력 스키마 | 출력 | 실패 처리 | 권한 |
|---|---|---|---|---|
| `wd_search` | `{query:str, lang:"ko"\|"en", limit:int≤5}` | `[{qid,label,description}]` | 빈 결과 → **다음 질의 변형**(소진까지) · 429/5xx → **지수 백오프 2회** → 실패 표시 | 읽기 |
| `wd_entity` | `{qid:str, props:str[]}` | `{P170,P571,P186,P276,P195,P135,P180…}` | qid 무효 → **P2로 되돌림** | 읽기 |
| `wd_sparql` | `{artistQid:str, limit:int≤20}` | `[{qid,label,inception,material}]` | 20초 타임아웃 → 폴백 실패 | 읽기 · **질의 템플릿 고정**(자유 SPARQL 금지) |
| `commons_file` | `{title:str}` 또는 `{search:str}` | `{imageUrl,license,author,credit}` | 파일 없음 → 라이선스 **«불명»** → **P4에서 중단** | 읽기 |
| `archive_search` | `{q:str, topK:int≤8}` | `[{slug,title,url,section,score}]` | — (로컬 2,978청크) | 읽기 |
| **`emit_record`** | `{record:object}` | 등재 JSON | 스키마 미달 → 거부 | **쓰기 — ★승인 없이는 호출 불가** |

**설명(description) 작성 원칙** — 에이전트가 «언제» 쓸지 알 수 있게 쓴다.
예: `wd_sparql` → *"제목 검색이 모두 실패했을 때만 쓴다. 작가 Q번호로 그 작가의 작품 목록을 받아
제목을 대조하기 위한 마지막 수단이다. 제목 검색을 시도하지 않고 먼저 호출하지 말 것."*

**권한 최소화** — 읽기 도구 5개는 공개 데이터만 본다. **쓰기 도구는 `emit_record` 하나뿐**이고
**P7 승인 상태가 아니면 런타임이 호출 자체를 거부**한다(모델의 선의에 기대지 않는다).

## 6. 핵심 기능(MVP)과 화면 구성

### MVP — 반드시 있어야 하는 것

1. 입력 폼(제목·작가) + 실행 시작
2. **에이전트 루프** — 계획 → 도구 호출 → 관찰 → 다음 행동
3. **도구 6종** 연결 (스키마·설명·실패 규칙 포함)
4. **실행 트레이스 패널** — 스텝별 도구명·인자·결과 요약·소요 ms·토큰
5. **P7 승인 화면** — 필드별 값·출처·수정 입력
6. **결과물 실물** — 등재 JSON 미리보기 + 내려받기
7. **종료 조건** — 최대 스텝 12 · 도구 호출 20 · 180초
8. **이어하기** — 실행 상태를 저장해 새로고침·중단 후 재개
9. **3모드 실행** — 데모 재생 / 로컬 Ollama / BYO 키

### 화면

| 화면 | 내용 |
|---|---|
| **① 실행** | 입력 폼 · 모드 선택 · 진행 스텝 표시 |
| **② 트레이스** | 스텝 타임라인 · 도구 호출 상세 · **단계별 소요시간 막대(병목)** · 누적 토큰/비용 |
| **③ 승인** | 필드 표(값·출처·신뢰도) · 라이선스 배지 · 중복 경고 · 수정/승인/거부 |
| **④ 결과** | 등재 JSON · 내려받기 · 해설 4단 미리보기 |
| **⑤ 평가** | 평가 세트 결과표 · 세팅별 비교 · 실패 사례 분류 |

## 7. 실험 & 평가 계획

**평가 세트** — 아카이브에서 **40점 층화 표본**(6신화 비율대로). **정답은 이미 있다** —
`works.json`(작가·사조·등장인물)과 `meta` 청크(원제·연도·매체·소장처)가 그대로 정답지다.
**이게 이 과제의 가장 큰 자산이다. 정확도를 «느낌»이 아니라 «숫자»로 잰다.**

| 지표 | 정의 |
|---|---|
| **동정 정확도** | 고른 Wikidata 엔티티가 **실제로 그 작품인가** |
| **필드 정확도** | 작가 / 연도 / 사조 / 등장인물 각각의 일치율 |
| **완료율** | 사람 개입 없이 **P7까지** 도달한 비율 |
| **안전** | 라이선스 불명 건이 **등재로 넘어가지 않은** 비율 (목표 100%) |
| **효율** | 평균 스텝 · 도구 호출 수 · 소요시간 · 토큰 |

**세팅 변화 표** — ①단일 질의 ②재질의 ③+작가 폴백 ④도구 설명 강화 ⑤모델 교체.
**실패 분류** — 잘못된 엔티티 선택 / 중간 포기 / 환각 / 불필요한 반복 / 도구 오류.
