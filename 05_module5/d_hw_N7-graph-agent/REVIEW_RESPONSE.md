## B-2 ★제일 큰 것 — 경로 재현율은 «채점 결함»이었습니다

> 「한 번 풀어 보시면 둘 중 하나가 나올 텐데, 어느 쪽이든 리포트가 강해집니다.」

**첫 번째가 나왔습니다.** 원인이 하나 더 있었습니다.

```python
st["evidence"] = uniq[:60]              # ← 답변 프롬프트용으로 자른 것을
pr = score_path(ctx, rec["evidence"])   # ← ★채점에도 그대로 썼다
```

먼저 얼마나 잘렸는지 셌습니다.

```
gather 45건 중 60 상한에 걸린 것   ★39건 (87%)
실제 개수   최소 0 · 중앙 192 · 최대 207
```

⇒ 기대 삼중항이 **61번째 뒤에 있으면 «그래프에 있어도» 실패**로 찍혔습니다.
`evidence_all`(자르지 않은 전체)을 따로 두고 **채점만 그것으로** 바꿔 다시 돌렸습니다.

| 구분 | 제출본 | 상한 푼 뒤 |
|---|---|---|
| 1홉 | 50.0% | **100.0%** (+50.0%p) |
| 2홉 | 58.3% | **100.0%** (+41.7%p) |
| 4홉 | 45.8% | **100.0%** (+54.2%p) |

### ★그런데 「올랐다」로 끝내면 안 될 것 같아 대조를 했습니다

근거 192개는 **엣지 661개의 29%** 입니다 — 「뭘 넣어도 통과」일 수 있습니다.
그래서 **그래프에서 무작위로 192개**를 뽑아 같은 채점기에 넣어 봤습니다(20회).

```
무작위 192 삼중항   29.2%     ← 지표는 여전히 «가른다»
실제 근거 192개    100.0%
```

⇒ **100% 는 진짜입니다.** 답변 프롬프트는 여전히 `[:60]` → 앞 40개만 쓰므로
**토큰 비용은 안 늘었습니다.** 바뀐 것은 «채점»뿐입니다.

### ★제가 배운 것이 결과보다 큽니다

저는 45~58% 라는 값에 **「같은 가치에 다른 물음으로 닿아도 답은 맞다」**는 설명을 붙여
REPORT §6 에 실었습니다. 그럴듯했고 **틀렸습니다.**

제 작업 규칙에 **「측정값이 예상과 어긋나면 «설명»하지 말고 «확인»한다」**고 적어 두고도,
어긋난 값에 **이야기를 붙여 제출**했습니다. 코드를 읽어 주지 않으셨으면 못 찾았을 자리입니다.

**남은 숙제가 바뀌었습니다** — 이제 이 지표가 **너무 쉽습니다.**
「근거 안에 있나」는 **「의도한 추론을 했나」와 다른 질문**입니다.
다음에 재야 할 것은 **답변이 «자기가 탄 경로»를 말하게 하고 그것을 대조**하는 쪽입니다.

## B-3 거절 3건 중 2건은 «구조적»이 아니었습니다

제출본은 거절을 구조적이라고만 적었는데, 재 보니 다릅니다.

```
거절-01   근거 ★0개       → 탐색 층. 가져올 것이 없어 «구조적으로» 거절
거절-02   근거 150개 받고  → ★생성 층. 모델이 「이 중엔 제작비가 없다」고 판단
거절-03   근거 117개 받고  → ★생성 층. 〃
```

3/3 으로 안정적이지만 **보증의 세기가 다릅니다** — 거절-01 은 **코드가 보장**하고,
거절-02·03 은 **프롬프트가 부탁**하는 것입니다. §2 에 그대로 적었습니다.

## B-4 「홉 수」는 문항 난이도지 실행 설정이 아닙니다
