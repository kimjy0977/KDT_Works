# 시네필 위키 — 지식 그래프와 GraphRAG

**모듈5 노드6 「영화 추천 에이전트 만들기 - GraphRAG」 · 2026-09-18**

한국어 위키백과 한국영화 문서 **80건**에서 관계를 삼중항으로 뽑아 지식 그래프를 세우고,
LangGraph 로 질문 유형에 따라 **지역·경로·전역** 세 갈래를 골라 답하는 에이전트.

> 노드가 정한 목표 — *「성능의 천장까지 올리지 않는다.
> **무엇이 부족한지 숫자로 말할 수 있게 되는 것**이 목표」*

---

## 한 줄

**벡터·키워드 검색은 «질문이 온 뒤에» 연결을 만들려 해서 멀티홉에서 무너진다.
GraphRAG 는 «문서를 넣는 시점에» 미리 연결을 만들어 둔다.**

「기생충에 출연한 배우의 **다른 작품**」은 기생충 문서에도, 송강호 문서에도
**그대로 적혀 있지 않다.** 두 문서를 이어 붙여야 나온다.

## 결과

### ① 벽 — BM25 베이스라인 (7강 · 그래프를 만들기 «전»에 쟀다)

**정답을 담은 문서를 후보 안에 데려왔는가** (Recall@k)

| | 단순 (1홉) | 추천 (2홉) | 격차 |
|---|---:|---:|---:|
| k=3 | 53.3% | 28.7% | 24.6%p |
| **k=5** | **86.7%** | **51.8%** | **34.9%p** |
| k=10 | 93.3% | 73.3% | 20.0%p |
| k=20 | 100.0% | 85.7% | 14.3%p |

★**어느 k 에서도 멀티홉이 뒤진다.** 그리고 **k 를 키우는 것은 해법이 아니다** —
k=20 은 문서 80건 중 **20건을 통째로 문맥창에 퍼넣는** 것이다.
전역 질문 2건은 이 잣대로 **잴 수조차 없다**(정답 «문서»가 없다).

### ② 색인 커버리지 (9강)

골든셋 정답 삼중항 **39개 중 38개 = 97.4%** 가 그래프에 있다.
없는 것은 `(송강호, WON_AWARD, 대종상)` 하나.

### ③ GraphRAG 답변 (14강 · **3회** 측정)

| | 값 |
|---|---|
| 경로 적절성 | **13/15 = 86.7%** (3회 동일) |
| 답변 적절성 | 80.0% · 73.3% · 80.0% → **평균 77.8% · 폭 6.7%p** |
| **안정성** | **13/15** — 3회 모두 같은 결과 |

★**한 번만 쟀으면 86.7% 라고 적었을 것이다.** 실제로 그 값이 한 번 나왔다.
세 번 재니 73.3~80.0% 였다. **평균이 아니라 폭을 봐야 한다.**

## ★무엇이 부족한가 — 숫자로 지목한다

실패를 **색인·검색·생성**으로 가른다. 세 자리는 고치는 사람이 다르다.

```
색인 실패   정답 삼중항이 «그래프에 없다»      → 8·9강(추출·보강)
검색 실패   그래프엔 있는데 «근거로 안 왔다»   → 12강(탐색)
생성 실패   근거엔 왔는데 «답에 안 썼다»       → 프롬프트·모델
```

| 문항 | 상태 | 원인 |
|---|---|---|
| **추천-06** | 3회 모두 실패 | **검색** — 2홉인데 탐색 폭이 `sorted(mids)[:30]` 이라 시상식이 밀렸다 |
| **추천-09** | 3회 모두 실패 | **구조** — `chain` 이 **3홉**인데 `two_hop` 은 2홉까지다 |
| 추천-04 · 추천-12 | 1/3 통과 | **분산** — 답변 모델이 흔들린다 (`temperature=0` 인데도) |

★**고치지 않았다.** 노드가 「천장까지 올리지 않는다」고 했고,
원인을 지목하는 데까지가 오늘 목표다. 올리는 일은 남겨 둔다.

## ★오늘 내가 틀린 것 «다섯» — 이게 배운 것이다

### 1. 한 줄 고쳐 12개를 살렸더니 다른 곳에서 7개가 잘못 생겼다

기생충 문서에서 `ACTED_IN` 이 **0개**였다. 캐스팅이 문장이 아니라
`송강호: 김기택 역 - 설명` **목록**이라 「출연했다」가 없었다.
프롬프트에 *「배우: 배역 역 목록도 출연이다」* 를 넣으니 **0 → 12개**.

그런데 「한국영화아카데미」 문서의 **졸업생 필모그래피**
(`봉준호 : 플란다스의 개, 살인의 추억 …`)까지 출연으로 읽혀
**「봉준호–봉준호 4편」** 같은 조합이 생겼다.

⇒ 고친 자리와 깨진 자리가 **다른 파일**이라 바로 안 보였다.

### 2. ★자(尺)가 틀려 있었다

전역-15 를 **정확히 답했는데 17%로 찍혔다.** 채점기가
`reference` 의 「봉준호–송강호」를 en dash 로 안 쪼개서 통째로 찾았고,
답변은 「봉준호 감독과 송강호 배우가」라 문자열이 안 맞았다.

고친 뒤 **총점은 8/15 로 같았는데 «어느 문항이 맞았나»가 바뀌었다.**
전역-15 17%→89%, 추천-08 33%→67%, 추천-05 40%→20%, 추천-10 42%→17%.

⇒ **같은 53.3% 가 «다른 셋»이었다.** 점수가 같다고 같은 상태가 아니다.

### 3. ★파이프라인이 비결정적이었다

`two_hop` 에 `list(set)[:30]` 이 있었다. 같은 질의를 3번 돌려
해시가 **3번 다 달랐다**. 그래서 추천-07 이 회차마다 67% ↔ 0% 로 뒤집혔다.

**답변 규칙을 고쳐서 깨진 줄 알았다.** 원인은 거기가 아니었다.
`sorted()` 로 고정하니 3회 동일. ⇒ **재현되지 않으면 «무엇을 고쳤는지»도 말할 수 없다.**

---

### 4. ★자가 «또» 틀렸다 — context recall 이 괄호에 먹혔다

basic 92% vs graph **33%** 가 나왔다. GraphRAG 가 근거를 «덜» 가져온다는 뜻인데
말이 안 됐다. 원인은 내 정규화 함수였다.

```
key('(봉준호, DIRECTED, 기생충 (영화))')  ->  ')'
```

`key()` 는 「기생충 (영화)」를 「기생충」으로 만들려고 괄호 안을 지운다.
그런데 GraphRAG 의 근거는 `(s, r, o)` 형식이라 **삼중항 전체가 괄호로 먹혔다.**
basic 은 «원문»이라 멀쩡했다 — **두 방식에 다른 자를 댄 것이다.**

고치니 **92% vs 100%** 로 뒤집혔다. 처음 값을 그대로 믿었으면
「GraphRAG 는 근거를 못 가져온다」는 **정반대 결론**을 적었을 것이다.

### 5. ★그림이 통계보다 먼저 잡았다

4강이 *"시각화는 «디버깅 도구»입니다. 추출이 잘못되면 통계보다 그림에서 먼저
티가 납니다"* 라고 했는데 건너뛰었다. 나중에 그려 보니 노드 두 개에
**동그란 고리(self-loop)** 가 있었다.

```
(아카데미 작품상, WON_AWARD, 아카데미 작품상)   ← 분류 보강이 만든 것
(황금종려상,   WON_AWARD, 황금종려상)          ← 같은 원인
(기생충 (영화), ACTED_IN, 기생충 (영화))        ← 추출 오류
```

「아카데미 작품상」 문서의 분류에 「아카데미 작품상 수상작」이 있어
`(X, WON_AWARD, X)` 가 됐다. **삼중항 2,103개 안에서는 안 보였다.**

그리고 타입을 붙이니 방향이 뒤집힌 것도 하나 나왔다 —
`(버닝 (2018년 영화), DIRECTED, 이창동)`. 4강이 말한 「타입으로 걸러낸다」가 이것이다.
