## 4. ★채점기 자체의 결함 — 32건 중 2건은 아무도 못 맞힌다

### 11강의 「채점기 자기 검증」은 왜 못 잡았나
```python
score_turn(expect, expect["reference"], expect["tools"], expect["action"])
                                        ^^^^^^^^^^^^^^  ^^^^^^^^^^^^^^^^
                                        정답 그대로      정답 그대로
```
**「모범 답안 문장이 must/forbid 를 만족하는가」**는 본다.
그런데 실제 채점에는 **action 판정 로직**이 한 겹 더 있고,
**그렇게 행동했을 때 그 로직이 기대값을 돌려주는지**는 아무도 안 본다.
⇒ **검사는 있었는데 «보는 자리»가 한 겹 얕았다.**

## 5. 어려운 케이스 72건 — 6강의 관찰이 재현됐다 (하나만 빼고)

```
[확신도 평균]                   [6강이 본 것]
분류체계밖  0.50 → 12/12 범위밖   같음
극단단답   0.62 →  9/12 범위밖   같음
문맥의존   0.85 →  7/9 처리해버림  ★6강은 0.3까지 떨어졌다
경계모호   0.92 →  이관 0건 (0%)  같음
```
★**문맥의존만 다르다.** 큰 모델은 「내가 앞 대화를 모른다」를 아는데 **2B 는 모른다.**

★그리고 **임계값 0.5 는 이 모델에서 작동하지 않는다** — 0.5 이하에선 이관이 **0건**이다.
6강이 남긴 숙제(「확신도 «자체»를 검증해야 한다」)를 검증해 보니 **신호 구실을 못 한다.**

## 6. ★오늘 배운 것 — 「무엇을 세는지」

```
①  eval 은 올랐는데 outscope 가 무너졌다   → 한쪽만 재면 속는다
②  총점은 같은데 위험한 실패 수가 다르다     → 한 숫자로 합치면 안 보인다
```

### 가설이 두 번 기각됐다
| 가설 | 검증 |
|---|---|
| ① 범인은 「OTHER 억제 문단」 | ❌ v3 로 분리하니 outscope 동일(57.6%) |
| ② 범인은 「보내지 말라」는 금지 표현 | ❌ v4 로 바꾸니 1건만 회복(60.6%) |
| ③ **범인은 「판단법」을 정교하게 준 것** | ✅ 샌 6건이 SHIPPING 이 아니라 ORDER_PLACE·PRODUCT_INFO 로 |

⇒ **판단 기준을 정교하게 줄수록 모델은 «그 기준 안에서» 답을 찾으려 한다.**
  **「해당 없음」이 밀려난다.**

### 두 효과가 «가산적»이다
```
fewshot   eval +0.111 · outscope +6.0%p     ← 거래가 «없다»
v4        eval +0.185 · outscope −18.2%p    ← 거래다
합치면     eval +0.260 · outscope −12.1%p    (−18.2 + 6.0 = −12.2 ≈ −12.1)
```
fewshot 의 **+6%p** 는 **두 조건 모두에서 같은 크기**였다(78.8→84.8 · 60.6→66.7).

### ★★검사기를 만들면 그 검사기도 틀린다 — 오늘만 네 번
```
점검기   열거를 두 겹 하고 「0건」 보고       범위를 잘못 잡음
감사기   is_external_channel 고정 → 오탐    전제를 잘못 잡음
리포트   re.M 누락 → 「못 읽음」을 「없음」으로  실패와 부재를 같은 칸에
★폴백    결론 문구를 «미리 써 둠»            ★출력이 실측을 «가림»
```
네 번째가 제일 위험하다 — `retry: 3` 이 화면에 찍혀 있는데
바로 아래 줄에 **「재시도 0회로 바로 폴백했다」**가 있었다.
⇒ 결론 문구를 **`stat` 에서 «읽어» 만들게** 고쳤다. 고치자 13.8초 → **6.9초**(절반).
