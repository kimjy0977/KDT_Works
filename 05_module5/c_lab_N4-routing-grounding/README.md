## 2-3. ★★「폭」을 재 봤다 — 만영님 관찰이 **내 환경에서 그대로** 나왔다

> 「같은 설정으로 다시 재니 **최대 12.8%p** 까지 흔들렸습니다. `temperature=0` 인데도 그렇습니다.」
> 「라우터는 **한 배치 안에서는 폭 0.000** 으로 재현되는데
>  **배치를 달리하면 0.942~0.971** 로 움직입니다.」 — 김만영님(C4) 회고

`01_ollama_router.py --repeat 3` 을 붙여 **같은 프로세스 안에서 3회** 쟀다:

```
2B + v4 + hard-fewshot     macro F1  0.835 · 0.835 · 0.835    ★폭 0.000
                           정확도    0.817 · 0.817 · 0.817    ★폭 0.000
```

⇒ ★**완전히 재현된다.** 만영님이 본 것과 «같다».

### ★배치를 «달리해도» 같았다 — 그런데 «설정마다» 다르다

같은 설정을 **별도 프로세스**로 한 번 더 쟀다. 그리고 로그 열 개를 전수 대조했다:

| 설정 | 관측 | 값 | 폭 |
|---|---|---|---|
| **v4 + hard-fewshot** | **4회**(19·24×3·28) | 0.835 · 0.835 · 0.835 · 0.835 | **0.000** |
| v3 (지침만) | 2회(05·16) | 0.738 → **0.741** | 0.003 |
| v4 (지침만) | 2회(06·16) | 0.741 → **0.738** | 0.003 |

⇒ ★★**같은 모델인데 «어떤 설정은» 흔들리고 «어떤 설정은» 안 흔들린다.**
  v3·v4 는 **값이 서로 맞바뀌었고**, v4+hard-fewshot 은 **네 번 다 소수점까지 같다.**

⇒ **[추정]** 예시가 붙은 지침(2,062자)이 지침만 쓴 것(1,628자)보다
  모델 출력을 «더 고정»시키는 것으로 보인다. 다만 2회 vs 4회라 표본이 다르다 —
  단정하지 않는다.

⇒ ★**실용적 결론: 폭은 «비교하려는 그 설정에서» 재야 한다.**
  한 설정에서 폭을 구해 모든 비교에 쓰면 안 된다. 여기서 실제로 달랐다.

⇒ 그 기준으로 내 주장들을 판정하면:
```
hard-fewshot 효과  +0.019   그 설정의 폭 0.000    ★주장할 수 있다
7B 지침 효과       +0.014   〃                   ★주장할 수 있다
v3 vs v4          +0.003   그 설정의 폭 0.003    ⛔ 주장할 수 없다 (실제로 뒤집혔다)
```

## 3. ② 1턴 답변

| 설정 | 통과 | ANSWER | ASK | ★위험한 실패 | tools 미호출 | 가드레일 차단 |
|---|---|---|---|---|---|---|
| 2단계 · 적극 조회 | **6/32 (18.8%)** | 6/22 | 0/8 | **8** | 14 | 2 |
| 2단계 · 덜 조회 | **6/32 (18.8%)** | 4/22 | 2/8 | **6** | 19 | 3 |

★**총점이 같다.** ANSWER 에서 잃은 2건을 ASK 에서 되찾았다.
⇒ **점수로는 고를 수 없다.** 11강 기준(위험한 실패 = ASK→ANSWER)으로 보면 **「덜 조회」가 낫다.**

### ★★그리고 모델을 2B → 7B 로 키워도 «총점이 안 올랐다»

| 모델 | 통과 | ANSWER | ASK | OUT_OF_SCOPE |
|---|---|---|---|---|
| qwen3.5:2b | 6/32 (18.8%) | 4/22 | 2/8 | 0/2 |
| **qwen2.5:7b** | **6/32 (18.8%)** | 5/22 | 1/8 | **1/2** |

①에서는 같은 교체가 **0.556 → 0.911 (+0.355)** 였다. ②는 **±0** 이다.
**안을 열어 보면 «개선은 있었다»:**
```
             2B    7B
tools 미호출   19 →  9    ★절반으로 줄었다 (도구를 훨씬 잘 부른다)
must 누락     19 → 15
OUT_OF_SCOPE  0 →  1    ★맞히기 시작했다
```

⇒ ★★**부분 개선이 «점수로 안 나타난다».**
②는 **action · tools · must · forbid 4축을 «전부» 통과해야 1점**이라,
셋을 고쳐도 하나가 틀리면 **0점 그대로**다.

```
① 분류    한 번의 판단           → 모델 능력이 «직결»된다
② 답변    4축 전부 통과해야 1점    → 부분 개선이 «묻힌다»
```

★이것이 ①과 ②가 **같은 파이프라인인데 다르게 움직이는** 이유다.
지표를 고를 때 **「채점이 전부-아니면-무인가」**를 먼저 봐야 한다.

## 4-2. ★12강이 든 한계 ① — 엔티티 링킹을 고쳤다

12강 본문: 「`search_product` 는 **토큰 겹침**으로만 찾습니다.
"요일팬티 세트"가 "브라·팬티 세트"와 **동점**이 되는 문제가 남아 있어요.」

**코드를 읽으니 원인이 한 줄에 있다:**
```python
n = sum(1 for t in qt if t in flat or any(t in x or x in t for x in nt))
                                          ^^^^^^^^^^^^^^^^^^^^^^^^
# 「한쪽이 다른 쪽을 품기만 해도」 «완전 일치»와 같은 1점
```
그래서 「팬티」가 「요일팬티」와도 「브라·팬티」와도 만점이 되고 **동점이 된다.**

**고친 방식 — 가중 점수 (`13_search_v2.py`)**
```
완전 일치(토큰이 같다)        1.0
포함(한쪽이 다른 쪽을 품는다)   0.5   ← 여기가 원래 1.0 이었다
분모 = (질의어 토큰 수 + 상품명 토큰 수) / 2
```
분모를 **평균**으로 둔 것이 핵심이다 — 질의어를 다 맞혀도
**상품명에 남는 토큰이 많으면 감점**된다.

| | 정확히 특정 | 애매(동점) |
|---|---|---|
| v1 (원본) | 15/18 | 1 |
| **★v2 (가중)** | **16/18** | **0** |

★**채점에서 내가 한 번 틀렸다** — `gold_pairs()` 가 처음엔 **«마지막»** `tool_args` 를
정답으로 썼다. C-011 은 턴이 둘(P1001 → P2002)인데 질문은 **첫 턴**이라
정답이 어긋나 **v2 를 오답으로 잡았다.** ⇒ 질문과 정답은 **같은 턴**에서 와야 한다.

★**나중에 안 것 — 채원님도 같은 결론에 닿았다.**
「점수가 완전히 들어맞으면 1점, 일부만 겹치면 0.5점으로」 — **수치까지 같다.**
서로 안 보고 같은 곳에 닿았다는 건 **그 진단이 맞다는 증거**다.

```
[확신도 평균]                   [6강이 본 것]
분류체계밖  0.50 → 12/12 범위밖   같음
```

6강이 남긴 숙제(「확신도 «자체»를 검증해야 한다」)를 검증해 보니 **신호 구실을 못 한다.**

## 6. ★오늘 배운 것 — 「무엇을 세는지」

```
①  eval 은 올랐는데 outscope 가 무너졌다   → 한쪽만 재면 속는다
②  총점은 같은데 위험한 실패 수가 다르다     → 한 숫자로 합치면 안 보인다
③  ★4축 전부 통과해야 1점인 지표에서는      → 부분 개선이 «점수로 안 나온다»
④  ★폭을 모르면 «개선»이라 말할 자격이 없다   → 아래
```

### ★★가장 늦게 배운 것 — 「폭을 재서 «주장의 자격»을 판정한다」

같은 조 만영님(소울매트) 회고에서 가져왔다:

> 「2~6번의 변화는 **반복 측정 폭 안이라 효과를 주장할 수 없습니다.**
>  같은 설정으로 다시 재니 **최대 12.8%p** 까지 흔들렸습니다. `temperature=0` 인데도 그렇습니다.」
> 「라우터는 **한 배치 안에서는 폭 0.000** 인데 **배치를 달리하면 0.942~0.971** 로 움직입니다.」

★**나도 같은 것을 봤다.** v3 0.738 → 0.741, v4 0.741 → 0.738 로 **값이 맞바뀌었다.**
그런데 나는 그걸 「120건 중 1건 수준의 미세한 비결정성」이라 적고 **넘어갔다.**

```
같은 현상       만영님  →  «주장을 내렸다» (2~6번은 효과 없음으로 처리)
              나     →  «각주로 적었다» (그리고 다음 표를 그대로 썼다)
```

⇒ 내 표의 **+0.019(hard-fewshot)** 와 **+0.014(7B 지침)** 는
  **폭 안인지 «모르는» 숫자**다. `--repeat` 를 붙여 다시 잰다.

★이건 「두 번 재라」의 반복이 아니다. **한 겹 더 깊다** —
  「두 번 재라」는 **재는 법**이고, 「폭을 재라」는 **말할 자격의 기준**이다.

### 가설이 두 번 기각됐다
| 가설 | 검증 |
|---|---|
| ① 범인은 「OTHER 억제 문단」 | ❌ v3 로 분리하니 outscope 동일(57.6%) |
| ② 범인은 「보내지 말라」는 금지 표현 | ❌ v4 로 바꾸니 1건만 회복(60.6%) |
| ③ **범인은 「판단법」을 정교하게 준 것** | ✅ 샌 6건이 SHIPPING 이 아니라 ORDER_PLACE·PRODUCT_INFO 로 |

⇒ **판단 기준을 정교하게 줄수록 모델은 «그 기준 안에서» 답을 찾으려 한다.**
  **「해당 없음」이 밀려난다.**

### 두 효과가 «가산적»이다
```
fewshot   eval +0.111 · outscope +6.0%p     ← 거래가 «없다»
v4        eval +0.185 · outscope −18.2%p    ← 거래다
합치면     eval +0.260 · outscope −12.1%p    (−18.2 + 6.0 = −12.2 ≈ −12.1)
```
fewshot 의 **+6%p** 는 **두 조건 모두에서 같은 크기**였다(78.8→84.8 · 60.6→66.7).

### ★★검사기를 만들면 그 검사기도 틀린다 — 오늘 **여섯 번**

★여섯째는 성격이 다르다 — **계산이 틀린 게 아니라 «재야 할 축 하나»를 안 쟀다.**
  역방향 가드레일에서 **정밀도만 재고 재현율을 안 쟀다**(정밀도 88% · 재현율 9%).
  앞의 다섯은 «틀린 값»을 냈고, 여섯째는 **«옳은 값을 냈지만 반쪽»**이었다.
  ⇒ 「검사기가 틀렸다」보다 **「검사 «설계»가 반쪽이었다」**가 잡기 어렵다.
    틀린 값은 대조하면 드러나는데, **안 잰 축은 대조할 것이 없다.**

### (앞선 네 번)
```
점검기   열거를 두 겹 하고 「0건」 보고       범위를 잘못 잡음
감사기   is_external_channel 고정 → 오탐    전제를 잘못 잡음
리포트   re.M 누락 → 「못 읽음」을 「없음」으로  실패와 부재를 같은 칸에
★폴백    결론 문구를 «미리 써 둠»            ★출력이 실측을 «가림»
```
네 번째가 제일 위험하다 — `retry: 3` 이 화면에 찍혀 있는데
바로 아래 줄에 **「재시도 0회로 바로 폴백했다」**가 있었다.
⇒ 결론 문구를 **`stat` 에서 «읽어» 만들게** 고쳤다. 고치자 13.8초 → **6.9초**(절반).
