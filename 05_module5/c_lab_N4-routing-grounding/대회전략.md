> 코드를 돌리기 전에 **채점기부터 읽었다.** 무엇으로 재는지 모르면 어디를 고칠지도 모른다.
> (노드3에서 배운 것 — 「무엇을 세는지 먼저 정한다」)

**퍼실 제시 기준선** ① 의도 분류 **0.94** (macro F1 0.945) · ② 1턴 답변 **56% (18/32)**
**내가 잰 바닥** ① 규칙 라우터 **0.583** (macro F1 0.677) — 2026-09-16 12:4x · 키 없이 측정

## 0. ★★가장 먼저 — 이 대회는 «지표 해킹»이 가능하다

평가셋의 정답 분포를 세어 봤다.

```
split      ORDER_PLACE  PRODUCT_INFO  SHIPPING  RETURN_REFUND  OTHER
eval            30           30          30          30       ★ 0
fewshot         10           10          10          10          0
outscope         0            0           0           0         33
```

### **평가셋 120건에 OTHER 정답이 «하나도» 없다.**

그래서 `macro F1` 을 `LABELS4`(OTHER 제외)로 잰다. 코드를 읽어야 알 수 있는 이유다.

**⇒ 여기서 나오는 결과:**
```
OTHER 로 «잘못 보내는 것»      → 무조건 감점
OTHER 를 «제대로 잡는 것»      → 평가셋으로는 «측정되지 않는다»
```

**⇒ 라우터가 OTHER 를 덜 쓰게만 만들면 ① 지표는 «무조건» 오른다.**
그리고 그 대가인 **outscope 33건(진짜 범위 밖)을 놓치는 것은 `evaluate.py` 가 안 잰다.**

### 실제로 그런 일이 일어나는지 재 봤다 — 규칙 라우터로

| 무엇을 재나 | 건수 | 적중률 |
|---|---|---|
| eval (4라우트) | 120 | **58.3%** |
| outscope (OTHER) | 33 | **84.8%** |
| fewshot | 40 | 57.5% |

**같은 라우터인데 어느 셋을 재느냐로 정반대로 보인다.** 규칙 라우터는 OTHER 를 남발한다
(오분류 50건 중 **40건이 → OTHER**). 그래서 **범위 밖은 잘 잡고 범위 안은 못 잡는다.**

⇒ **점수를 올리는 가장 쉬운 길은 「OTHER 를 줄이는 것」이고, 그건 서비스를 나쁘게 만든다.**
⇒ ★**그래서 나는 개선할 때마다 `outscope` 도 같이 잰다.** 한쪽만 재면 속는다.

## 1. 채점이 «정확히» 어떻게 되나 — `evaluate.py` 실측

### ① 의도 분류 (eval 120건)
```python
f1_score(y, pred, labels=LABELS4, average="macro")   # OTHER 제외
accuracy_score(y, pred)                              # 전체
```

### ② 1턴 답변 (32건) — **4축 전부 통과해야 1점**
```python
1. action   기대 == 실제            (ANSWER / ASK / OUT_OF_SCOPE)
2. tools    need - called 가 비어야  ← ★«더 부른 것»은 감점 아님
3. must     전부 답변에 «포함»
4. forbid   하나도 «없어야»
+ ASK 면   ? · 주시겠 · 알려주 · 말씀해  중 하나가 있어야
```

## 2. ★코드를 읽어야만 보이는 것 넷

### (1) `norm_num` 은 **콤마만** 지운다
```python
re.sub(r"(?<=\d),(?=\d)", "", s)
```
⇒ **「50,000원」**이라 써도 `must: "50000"` 통과. 단 **「5만원」은 실패.**

### (2) ★**도구는 «더» 불러도 감점이 없다**
```python
need - set(tools_called)      # 미호출만 본다
```
⇒ **애매하면 더 부르는 쪽이 이득이다.** 비용만 더 든다.

### (3) ★★**ASK 판정이 «도구를 안 불렀을 때»만 된다**
```python
elif not results and re.search(r"\?|주시겠|알려주|말씀해", text): action = "ASK"
```
⇒ ASK 기대인데 **도구를 하나라도 부르면 → ANSWER 로 판정 → 실패.**
⇒ **채점 32건 중 ASK 가 8건(25%).**
⇒ ⚠ 그런데 `prompts.py` 는 정반대를 시킨다 —
   *「도구를 부를 수 있는데도 부르지 않고 되묻는 것은 실패다」*
   **프롬프트와 채점기가 서로 다른 것을 요구한다.**

### (4) 채점기 «자기 검증»이 이미 들어 있다
모범 답안(`reference`)으로 채점해 전부 통과하는지 먼저 본다.
⇒ 노드3에서 내가 만든 `01_test_verify.py` 와 같은 발상.
⇒ **여기가 0 이 아니면 채점기가 틀린 것** — 내 개선보다 채점을 먼저 봐야 한다.

## 3. 코드에서 확인한 것 3건 — (A)만 내가 찾은 결함이다

### (A) **`CONF_THRESHOLD` 를 `config.py` 에서 바꿔도 안 먹는다**
```python
router.py:16   from config import CONF_THRESHOLD, MODEL   # 가져오고
router.py:50   CONF_THRESHOLD = 0.5                        # ★바로 아래서 덮어쓴다
```
`gate()` 가 읽는 건 아래쪽 값이다. 그런데 `config.py` 주석은
**「여기 값만 바꿔도 동작이 달라진다」**고 한다. 이 값만은 안 달라진다.

⇒ **임계값 조정을 시도한 팀은 «아무 효과 없는 실험»을 하게 된다.**
  숫자가 안 움직이면 「효과 없음」으로 결론 내리겠지만 **바뀐 적이 없다.**
⇒ ⚠ 이건 `hard_cases.csv` 72건과 직결된다 — 그 파일의 `expected_behavior` 가
  *「확신도를 임계값 미만으로 낮춰 이관한다」* 다. **고치려는 그 손잡이가 끊겨 있다.**

### (B) ~~내가 찾은 결함~~ → **강의가 «먼저» 인정한 한계** (정정 2026-09-16)
```python
for a in base:
    for b in base:
        if a > b: allowed.add(a - b)
        allowed.add(a + b)
```
⚠ **10강 본문이 이 한계를 이미 적어 두었다** — 내가 「찾은」 것이 아니다:
> 「산술 유도값을 허용하는 규칙은 **허용 집합을 크게 넓히므로** 반대로 놓치는 경우(미탐)가 생길 수 있고 …
> 그래서 가드레일은 **즉시 차단보다 «경고 후 재생성 또는 이관»**으로 쓰는 것이 안전합니다」

**내가 «더한» 것은 규모뿐이다** — 이중 루프라 숫자 N개면 허용이 **N²**로 는다.
강의가 말한 「크게 넓힌다」가 **제곱**이라는 뜻이다.
그리고 `min_check=1000` 이라 **1000 미만은 아예 안 본다** — forbid 에 `7일` 이 있는데 7 은 검사 밖.

### (C) **`answer.py` 는 import 만으로 키를 요구한다**
```python
answer.py:26   llm_t = init_chat_model(ANSWER_MODEL, ...).bind_tools(LC_TOOLS)   # 모듈 최상위
```
함수 안이 아니라 **불러오는 순간 실행**된다. (`router.py` 는 `_router_chain=None` 으로 지연 생성 — 대칭이 안 맞는다)
