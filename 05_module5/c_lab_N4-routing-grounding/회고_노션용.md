# 김주영

**OpenAI 키가 없어 LLM 자리에 전부 로컬 Ollama를 꽂았습니다.**
그래서 아래 숫자는 퍼실 기준선(0.945 / 56%)과 **비교할 수 없습니다.** 모델이 다릅니다.
비교되는 건 같은 모델 안에서의 전후뿐입니다.

---

## 결과

| | 시작 | 최종 |
|---|---|---|
| ① 의도 분류 (macro F1) | 0.556 (2B 지침만) | **0.925** (7B + 지침 v4 + 경계 예시) |
| ② 1턴 답변 | 18.8% (6/32) | **34.4%** (11/32) |
| 범위 밖(OTHER) 탐지 | 78.8% | 75.8% |

### 반복 측정 폭 — 같은 설정을 여러 번 재 봤습니다

| 설정 | 관측 | 값 | 폭 |
|---|---|---|---|
| 2B + v4 + 경계예시 | **4회** | 0.835 · 0.835 · 0.835 · 0.835 | **0.000** |
| 2B + v3 (지침만) | 2회 | 0.738 → **0.741** | 0.003 |
| 2B + v4 (지침만) | 2회 | 0.741 → **0.738** | 0.003 |

**같은 모델인데 설정에 따라 다릅니다.** v3·v4는 값이 서로 맞바뀌었고, 경계예시를 붙인 설정은 네 번 다 소수점까지 같았습니다.

⇒ **폭은 「비교하려는 그 설정에서」 재야 합니다.** 한 번 구해서 모든 비교에 쓰면 안 됩니다.
⇒ 그 기준으로 제 주장을 판정하면 — **v3 vs v4의 +0.003은 내립니다**(폭과 같고 실제로 뒤집혔습니다). +0.019·+0.014는 그 설정의 폭이 0.000이라 남깁니다.

## 1. 아직 아무도 안 짚은 것 두 가지

### `config.py`에서 `CONF_THRESHOLD`를 바꿔도 **안 먹습니다**

```python
router.py:16   from config import CONF_THRESHOLD, MODEL   # 가져오고
router.py:50   CONF_THRESHOLD = 0.5                       # 바로 아래서 덮어쓴다
```

`gate()`가 읽는 건 아래쪽 값입니다. `config.py` 주석은 「여기 값만 바꿔도 동작이 달라진다」고 되어 있습니다.

**임계값을 조정해 보신 분이 있다면, 효과가 없던 게 아니라 «바뀐 적이 없는» 겁니다.**
`router.py:50` 줄을 지우면 됩니다. 6강 더해보기 3이 이것 때문에 실행 불가입니다.

### 평가셋 120건에 **OTHER 정답이 0건**입니다

```
split       ORDER_PLACE  PRODUCT_INFO  SHIPPING  RETURN_REFUND  OTHER
eval             30           30          30          30        ★0
outscope          0            0           0            0        33
```

라우터가 OTHER를 덜 쓰게만 만들면 ① 점수는 **무조건** 오르고, 그 대가(범위 밖 33건을 놓치는 것)는 `evaluate.py`가 **안 잽니다.**

실제로 이런 일이 있었습니다:
```
지침만   eval 0.556 · outscope 78.8%
v4      eval 0.741 · outscope 60.6%   ← eval은 올랐는데 범위 밖이 무너졌다
```
**한쪽만 쟀으면 「큰 개선!」이라고 발표했을 겁니다.** 그래서 매번 `outscope`를 같이 쟀습니다.

## 2. 프롬프트 개선은 **작은 모델에서만** 크게 먹힙니다

같은 프롬프트 개선을 두 모델에 각각 넣었습니다.

```
2B 고정   v1 0.556 → v4+경계예시 0.835    +0.279
7B 고정   v1 0.911 → v4+경계예시 0.925    ★+0.014
```

**7B는 이미 잘해서 고칠 여지가 없습니다.** 하루 종일 한 프롬프트 개선이 0.014를 벌었습니다.

거래도 작은 모델에서만 일어납니다:
```
outscope   2B  78.8% → 57.6%   (−21.2%p)
           7B  75.8% → 75.8%   (변화 없음)
```

중간에 「판단 기준을 정교하게 줄수록 «해당 없음»이 밀려난다」고 결론냈었는데, **2B에 한정된 현상**이었습니다.

그리고 강의 조언 몇 개가 2B에서는 반대로 나왔습니다 — TF-IDF는 규칙보다 **낮았고**(0.550 < 0.677), 7,227자로 쪼갠 매뉴얼에서도 **도구 호출을 잃었고**, 12강이 「정석」이라 한 메시지 목록보다 **단순 concat이 나았습니다**(후속턴 35.0% vs 25.0%).

⇒ 강의가 틀린 게 아니라 **강의는 `gpt-5.6` 기준**입니다.

## 3. ②가 안 오르던 이유 — 모델을 키워도 **총점이 같았습니다**

```
2B  6/32 (18.8%)
7B  6/32 (18.8%)   ← 같다
```

①은 같은 교체로 +0.355였는데 ②는 ±0입니다. 안을 열면 **개선은 있었습니다**:

```
             2B    7B
tools 미호출   19 →  9    절반으로 줄었다
must 누락     19 → 15
OUT_OF_SCOPE  0 →  1
```

②는 **action·tools·must·forbid 4축을 전부 통과해야 1점**이라, 셋을 고쳐도 하나가 틀리면 0점입니다. 부분 개선이 묻힙니다.

### 실제로 올린 것 — must 누락 15건을 문장으로 읽었습니다

```
A  조회하고도 자리표시    C-002  must "50000" → 「현재 담아두신 금액이 ○○원」
B  「확인해 보겠습니다」   C-011  must "불가"  → 이미 조회했는데 앞으로 하겠다고 함
C  같은 뜻 다른 말        C-012  must "품절"  → 「재고는 없습니다」
```

답변 규칙에 세 줄을 더했습니다 — **조회 결과의 숫자는 그대로 쓸 것**, **이미 조회했으면 미루지 말 것**, **조회 결과에 적힌 그 단어를 쓸 것**.

⇒ **18.8% → 31.2%.** ANSWER 5/22 → 7/22, ASK 1/8 → 3/8.

### 신서연님의 `MAX_TOOL_TURNS 3 → 5` 도 제 환경에서 먹혔습니다

> 「설정값 한 줄이 프롬프트 여러 줄보다 셌음 — 도구 호출 상한(3)이 막고 있어
>  프롬프트로 조회를 늘려도 이관으로 떨어졌음」

```
31.2% → 34.4%    tools 미호출 11 → 7 · must 누락 16 → 12 · ANSWER 7/22 → 10/22
```
⚠ 대신 **ASK가 3/8 → 1/8로 떨어졌습니다.** 신서연님이 말한 「되묻기와 답변은 반대로 움직인다」 그대로입니다.

**누적: 18.8% → 31.2% → 34.4%**

## 4. 이정은님의 「역방향 가드레일」을 구현해 봤습니다

> 「지금 가드레일은 "답변에 있는데 출처가 없는 숫자"만 잡지, **"출처에 있는데 답변에 없는 숫자"는 안 잡는다**」 — 이정은님 회고, 남은 아이디어

제 최대 실패 유형이 정확히 이것이라 만들어 봤는데, **그대로는 안 됐습니다.**

**모범 답안 25건에 걸어 오탐을 쟀습니다** (사람이 쓴 맞는 답변이니 걸리면 전부 오탐):

| 규칙 | 오탐 |
|---|---|
| 조회 결과의 모든 숫자 | 24/25 |
| ID류 제외 | 23/25 |
| 금액·기간만 | 19/25 |
| **답변이 «언급한 항목»만** | **3/25** |

좁히는 데 필요했던 것 — 날짜를 조각내지 않기(`2026-08-24`를 세 숫자로 세면 「8월 24일」이라 써도 누락 처리됨), 식별자 제외, 그리고 **`0`은 말로 쓰는 게 맞다고 인정하기**(`stock:0` → 「품절」, `return_fee:0` → 「발생하지 않습니다」).

**남은 3건은 원리적으로 못 잡습니다:**
```
C-004  조회 free_shipping_threshold=38000
       답변 「화장품은 결제 금액과 무관하게 무료배송 대상이 아니며」
       ⇒ 이 값은 «쓰면 틀린다». 화장품은 제외 품목이다
C-007  품절·환불 문의에 상품 가격 74,000  ⇒ 무관
C-026  배송비 2,500인데 무료 기준 충족    ⇒ 안 쓰는 게 맞다
```

⇒ **「출처에 있는데 답변에 없는 숫자」 중에는 «없는 게 맞는» 것이 섞여 있습니다.**
그걸 가르려면 매뉴얼 조항의 «적용 조건»을 판단해야 합니다. 규칙이 아니라 판단의 일입니다.

### ★그런데 효과가 **0이었습니다** — 그리고 이유가 제 검증의 구멍이었습니다

실제 파이프라인에 붙여 32건을 재니 답변이 **한 글자도 안 바뀌었습니다.**
발동 내역을 찍어 보니 `빠진값 발견 0`. **한 번도 안 걸렸습니다.**

재현율을 재 봤습니다:

```
정밀도   모범 답안 25건 중 오탐 3건    88%
재현율   실제 must 누락 11건 중 1건     9%
```

**오탐을 24/25 → 3/25로 줄이는 동안 재현율이 함께 죽었습니다.**
저는 규칙을 좁힐 때마다 「오탐이 줄었다」고 좋아했고, **잡아야 할 것도 같이 놓치고 있다는 걸 볼 자가 없었습니다.**
10강이 「오탐 0건」을 강조해서 그 축만 봤습니다.

**그리고 더 근본적인 한계가 있습니다** — must 누락 11건 중 **5건은 숫자가 아닙니다**:
```
고객센터 · 품절 · 신축성 · 제조사 · 9월 1일
```
숫자 가드레일로는 **원리적으로 절반을 못 잡습니다.**

⇒ 「기계적으로 잡을 수 있다」는 성립하지 않습니다. 아이디어가 틀린 게 아니라,
**가드레일은 답변이 «무엇을 말하는지»는 봐도 «무엇이 적용되는지»는 모르기 때문**입니다.
10강이 LLM-as-a-judge를 둔 자리가 여기입니다.
