# DESIGN — 큐레이터 데스크 화면 설계

> 이 문서가 **정본**입니다. `ui.py` 는 여기 적힌 것을 **코드로 옮긴 것**뿐입니다.
> 값을 `ui.py` 에서 정하지 않습니다 — 정하려면 여기를 고치고 옮깁니다.
> (`config.json` 이 도메인 값의 유일한 출처인 것과 같은 이유)
>
> ← 실행 방법·폴더 구조는 **[README.md](README.md)** · 판단 근거는 **[REPORT.md](REPORT.md)**

---

## 0. 이 화면이 하는 일은 **하나**다

> **「10초 안에 판단하게 한다」**

승인 대기가 30건이면 사람은 같은 동작을 30번 합니다.
한 건에 30초 걸리면 15분, 10초면 5분입니다. **화면 설계가 그 차이를 만듭니다.**

그래서 **중요도 순서가 고정**입니다. 아래 순서를 바꾸는 변경은 하지 않습니다.

```
1  왜 멈췄나              ← 이걸 모르면 판단 자체가 불가능하다
2  통과시키면 뭐가 일어나나   ← 버튼 «바로 위». 강의 1강이 짚은 그 문장
3  무엇에 대한 건인가        ← 그림 · 제목 · 작가 · 연도
4  대기열 어디쯤인가         ← 1/33 · 남은 건수 · 진행
```

⛔**장식은 이 넷을 밀어내지 않는 자리에만** 둡니다.

## 1. 노드9 와 **무엇이 다른가** — 같은 서체, 다른 구조

| | 노드9 | 노드10 |
|---|---|---|
| 비유 | **측량 도면** | **결재 데스크** |
| 하는 일 | **읽는다** | ★**조작한다** |
| 구조 | 괘선으로 글을 나눈다 | ★**대기열 + 도켓 + 조작 띠** |
| 상태 | 거의 없다 | ★**줄어든다** (33 → 32 → …) |

**서체·색 토큰은 이어받습니다** — 같은 사람의 산출물이라는 표시입니다.
★**배치는 새로 짰습니다** — 「읽는 화면」과 「처리하는 화면」은 다른 물건입니다.

markbg     #FBEAE5   결과 예고 바탕

서체 — **IBM Plex Sans KR** + **IBM Plex Mono**.

### ★`fieldline` 은 **재서** 골랐습니다 — 한 번 틀렸습니다

```
#9A9281   paper 와 3.01:1  ✅
          ★field 와 2.66:1  ⛔  ← 단추 테두리는 «단추 바탕 위»에 있다
#8F8776   paper 3.47:1 · field 3.07:1  ✅
```

**어느 바탕과 재야 하는지를 틀렸습니다.** `redteam.py` 가 잡았습니다.
⇒ 색을 **눈대중으로 고르지 않습니다.** 조건을 적고 **계산해서** 찾습니다.

## 3. 갈래를 **색으로 가르지 않는다**

갈래가 넷입니다. 색으로 가르면 빠르지만 **접근성 규칙 `color-not-only`** 를 어깁니다.

```
1순위  ★글자          발행 / 이미지 / 작가 / 카탈로그
2순위   테두리 «모양»   solid / double / dashed / dotted
⛔        색            쓰지 않는다
```

테두리 모양은 **도면의 범례 문법**이고 색맹에게도 갈립니다.
글자가 이미 다 말하므로, 모양은 **거들 뿐**입니다.

## 4. 배치 — **정렬선은 하나**

```
┌──────────────────────────────────────────────────────┐
│ 큐레이터 데스크                                        │  머리
│ 모듈5 노드10 · 기준 N개 · 갈래 4 · SqliteSaver           │
├──────────────────────────────────────────────────────┤
│ ███████████████████░░░░  올린 160건 중 128건 처리       │  ★진행
├───────────┬──────────────────────────────────────────┤
│ 대기 32건  │ [작가] 1/19                              │
│ 발행    3 │ ┌────┐  04 - The fall of Icarus          │
│ 이미지  2 │ │그림│  Rrroza · 제작연도 미상             │
│ 작가   19 │ └────┘  ──────────────────────────        │
│ 카탈로그 8 │         왜 멈췄나                          │  ★1
│           │         C5  위키백과에 «화가»로 없다        │
│ ○ 전체     │         A2  근거 표시가 하나도 없다         │
│ ○ 발행     │         ┌────────────────────────┐       │
│ ○ 이미지   │         │ 통과시키면              │       │  ★2
│ ● 작가     │         │ 작가 소개가 게시됩니다   │       │
│ ○ 카탈로그 │         └────────────────────────┘       │
│           │         나갈 글                            │  ★3
│           │         Rrroza. 바로크 시대를 대표하는…     │
│           │  ▸ 고쳐서 내보내기                          │
│           │  [발행] [수정 후 발행] [반려] [다시 해설]    │
└───────────┴──────────────────────────────────────────┘
```

### ★읽을 것을 **한 칸**에 모읍니다

처음엔 제목·왜멈췄나는 오른쪽 칸, 「나갈 글」은 전체 폭이었습니다.
**왼쪽 모서리가 두 군데**가 되어 눈이 왔다 갔다 했습니다(캡처로 확인).
⇒ 읽는 것은 **전부 오른쪽 칸**. 그림만 왼쪽.

### ⛔**대기열을 `st.sidebar` 에 두지 않습니다** — 실측 판단

띄워 보니 **사이드바가 DOM 에 아예 안 생겼습니다.**
최소 앱(`st.sidebar` 한 줄)으로 **격리 시험**해도 같았습니다 ⇒ 제 코드 문제가 아닙니다.

★원인이 무엇이든 **대기열이 «사라질 수 있는 자리»에 있으면 안 됩니다** —
채점자 화면에서 대기 건수와 갈래 필터가 통째로 없어집니다.
⇒ **본문 2단**으로 옮겼습니다. 접히지 않습니다.
(부수 효과로 UX 가 나아졌습니다 — 처리하는 동안 대기열이 **계속 보입니다**)

## 5. 조작 — 응답 **넷**, 으뜸 **하나**

```
[발행]  ← 으뜸. 먹색 채움. 「보통 무엇을 하나」를 말한다
[수정 후 발행] [반려] [다시 해설]  ← 대등. 조작면 + 경계
```

★**응답이 둘이면 자동화가 무너집니다**(강의 4강) —
「이 문구만 고쳐서」를 전부 반려하고 사람이 직접 처리하게 됩니다.

- 전부 **최소 높이 44px** (규칙 `touch-target-size`, 실측 46px)
- `focus-visible` 링을 **지운 적이 없습니다** (규칙 `focus-states`)
- ⛔**래퍼 div 로 으뜸을 고르지 않습니다** — Streamlit 이 markdown 블록을 갈라
  `.primary .stButton>button` 이 **안 닿습니다**. 네이티브 `type="primary"` 를 씁니다.

### ★「고쳐서 내보내기」는 **접어 둡니다**

처음엔 「나갈 글」과 textarea 가 **같은 내용을 두 번** 보여 줬습니다.
⇒ 기본은 접힘. 화면이 짧아지고 초점이 안 흩어집니다(규칙 `progressive-disclosure`).

## 6. ⛔피한 것 — 2026 AI 생성 UI 표식

노드9 에서 세어 둔 16개 중 이 화면에 해당하는 것:

```
⛔카드 왼쪽 컬러 보더 (#11 — 가장 확실한 표식)
⛔그라디언트 · 글로우 · 그림자        → redteam 이 «실제로» 0 을 잰다
⛔가운데 정렬 히어로 · H1 위 배지
⛔올캡스 라벨
⛔4연속 스탯 배너
```

★**대기 건수는 스탯 배너가 아니라 «목록의 머리»에** 뒀습니다 —
**기능이지 장식이 아니기 때문**입니다. 진행 바도 같은 이유로 남겼습니다
(대기열은 «줄어드는 것»이고, 줄어드는 걸 안 보여 주면 끝이 안 보입니다).

## 7. 접근성 — 규칙 이름 그대로

| 규칙 | 어떻게 | 어디서 잰다 |
|---|---|---|
| `color-contrast` | 본문 4.5:1 · 조작 경계 3:1 | ★`redteam.py` 가 **계산** |
| `color-not-only` | 갈래는 **글자**가 먼저, 모양이 거듦 | §3 |
| `touch-target-size` | 최소 44px (실측 46) | 브라우저 실측 |
| `focus-states` | `focus-visible` 2px 링 | `ui.py` |
| `alt-text` | 그림에 제목을 넣음 | `app.py` |
| `progressive-disclosure` | 수정칸·자동처리·기준표를 접음 | `app.py` |
| `reduced-motion` | `prefers-reduced-motion` 존중 | `ui.py` |
| `deep-linking` | `?갈래=작가` 로 바로 열림 | `app.py` |
| `empty-states` | 빈 화면에 **할 말**을 둠 | `app.py` |

### ⚠못 한 것 — 정직하게

- **키보드 단축키**(`J`/`K`/`Enter`) — Streamlit 에서 안전하게 붙이기 어렵습니다.
  탭 순서와 포커스 링은 살아 있지만, **30건을 키보드만으로 처리하기는 불편**합니다.
- **다크 모드** — 한 가지 모습으로 **일부러** 고정했습니다.
  종이·잉크 비유가 전제고, 두 벌을 제대로 맞출 시간을 다른 데 썼습니다.

## 8. ⛔Streamlit 에서 **두 번** 밟은 함정

두 번 다 **후손 선택자**였습니다. 같은 병입니다.

```
.dk img          그림에 테두리·폭이 «안 걸렸다»
.primary .stButton>button   으뜸 단추가 «보통 단추»로 보였다
```

★**Streamlit 은 `st.markdown` 블록마다 따로 감쌉니다.**
「같은 도켓 안」처럼 보여도 DOM 에서는 **부모가 다릅니다.**

⇒ **규칙** — 내 클래스 밑으로 타고 내려가는 선택자는
**한 `st.markdown` 호출 안에서 함께 그려질 때만** 씁니다.
`redteam.py` 가 이걸 **검사**합니다.

## 9. 캡처는 **코드로** 찍습니다

```bash
python capture_demo.py --out docs/demo.png
python capture_demo.py --out docs/demo-작가.png --갈래 작가
```

- **개인 정보가 안 찍힙니다** — 빈 프로필 + 헤드리스라 브라우저 UI 자체가 없습니다
- ★**화면이 바뀌면 다시 찍습니다** — 한 줄이면 되니까 실제로 다시 찍습니다
- 「어떻게 찍었나」를 **글이 아니라 코드**로 남깁니다
- ⛔고정 `sleep` 을 쓰지 않습니다 — **「왜 멈췄나」가 뜰 때까지** 기다립니다
